## Central question

Six ways to wire an agent to a design tool. Which one fits the class you are teaching,
or the project you are building?

:::narration
Workshop one surveyed six framework combinations, and the useful finding was not that
one of them wins. It is that they trade the same two things against each other: how
much programming background the student needs, and how directly the agent reaches the
C A D environment. Every framework on the chart buys you one at the cost of the other.
Pick by who is in the room, not by what is newest.
:::

:::figure{id=framework_landscape caption="Figure 1. The six framework combinations from Workshop 01, placed by programming demand and CAD access. Drawn for this module from the workshop's merit and demerit notes."}
:::

:::keyidea
The two axes are **programming background required** and **how directly the agent
reaches the CAD environment**. Almost every option buys one at the cost of the other.
Choose for the room you are teaching, not for the newest stack.
:::

## The six, and what each one is actually for

:::cards
01 OpenAI SDK + raw Python | Fast, concentrated learning of the agentic loop | No CAD. Needs programming. No MCP.
02 OpenAI SDK in Grasshopper | Teachable with almost no coding background | Simulation plug-ins are hard. Needs Rhino 9 WIP for Python 3.10+.
03 FastMCP + any LLM UI | Real depth on MCP; quick to test in any chat client | No CAD. Needs server-connection literacy. No handoffs.
04 + RhinoCompute | Large functions via Grasshopper plug-ins; scales far | Advanced programming. Hops/RhinoCompute install is a real hurdle.
05 + Strands + Streamlit | Deployment-level; 3D visible in the app; any LLM | Several libraries to learn. Strong API background needed.
06 Grasshopper + Swiftlet | CAD access with instant visual feedback, no code | No agent handoffs or swarm behaviour.
:::

## What MCP is, and why it keeps appearing

:::narration
Four of the six frameworks route through M C P, the Model Context Protocol, so it is
worth being precise about what it is. M C P is a standard way for a model to discover
and call tools that you host. You write small functions on a server, the model sees a
list of them, and it decides which to call. The practical consequence for a course is
that the same server works with any client that speaks the protocol, so students are
not locked to one vendor's chat app. The practical cost is that they now have to think
about servers, ports and tunnels.
:::

**{{MCP}}** is a standard way for a model to discover and call tools you host. You
write small functions; the model sees the list and chooses. The same server then works
with any client that speaks the protocol.

:::workflow
Write the server | Small, single-purpose functions. `mcp_server.py` with FastMCP. |
Inspect it | `npx @modelcontextprotocol/inspector python mcp_server.py` — see every tool the model will see. |
Expose it | `ngrok http 8000` gives a public URL. Framework 06 needs `--host-header=rewrite`. |
Register it | Turn on Developer mode in the client, create an app, and paste the URL with `/mcp` appended. |
:::

:::keyidea
The `/mcp` suffix on the tunnel URL is the step people miss. `https://…ngrok-free.dev`
is not the endpoint; `https://…ngrok-free.dev/mcp` is.
:::

## How to choose

:::narration
My reading of the six, for teaching purposes. If the room has no programming
background and you want them to see geometry change, framework six is the honest
answer, and you accept that they will not learn handoffs. If you want them to
understand the agentic loop itself in one session, framework one, and accept that
nothing appears in Rhino. If you are building something for a research project rather
than a class, framework five is the current state of the art and the cost is that you
are learning several libraries at once. There is no framework here that gives you no
programming, full C A D, and agent handoffs. That combination does not exist yet.
:::

:::compare
Teaching a design studio | Framework 06, or 02 | Students see geometry respond. They will not learn handoffs or MCP depth — decide whether that matters for the session.
Teaching the agentic loop | Framework 01, or 03 | Fastest route to understanding agents and tools. Nothing appears in the CAD environment.
:::

:::keyidea
No option on this chart gives you *no programming*, *full CAD access*, **and** agent
handoffs. That combination does not currently exist. Say so out loud when you choose,
so the tradeoff is on the record.
:::

:::details{summary="A note on what these merits and demerits are"}
The six comparisons come from the SI Lab's own Workshop 01 notes — hands-on
assessments made while building each stack, not a published benchmark. They reflect
the tools available at the time of the workshop, on the machines in that room. Rhino 9
is work-in-progress; MCP is moving quickly. Re-test before relying on any of it for a
term plan.
:::

You want students with no coding background to see a massing change in response to an
agent. Which framework fits?

- Framework 05 — the full Strands and Streamlit stack
:::
