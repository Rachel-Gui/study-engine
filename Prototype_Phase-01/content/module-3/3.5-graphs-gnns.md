## Central question

Images describe appearance. How can a model represent the *relationships* among
rooms, systems, buildings, or urban networks?

:::narration
A floor plan is not really a picture. It is a set of rooms and the relationships
between them: which room opens onto which, what you can see from where, where air and
people move. A graph stores exactly that — nodes for the things, edges for the
relationships — and a graph neural network learns on it by letting each node send
messages to its neighbours. One important warning before we go on. A graph is a way
of storing data. A G N N is a neural model that learns on that data. They are not the
same word, and the difference matters when you write it up.
:::

## Graph representation

- **Node** — a room, facade, sensor, building, or urban block.
- **Edge** — adjacency, circulation, visibility, airflow, similarity, or energy
  exchange.
- **Node features** — area, program, occupancy, temperature, material.
- **Edge features** — distance, connection type, shared boundary, direction,
  capacity, flow.
- **Global features** — site, climate, project target, building-level properties.

## GNN message passing

1. Each node begins with its own features.
2. The node receives messages from connected neighbours.
3. Neighbour messages are aggregated.
4. The node updates its representation.
5. Multiple layers allow information to travel farther through the graph.
6. The model predicts node labels, edge relationships, graph-level properties, or new
   structures.

:::keyidea
A graph is a data representation. A {{GNN}} is a neural model that learns on graphs.
A hypergraph model, an adjacency algorithm, or a self-organizing map is **not**
automatically a GNN. Use the word only when a neural message-passing model is
actually doing the learning.
:::

## Architectural applications

- Room adjacency and circulation reasoning.
- Floor-plan analysis or generation.
- Building-system and energy-network modeling.
- Urban accessibility and mobility relationships.
- Mesh-based physical-field approximation.
- Knowledge graphs linking buildings, materials, performance, and regulations.

## Hypergraph distinction

- A normal graph edge usually connects two nodes.
- A hyperedge can connect several nodes simultaneously.
- A hyperedge can represent one apartment, a shared circulation zone, a functional
  group, or a multi-room relationship.

:::flow
Program requirements > room nodes > adjacency and access edges > graph or hypergraph > optional GNN > geometry-generation rules > candidate floor plans > daylight, carbon, circulation and space-efficiency evaluation > designer selection
:::

## Research example

Weber, Mueller and Reinhart use a hypergraph to encode floor-plan organization and
support automatic geometry generation. Within that study, improved space efficiency
outperformed envelope upgrades for operational carbon in **72%** of surveyed Zurich
buildings, **61%** in New York, and **33%** in Singapore. A Zurich case study
increased daylight access by up to **24%**.

:::keyidea
Those figures belong to that study's datasets, assumptions and evaluation scope.
Quote them with the scope attached or do not quote them.
:::
