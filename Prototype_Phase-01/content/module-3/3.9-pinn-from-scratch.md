## What you are building

Episode 3.6 described a PINN as "a normal network with an unusual loss". This
episode builds one in about eighty lines of numpy, with every derivative written by
hand, so that nothing is hidden inside a framework. The problem is small enough to
solve on paper, which means every number the network produces can be checked.

:::narration
In episode three point six a physics-informed network was described as a normal
network with an unusual loss. This episode builds one, in numpy, with every
derivative written out by hand. No framework, no automatic differentiation, nothing
you cannot check. The problem is deliberately tiny: a second-order equation on the
unit interval whose exact answer is a sine wave. Small enough to solve on paper,
which is the point. When the network gets it right you will know exactly why, and
when you break it, in the last step, you will know exactly what broke.
:::

:::figure{id=pinn_problem caption="Figure 1. The problem: u″ = −π² sin(πx) on (0, 1), u(0) = u(1) = 0. The network never sees the answer. Redrawn for this module."}
:::

:::stats
16 | hidden neurons
30 | collocation points
0 | training examples of the answer
:::

:::flow
Write the equation > Network with u″ by hand > Loss: residual + boundary > Adam > Compare with the exact answer > Break it on purpose
:::

By the end of this episode you should be able to:

- Write a PINN loss for a one-dimensional boundary-value problem
- Differentiate a small network twice with respect to its input, by hand
- Train it and verify the result against a known solution
- Show what each loss term contributes by removing it

## The problem, read as a building

:::narration
Read the equation as a wall. One metre thick, both faces held at the ambient
temperature, and a distributed heat source inside it, strongest in the middle, like
solar absorption in a glazing cavity or hydration heat in curing concrete. u of x is
the temperature rise at depth x. The equation says the curvature of the temperature
profile equals the source. The boundary conditions say the rise is zero at both
faces. The exact answer is the sine of pi x, and we will pretend not to know that.
The network gets the equation, the two ends, and thirty points at which to check
itself. Nothing else.
:::

:::keyidea
u″(x) = f(x) with f(x) = −π² sin(πx), and u(0) = u(1) = 0. Exact solution: u = sin(πx).
The network is never shown u. It is shown f, the two boundary values, and where to
check.
:::

:::cards
The equation | u″ = f | curvature of the profile equals the source
Boundary conditions | u(0) = u(1) = 0 | both faces held at ambient
Collocation points | 30 values of x in [0, 1] | where the residual is measured
The answer | sin(πx) | used only to grade the network afterwards
:::

:::technical{summary="The derivatives, worked out — this is what autodiff would do for you"}
With one hidden layer of H tanh units, u(x) = Σⱼ w2ⱼ · tanh(w1ⱼ x + b1ⱼ) + b2.

Write tⱼ = tanh(w1ⱼ x + b1ⱼ) and sⱼ = 1 − tⱼ² (the derivative of tanh). Then

```
u'(x)  = sum_j  w2_j * w1_j   * s_j
u''(x) = sum_j -2 * w2_j * w1_j^2 * t_j * s_j
```

The residual r(x) = u″(x) − f(x) depends on the weights, so the loss needs ∂r/∂θ:

```
dr/dw2_j = -2 * w1_j^2 * t_j * s_j
dr/dw1_j = -2 * w2_j * ( 2*w1_j*t_j*s_j  +  w1_j^2 * x * s_j * (1 - 3*t_j^2) )
dr/db1_j = -2 * w2_j * w1_j^2 * s_j * (1 - 3*t_j^2)
dr/db2   = 0
```

and the boundary term needs ∂u/∂θ, which is the ordinary backward pass:
∂u/∂w2ⱼ = tⱼ, ∂u/∂b2 = 1, ∂u/∂w1ⱼ = w2ⱼ·sⱼ·x, ∂u/∂b1ⱼ = w2ⱼ·sⱼ.

Every line above is checked in the lab against a finite difference. In PyTorch the
whole block is two calls to `torch.autograd.grad`, which is why real PINNs use a
framework — but the framework is doing exactly this.
:::

## Interactive code lab — the PINN, step by step

:::narration
Six steps. First, the problem and the collocation points. Second, the network and its
second derivative, checked against a finite difference before we trust it. Third, the
loss: the mean squared residual at the collocation points plus ten times the mean
squared boundary error, with the gradient of both. Fourth, two thousand steps of
Adam, printing the residual and the true error as it trains. Fifth, the picture: the
network on top of the exact answer inside the domain, and drifting away outside it.
Sixth, three experiments that remove one ingredient each. Run them in order; each
step uses the one before.
:::

:::pylab{title="A PINN from scratch, in numpy" packages=numpy,matplotlib}
# step: The problem, and the answer we will pretend not to know
import numpy as np
PI = np.pi

f      = lambda x: -PI**2 * np.sin(PI * x)     # the source term:  u''(x) = f(x)
exact  = lambda x: np.sin(PI * x)              # solves it, with u(0) = u(1) = 0

x_col = np.linspace(0, 1, 30)                  # collocation points: where we check the equation
x_bc  = np.array([0.0, 1.0]); u_bc = np.array([0.0, 0.0])   # the two boundary conditions
print("collocation points:", len(x_col), "  boundary points:", len(x_bc))
print("The network will never be shown exact(x). It is shown f(x), the two ends, and nothing else.")

# step: A tiny network, and its second derivative by hand
rng = np.random.default_rng(0)
H = 16                                                        # hidden neurons, tanh activation
p = dict(w1=rng.normal(0, 1.5, H), b1=rng.uniform(-1.5, 1.5, H),
         w2=rng.normal(0, 0.3, H), b2=np.zeros(1))

def forward(p, x):
    """u(x) = sum_j w2_j tanh(w1_j x + b1_j) + b2, and u''(x) by the chain rule."""
    t = np.tanh(np.outer(x, p["w1"]) + p["b1"])              # (n, H)
    s = 1 - t**2                                             # tanh'(z) = 1 - tanh(z)^2
    u   = t @ p["w2"] + p["b2"][0]
    upp = (-2 * p["w2"] * p["w1"]**2 * t * s).sum(1)         # d2/dx2 of each term, summed
    return t, s, u, upp

# check the analytic u'' against a finite difference before trusting it
x0, h = 0.37, 1e-3
u_m, u_0, u_p = (forward(p, np.array([x0 + d]))[2][0] for d in (-h, 0, h))
fd = (u_p - 2 * u_0 + u_m) / h**2
print("u''(0.37) analytic:", round(forward(p, np.array([x0]))[3][0], 5), "  finite difference:", round(fd, 5))

# step: The physics-informed loss and its gradient
def loss_and_grad(p, lam_bc=10.0):
    t, s, u, upp = forward(p, x_col)
    r = upp - f(x_col)                          # the PDE residual at every collocation point
    n = len(x_col); w1, w2 = p["w1"], p["w2"]
    g = {k: np.zeros_like(v) for k, v in p.items()}

    # gradient of  mean(r^2)  through u''  (three of the four parameter groups)
    c = (2.0 / n) * r
    g["w2"] += c @ (-2 * w1**2 * t * s)
    g["w1"] += c @ (-2 * w2 * (2 * w1 * t * s + w1**2 * x_col[:, None] * s * (1 - 3 * t**2)))
    g["b1"] += c @ (-2 * w2 * w1**2 * s * (1 - 3 * t**2))

    # gradient of  lam_bc * mean((u(x_bc) - u_bc)^2)  through u
    tb, sb, ub, _ = forward(p, x_bc)
    e = ub - u_bc
    cb = lam_bc * (2.0 / len(x_bc)) * e
    g["w2"] += cb @ tb;                  g["b2"] += cb.sum()
    g["w1"] += cb @ (w2 * sb * x_bc[:, None]);   g["b1"] += cb @ (w2 * sb)
    return np.mean(r**2), np.mean(e**2), g

L_pde, L_bc, _ = loss_and_grad(p)
print("before training:  PDE residual", round(L_pde, 2), "  boundary error", round(L_bc, 4))

# step: Train with Adam
def train(p, steps=2000, lr=0.01, lam_bc=10.0, log=True):
    m = {k: np.zeros_like(v) for k, v in p.items()}; v = {k: np.zeros_like(vv) for k, vv in p.items()}
    hist = []
    for it in range(1, steps + 1):
        L_pde, L_bc, g = loss_and_grad(p, lam_bc)
        hist.append(L_pde + lam_bc * L_bc)
        for k in p:                                                   # Adam (Kingma & Ba, 2015)
            m[k] = 0.9 * m[k] + 0.1 * g[k]
            v[k] = 0.999 * v[k] + 0.001 * g[k]**2
            p[k] -= lr * (m[k] / (1 - 0.9**it)) / (np.sqrt(v[k] / (1 - 0.999**it)) + 1e-8)
        if log and (it in (1, 100, 500, 1000, 2000)):
            xt = np.linspace(0, 1, 101); err = np.abs(forward(p, xt)[2] - exact(xt)).max()
            print(f"step {it:5d}   PDE residual {L_pde:9.4f}   boundary {L_bc:8.6f}   max|u - exact| {err:.4f}")
    return hist

hist = train(p)
print("\nThe network has reproduced sin(pi x) to three decimals without ever seeing it.")

# step: Look at it
import matplotlib.pyplot as plt
xt = np.linspace(-0.25, 1.25, 151)
fig, ax = plt.subplots(1, 2, figsize=(8, 3))
ax[0].plot(xt, exact(xt), "k--", lw=1.5, label="exact sin(pi x)")
ax[0].plot(xt, forward(p, xt)[2], c="#4b2e83", lw=2, label="PINN")
ax[0].axvspan(0, 1, color="#f6f3ec"); ax[0].plot(x_col, 0 * x_col - 1.15, "|", c="#4b2e83")
ax[0].set_title("inside [0, 1] it matches; outside it drifts"); ax[0].legend(fontsize=8)
ax[1].semilogy(hist, c="#4b2e83"); ax[1].set_title("total loss per step"); ax[1].set_xlabel("step")
plt.tight_layout()

# step: Three experiments that show what each ingredient does
def experiment(label, **kw):
    global x_col
    q = dict(w1=rng.normal(0, 1.5, H), b1=rng.uniform(-1.5, 1.5, H), w2=rng.normal(0, 0.3, H), b2=np.zeros(1))
    saved = x_col
    if "n_col" in kw: x_col = np.linspace(0, 1, kw["n_col"])
    train(q, steps=1500, lam_bc=kw.get("lam_bc", 10.0), log=False)
    xt = np.linspace(0, 1, 101); err = np.abs(forward(q, xt)[2] - exact(xt)).max()
    u0, u1 = forward(q, np.array([0.0, 1.0]))[2]
    x_col = saved
    print(f"{label:38s} max error {err:6.3f}   u(0) = {u0:+.2f}   u(1) = {u1:+.2f}")

experiment("baseline (30 points, lam_bc = 10)")
experiment("no boundary loss (lam_bc = 0)", lam_bc=0.0)
experiment("only 3 collocation points", n_col=3)

xo = np.array([1.1, 1.25, 1.5])
print("\nextrapolation with the trained baseline - residual |u'' - f| at x =", xo, ":",
      np.abs(forward(p, xo)[3] - f(xo)).round(2))
print("Nothing enforced the equation past x = 1, so the network stopped obeying it there.")
:::

## Reading the results

:::narration
Three things to take from the output. The residual falls by four orders of magnitude
and the maximum error against the exact solution ends below one thousandth, from an
equation and two numbers. Remove the boundary term and the residual still falls, but
the curve sits metres away from the answer, because the equation alone has
infinitely many solutions. Cut the collocation points to three and the network is
right at those three points and wrong between them. And past x equals one, where no
point checked it, the residual grows immediately. A P I N N is only ever as good as
its loss and its collocation set. That is not a weakness; it is a specification you
can write down.
:::

:::compare
What the PINN was given | the equation, two boundary values, 30 checkpoints | It reproduced the exact solution to three decimals — no training examples of the answer.
What it was not given | anything about x < 0 or x > 1 | It stopped obeying the equation the moment it left the collocation set. Physics is enforced where you check it.
:::

:::keyidea
Removing one term at a time is the honest way to report a PINN. Each ablation says
what that term bought. "It works" says nothing; "without the boundary term the error
is 3.3, with it 0.0005" is a result.
:::

:::widget{id=pinn-lab}
:::

:::predict
You add four noisy measurements of u inside the domain with a large data weight
(λ data = 10) and train again. The PDE residual ends higher than before. Why?
- The network is too small to fit both | Sixteen units fit a sine easily; capacity is not the issue.
- *The noisy points pull the curve away from the exact solution, and the exact solution is what makes the residual zero | Yes. Data and physics disagree because the data is noisy. The λs decide who wins; that is a modelling choice, not a bug.
- Adam cannot minimise two losses at once | Adam minimises whatever sum you give it. The sum has a different minimum now.
:::

## From numpy to a framework

:::narration
Everything here scales up in one direction: replace the hand derivatives with
automatic differentiation. In PyTorch the whole derivative block becomes two calls,
and the same code handles two spatial dimensions, time, a nonlinear equation, or a
deeper network without you deriving anything. What does not change is the loss
structure, the need for collocation points, the boundary weighting, and the ablation.
The technical block has the PyTorch version, ready for Colab. Run it with a G P U
runtime and it trains in seconds.
:::

:::technical{summary="The same PINN in PyTorch, for Colab (not the browser)"}
Pyodide cannot run PyTorch, so this block is for Colab or your laptop. Paste it into a
notebook cell.

```
import torch, math
torch.manual_seed(0)
net = torch.nn.Sequential(torch.nn.Linear(1, 32), torch.nn.Tanh(),
                          torch.nn.Linear(32, 32), torch.nn.Tanh(), torch.nn.Linear(32, 1))
f = lambda x: -math.pi**2 * torch.sin(math.pi * x)

x_col = torch.linspace(0, 1, 50).view(-1, 1).requires_grad_(True)
x_bc  = torch.tensor([[0.0], [1.0]])
opt = torch.optim.Adam(net.parameters(), lr=1e-3)

for step in range(5000):
    u   = net(x_col)
    du  = torch.autograd.grad(u, x_col, torch.ones_like(u), create_graph=True)[0]
    d2u = torch.autograd.grad(du, x_col, torch.ones_like(du), create_graph=True)[0]
    loss_pde = ((d2u - f(x_col))**2).mean()
    loss_bc  = (net(x_bc)**2).mean()
    loss = loss_pde + 10 * loss_bc
    opt.zero_grad(); loss.backward(); opt.step()
    if step % 1000 == 0:
        print(step, float(loss_pde), float(loss_bc))

xt = torch.linspace(0, 1, 101).view(-1, 1)
print("max error:", float((net(xt) - torch.sin(math.pi * xt)).abs().max()))
```

The two `autograd.grad` calls are the whole difference. `create_graph=True` keeps the
derivative differentiable so the loss can be backpropagated through it. Change `f`
and the boundary points and the same code solves a different equation; add a second
input column and it solves one in two dimensions.
:::

:::boundary
Data | none — the network is trained from an equation and two boundary values; the exact solution is used only to grade it
Evidence | every number is [[simulated]] and reproduces exactly with the seed shown
Establishes | how a PINN loss is built and differentiated, that it recovers a known solution, what each term contributes, where it stops being valid
Does not establish | that a PINN solves a real building physics problem — a 2D or transient heat problem with real boundary conditions needs the framework version, a validation against a solver, and the same ablations
:::

:::reflect
A colleague proposes a PINN for indoor-temperature prediction and says it "will
respect the physics by construction". Which reply is accurate?
- Correct — a PINN cannot violate its equation | It minimises the residual; it does not zero it, and only at the collocation points.
- *It will be penalised for violating the equation at the points you check, and it needs validation like any other model | Yes. The physics is a loss term, not a constraint, and it enforces nothing where nothing was checked.
- PINNs only work for toy problems | They have solved real forward and inverse problems; they simply need the same honesty about range and validation.
:::
