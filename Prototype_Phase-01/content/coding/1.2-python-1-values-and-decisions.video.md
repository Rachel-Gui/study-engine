narration: |
  Here is the picture to keep in your head. Python reads your program from the top to
  the bottom, one line at a time. Each line does one of two things: it gives a name a
  value, or it produces something you can see on the screen. When something goes wrong,
  Python stops and tells you exactly which line. That is the whole model, and it never
  gets more complicated than that.
:::

:::scene{type=code}
heading: Your first program
code: |
  print("hello")
  print(2 + 2)
  print("2 + 2")
output: |
  hello
  4
  2 + 2
note: print shows something on the screen. The round brackets hold what to show. The quotes mark text — "2 + 2" in quotes is just text, so it is shown unchanged.
narration: |
  The smallest useful program is one line: print, and in brackets, hello in quotes.
  Print shows something on the screen. The round brackets hold what to show. The quotes
  mark text. Look at the second and third lines. Two plus two without quotes prints four,
  because Python works out what is inside the brackets first. Two plus two in quotes
  prints the text two plus two, unchanged. The quotes are the difference between a
  calculation and a piece of text.
:::

narration: |
  Everything Python works with is a value, and every value has a type. Four types cover
  almost everything in this course. Int is a whole number, like seven hundred and sixty
  eight. Float is a number with a decimal point, like zero point three five. Str, short
  for string, is text in quotes. And bool is True or False, the answer to a question.
  Type, with a value in brackets, tells you which one you have. The quotes are the whole
  difference between the number three and the text three.
:::

:::scene{type=code}
heading: Names — a label attached to a value
code: |
  width = 6
  depth = 4
  area = width * depth
  print(area)

  width = 10
  print(area)
output: |
  24
  24
note: area stayed 24. The line area = width * depth ran once, when width was 6. Python remembers values, not formulas.
narration: |
  A variable is a name attached to a value. Width equals six does not mean width is
  equal to six in the maths sense. It means: work out the right hand side, then attach
  the name width to it. Now watch the surprise. Area is width times depth, twenty four.
  Then width becomes ten. And area is still twenty four. The line that computed area ran
  once, when width was six. Python remembers values, not formulas. If you want area
  updated, you run that line again.
:::

  temp: fine for two lines of scratch work, a trap after twenty lines. Your future self

:::scene{type=code}
heading: Text — building a message
code: |
  name = "Kitchen"
  area = 12.5
  print(name + " is " + str(area) + " m2")
  print(f"{name} is {area} m2")
  print(f"{area:.2f}")
output: |
  Kitchen is 12.5 m2
  Kitchen is 12.5 m2
  12.50
note: An f before the quote lets you write names inside curly braces. Use f-strings everywhere. The :.2f formats a number with two decimals.
narration: |
  You will spend a surprising amount of a data project building labels, file names and
  messages. Plus joins pieces of text, but a number has to be converted with s t r
  first. The cleaner way is the f string: put an f before the quote and write the names
  in curly braces. Kitchen is twelve point five square metres. And a colon dot two f
  inside the braces formats the number with two decimals. You will use that in every
  table and plot label from here on.
:::

:::scene{type=code}
heading: Decisions — if, elif, else
code: |
  eui = 142            # energy use, kWh per m2 per year

  if eui < 100:
      label = "A"
  elif eui < 150:
      label = "B"
  else:
      label = "C"
  print(label)
output: |
  B
note: The first condition is False, the second is True, so only label = "B" runs. The else block is skipped entirely.
narration: |
  Programs branch. A comparison like e u i less than one hundred is a question, and its
  answer is True or False. If runs its block only when the answer is True. Here the
  energy use is one hundred and forty two. Is it under one hundred? No. Is it under one
  hundred and fifty? Yes: so the label is B, and the else block is skipped entirely.
  Read if blocks by their indentation: the indented lines belong to the condition above
  them. And elif and else are only checked when everything above them was False.
:::

:::scene{type=quiz}
question: "x = 5 and then, on the next line, if x = 5: — what happens?"
options:
  - It prints nothing, because 5 is not True
  - A SyntaxError — a single = is assignment, not a comparison
  - It runs, because x really is 5
answer: 1
pause: 5
explain: Inside a condition you need two equals signs. One = attaches a name to a value; == asks "are these equal?". Python refuses to guess which one you meant.
narration: |
  Quick check. X equals five. Then on the next line: if x equals five, with a single
  equals sign. What happens? A: it prints nothing. B: a syntax error, because a single
  equals is assignment, not a comparison. C: it runs, because x really is five. Pause
  and pick one.
after: |
  It is B. One equals sign attaches a name to a value. Two equals signs ask the
  question, are these equal. Python refuses to guess which one you meant, so it stops
  with a syntax error. You will make this mistake at least once. Now you know what the
  message means.
:::
