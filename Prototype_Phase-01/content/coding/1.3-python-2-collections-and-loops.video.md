:::scene{type=diagram id=collections}
heading: Four containers, chosen by what you need
narration: |
  Four containers, and you choose by what you need. A list keeps things in order and
  lets you change them. A tuple keeps things in order but is fixed once made. A set
  holds unique values with no order. And a dictionary looks things up by name. Watch
  how the figure builds: the shape of the brackets tells you which one you are looking
  at. Square for lists, round for tuples, curly for sets and dictionaries.
:::

:::scene{type=code}
heading: Lists — counting starts at 0
code: |
  rooms = ["kitchen", "living", "hall", "bed 1", "bath"]

  print(rooms[0])        # the first item
  print(rooms[-1])       # the last item
  print(rooms[1:3])      # items 1 and 2: start included, stop excluded
  rooms.append("bed 2")  # add to the end
  print(len(rooms))
output: |
  kitchen
  bath
  ['living', 'hall']
  6
note: rooms[0] is the first item. Negative numbers count from the end. A slice rooms[1:3] includes the start and excludes the stop.
narration: |
  A list is an ordered sequence in square brackets. It can grow, shrink and change.
  Here is the rule that trips everyone: counting starts at zero. Rooms zero is the
  first item, kitchen. Negative numbers count from the end, so rooms minus one is the
  last item, bath. A slice, one colon three, gives items one and two: the start is
  included, the stop is excluded. Append adds to the end. And len tells you how many
  items there are.
:::

:::scene{type=quiz}
question: rooms = ["a", "b", "c"] — what is rooms[3]?
options:
  - '"c", the third item'
  - An IndexError — the last valid index is 2
  - An empty string
answer: 1
pause: 5
explain: Three items live at indices 0, 1 and 2. The last valid index is always one less than the length. rooms[-1] is the safe way to say "the last one".
narration: |
  Check. Rooms is a list of a, b, c. What is rooms three? A: c, the third item. B: an
  index error, because the last valid index is two. C: an empty string. Pause and pick.
after: |
  It is B. Three items live at positions zero, one and two. The last valid index is
  always one less than the length. If you want the last one, rooms minus one is the safe
  way to say it, whatever the length.
:::

:::scene{type=code}
heading: Dictionaries — look things up by name
code: |
  areas = {"kitchen": 12.5, "living": 24.0, "hall": 6.0}

  print(areas["living"])            # look up by key
  areas["bath"] = 5.5               # add a new key
  print(areas.get("attic", 0))      # safe lookup: a default instead of an error
  print("hall" in areas)
output: |
  24.0
  0
  True
note: A dictionary is the shape of every JSON file and every table row you will meet. Key in, value out.
narration: |
  A dictionary maps keys to values. You look things up by name instead of by position:
  areas of living, not areas of one. It is the container you will use most after the
  list, and it is the shape of every JSON file and every table row you will ever meet.
  Square brackets with a key gives the value. Assigning to a new key adds it. Get, with
  a default, is the safe lookup: it returns the default instead of crashing when the key
  is missing. And in asks whether a key is there.
:::

:::scene{type=diagram id=for_loop}
heading: A for loop — one pass per item
narration: |
  Now the loops. A for loop runs a block once for each item in a sequence. Any items
  left? Take the next one, run the block, come back to the top. When nothing is left,
  carry on after the loop. You never write the counting yourself. Python hands you each
  item in turn.
:::

:::scene{type=code}
heading: A running total
code: |
  loads = [31.3, 13.3, 20.4, 25.4]
  total = 0
  for a in loads:
      total = total + a
  print(total)

  for i in range(3):
      print(i)
output: |
  90.4
  0
  1
  2
note: range(3) is 0, 1, 2 — three numbers, starting at 0, stopping before 3. The same rule as slices.
narration: |
  A running total. Total starts at zero. For each value in loads, add it to the total.
  The line total equals total plus a runs four times, once per item. And range three
  gives zero, one, two: three numbers, starting at zero, stopping before three. It is
  the same rule as slices. Almost every off by one bug in a beginner's code is this rule,
  so say it out loud once: starts at zero, stops before the number.
:::

:::scene{type=compare}
heading: for or while?
left:
  title: for
  points:
    - '"for each item in this sequence"'
    - You know what to visit
    - Lists, ranges, dictionary items, file lines
right:
  title: while
  points:
    - '"keep going while this is true"'
    - You know when to stop
    - Doubling until it fits, reading until the file ends
verdict: If a while loop seems to hang, its condition never became False. Ask — which line changes what the condition looks at?
narration: |
  Two kinds of loop. For is for each item in this sequence: you know what to visit.
  While is keep going while this is true: you know when to stop, but not how many
  times. Keep doubling until it fits. Keep reading until the file ends. One warning: if a
  while loop seems to hang, its condition never became False. Ask yourself which line
  changes the thing the condition looks at. If no line does, the loop never ends.
:::

:::scene{type=code}
heading: Real data is nested — a table is a list of dictionaries
code: |
  buildings = [
      {"name": "Library", "height": 7.0, "load": 31.3},
      {"name": "Studio",  "height": 3.5, "load": 13.3},
      {"name": "Lab",     "height": 7.0, "load": 25.4},
  ]
  for b in buildings:
      if b["height"] > 5:
          print(b["name"], b["load"])
output: |
  Library 31.3
  Lab 25.4
note: A list of dictionaries is what a spreadsheet looks like to Python. Module 5 does this whole loop in one line of pandas — knowing the loop version is what makes the one-liner legible.
narration: |
  Real data is nested. A list of buildings, each one a dictionary, each dictionary with
  a name, a height, a load. That is what a spreadsheet looks like to Python. The loop
  visits each building; the if keeps only the tall ones; the print shows their loads.
  In module five, pandas does this whole thing in one line. Knowing the loop version is
  what makes that one line legible instead of magic.
:::

:::scene{type=recap}
items:
  - List — ordered and changeable; counting starts at 0; slices exclude the stop
  - Dictionary — look up by name; .get(key, default) never crashes
  - for — one pass per item; range(n) is 0 to n-1
  - while — keep going while a condition is true; something must change it
  - A table is a list of dictionaries — loops nest the same way data does
narration: |
  To remember. A list is ordered and changeable, counting starts at zero, and a slice
  excludes its stop. A dictionary looks things up by name, and get with a default never
  crashes. For runs one pass per item, and range n goes from zero to n minus one. While
  keeps going while a condition is true, so something inside must change it. And a table
  is a list of dictionaries, so loops nest the same way the data does.
:::
