:::scene{type=title}
narration: |
  Welcome to lesson one point four, the last chapter of Python from zero. So far you have
  written code that runs once, from top to bottom. This lesson is about writing code you
  can reuse: functions, which you write once and call many times; classes, which bundle
  data with the functions that belong to it; libraries, which are code other people
  wrote for you; and errors, which are the most precise help you will ever get.
:::

:::scene{type=idea icon=warn}
text: Repeating yourself is a bug.
sub: If you compute an area in three places, you will fix a mistake in two of them.
narration: |
  Start with the reason all of this exists. Repeating yourself is a bug. If you compute
  an area in three places in your program, one day you will fix a mistake in two of them
  and forget the third. A function is the cure: write the calculation once, give it a
  name, and call it wherever you need it.
:::

:::scene{type=diagram id=function_call}
heading: A function call
narration: |
  Here is what a call looks like. Values go in as arguments. The body runs in its own
  private workspace, with those values under the names the function chose. And one
  value comes back out through return. The names inside the function never exist
  outside it. That is a feature: my total cannot collide with your total.
:::

:::scene{type=code}
heading: Define once, call twice
code: |
  def area(width, depth):
      result = width * depth
      return result

  kitchen = area(4, 3)
  living = area(6, 5)
  print(kitchen, living)
output: |
  12 30
note: def names the block and lists its parameters. Calling area(4, 3) runs the block with width 4 and depth 3. return hands one value back.
narration: |
  Def names a block and lists its parameters, width and depth. Calling area four, three
  runs the block with width equal to four and depth equal to three, and return hands
  the result back. Then we call it again with six and five. Two calls, one definition.
  One thing to watch: a function without a return gives back nothing, which Python calls
  None. If you print inside a function instead of returning, you will see the number on
  screen but you cannot use it.
:::

:::scene{type=compare}
heading: Function or method?
left:
  title: function(thing)
  points:
    - len(rooms)
    - sum(loads)
    - round(x, 1)
    - stands alone; the thing goes in the brackets
right:
  title: thing.method()
  points:
    - rooms.append(x)
    - name.upper()
    - df.head()
    - belongs to the thing; called with a dot
verdict: Nothing behind the dot is magic — a method is a function that lives inside the value.
narration: |
  You will meet two shapes. Len of rooms is a function: it stands alone, and the thing
  goes in the brackets. Rooms dot append is a method: a function that belongs to the
  list, called with a dot. Strings, lists, dictionaries, files, and every library
  object you meet come with methods. Nothing behind the dot is magic. A method is a
  function that lives inside the value.
:::

:::scene{type=code}
heading: Libraries — a toolbox someone else wrote
code: |
  import math
  print(math.sqrt(144))

  from statistics import mean
  print(mean([31.3, 13.3, 20.4]))

  import numpy as np
  print(np.array([1, 2, 3]) * 3.6)
output: |
  12.0
  21.666666666666668
  [ 3.6  7.2 10.8]
note: import brings a module in; the dot reaches inside it. "import numpy as np" is the alias everyone uses. Module 5 is about that last line — every element at once.
narration: |
  Python ships with hundreds of modules, and pip install adds thousands more. Import
  brings one in, and the dot reaches inside it. Math dot square root. Or you can import
  just one name, like mean. Or import a library under a short alias, which is how
  everyone writes numpy: import numpy as n p. Look at that last line: multiply a whole
  array by three point six, and every element is multiplied at once. Module five is
  built on that idea.
:::

:::scene{type=diagram id=traceback}
heading: Reading an error message
narration: |
  Now errors. You will see error messages every hour you write code, for as long as
  you write code. They are not failures. They are the most precise help you will get.
  Read them from the bottom up. The last line says what went wrong. The line above it
  says where. Everything before that ran fine. So: bottom line, what; line above, where;
  then go and look at that line.
:::

:::scene{type=quiz}

  - The variable needs to be declared before use, like in other languages

narration: |
  Check. The last line of an error says name error, name t o t l is not defined. What
  happened? A: Python deleted the variable. B: a typo, the name was written differently
  where it was created and where it was used. C: it needs to be declared first. Pause
  and pick.
after: |
  It is B. Python does not delete variables on its own, and it needs no declarations. A
  name error almost always means the name was spelled differently in two places. Search
  for total with an a, and you will find it. Reading the last line first turns a scary
  wall of text into a one word answer.
:::

:::scene{type=code}
heading: A class — a blueprint for many objects
code: |
  class Room:
      def __init__(self, name, width, depth):
          self.name = name
          self.width = width
          self.depth = depth

      def area(self):
          return self.width * self.depth

  kitchen = Room("kitchen", 4, 3)
  print(kitchen.name, kitchen.area())
output: |
  kitchen 12
note: A class says which data each object carries and which functions belong to it. self is the particular object the method was called on — kitchen, here.
narration: |
  A class is a blueprint: which data each thing carries, and which functions belong to
  it. An object is one thing built from the blueprint. The special method init runs
  when you build an object, and self is the object being built: self dot name stores
  the name on it. Later, kitchen dot area calls the method on that object, and self is
  kitchen. You will write very few classes in this course and use hundreds. The point
  of writing one is to see that d f dot head, later, is just a method on an object.
:::

:::scene{type=code}
heading: Files — data lives on disk
code: |
  with open("rooms.csv") as f:
      for line in f:
          name, width, depth = line.strip().split(",")
          print(name, float(width) * float(depth))
output: |
  kitchen 12.0
  living 30.0
note: with open(...) as f closes the file for you, even if something goes wrong inside. Values read from a file are text until you convert them.
narration: |
  Data lives in files. With open, as f, is the pattern: the file is closed automatically
  at the end of the block, even if an error happens inside it. Each line arrives as
  text, so you split it at the commas and convert the numbers with float. That last
  point is the most common beginner bug in data work: values read from a file are text
  until you convert them. Pandas, in module five, does that conversion for you, but now
  you know what it is doing.
:::
