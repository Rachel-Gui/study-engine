## Before anything else

You have never run a line of Python. That is fine — nobody in this course assumes you
have. This guide takes you from a blank laptop to a working setup in about 45 minutes,
and every command in it has two versions: one for **Windows**, one for **macOS**. Pick
your tab once; the site remembers it on every page.

:::narration

## Step 1 — Install Python

Python is the language every lab and notebook in this course is written in. You need
version **3.10 or newer**; anything python.org offers today is newer than that.

:::os
[windows]
Go to [python.org/downloads](https://www.python.org/downloads/). On Windows the big
yellow button now reads **Download Python install manager** — the route python.org
recommends. Click it, open the downloaded file, and click **Install**.

![python.org/downloads on a Windows laptop. The main button installs the Python install manager; the link underneath is the older standalone installer.](assets/setup/real/pyorg-win.png)

Then open a **new** terminal (Start menu → type `Terminal` → Enter) and type:

```
python --version
```

The first time, the install manager downloads and installs the latest Python by itself
and may ask whether to add a folder to your PATH — answer **y** (yes). When it finishes
you should see `Python 3.1x.x`. If you see "not recognized", close the terminal, open a
new one, and try again.

**If the install manager will not install** (some managed university laptops block it),
use the **standalone installer** link under the button instead. On its first screen,
tick **"Add python.exe to PATH"** before clicking Install Now:
[mac]
Go to [python.org/downloads](https://www.python.org/downloads/). On a Mac the yellow
button downloads the macOS installer for the newest Python. Open it and accept the
defaults.

![python.org/downloads on a Mac: one button, the macOS installer for the newest release.](assets/setup/real/pyorg-mac.png)

**Always type `python3`, not `python`.** Plain `python` on a Mac often points to an old
built-in version or does not exist at all. Every Mac command in this course uses
`python3` and `pip3` for that reason.

Verify — open Terminal (Cmd+Space, type `Terminal`, Enter) and type:

```
python3 --version
```

You should see `Python 3.1x.x`. If you see "command not found", close Terminal, open it
again, and try again.
:::

You installed Python on Windows, opened the terminal that was already open before you
installed, and typed `python --version`. It says "not recognized". What is the most
likely cause?
- Python installed incorrectly | Probably not. The installer rarely fails silently.
- *The terminal was open before the install, so it does not know the new PATH yet | Yes. Windows only reads PATH when a terminal starts. Close it and open a fresh one.
- You need to restart the computer | Almost never. A new terminal is enough.

## Step 2 — Install VS Code

VS Code is the editor you will use to open and edit code. Any real code editor works
(PyCharm, Sublime), but the course instructions assume VS Code.

Go to [code.visualstudio.com](https://code.visualstudio.com/), download the installer
for your system, run it, and accept the defaults.

:::screenshot{src=assets/setup/real/vscode-dl.png caption="code.visualstudio.com. The download button matches your system; on a Mac it reads Download for macOS."}
:::

:::keyidea
**Do not edit code in Notepad, TextEdit, or Word.** They silently change indentation and
quotation marks, and Python breaks in ways that are painful to debug.
:::

After it opens, install two extensions. Click the Extensions icon in the left bar (four
squares), search for each, and click Install:

- **Python** (by Microsoft) — syntax colouring, run button, error underlines
- **Jupyter** (by Microsoft) — opens the course `.ipynb` notebooks inside VS Code

:::screenshot{src=assets/setup/real/vscode-hello.png caption="VS Code with the course folder open. Left: the Explorer, listing the files in the folder. Middle: the editor, showing hello.py. Bottom: the terminal panel, already inside the folder — python hello.py runs the file and prints area: 24."}
:::

:::os
[windows]
Open a project folder with **File → Open Folder…**. Open a terminal inside VS Code with
**Terminal → New Terminal** (or `Ctrl+backtick`). That terminal already starts in your
project folder, which sidesteps the most common mistake in Step 3.
[mac]
Open a project folder with **File → Open Folder…**. Open a terminal inside VS Code with
**Terminal → New Terminal** (or `Ctrl+backtick`). That terminal already starts in your
project folder, which sidesteps the most common mistake in Step 3.

If macOS asks you to install "command line developer tools" the first time, click
Install and wait — it is a one-time step.
:::

## Step 3 — The terminal, and the one mistake everyone makes

The terminal is a text window where you type commands. Every install command in this
course runs there. **Commands only work if the terminal is sitting inside the right
folder** — and a terminal opened from the Start menu or Spotlight starts in your home
folder, which is the wrong place.

:::screenshot{src=assets/setup/real/vscode-basics.png caption="The terminal (here, the one inside VS Code). The prompt — PS C:\\Users\\you\\Documents\\ai-course> — is the folder you are in. cd data moves in and the prompt changes; dir lists the files; cd .. moves back up. On Windows, dir prints a longer table with dates; the files are the same."}
:::

:::os
[windows]
**Easiest — right-click in File Explorer.** Navigate to the folder you want, right-click
it, and choose **Open in Terminal** (Windows 11) or hold **Shift** and right-click →
**Open PowerShell window here** (Windows 10).

**Or type the path yourself:**

```
cd "C:\Users\you\Documents\ai-course"
```

Confirm where you are:

```
dir
```

You should see the files you expect. If not, you are in the wrong folder.
[mac]
**Easiest — drag the folder into Terminal.** Open Terminal, type `cd ` (with a space,
do not press Enter), then drag the folder from Finder onto the Terminal window. macOS
pastes the full path. Now press Enter.

**Or** right-click a folder in Finder → **Services → New Terminal at Folder**.

Confirm where you are:

```
ls
```

You should see the files you expect. If not, you are in the wrong folder.
:::

Four commands you will use constantly:

:::cards
cd folder | change into a folder | `cd Documents`
cd .. | go up one level | back to the parent folder
dir  /  ls | list what is here | Windows / macOS
Ctrl+C | stop whatever is running | works everywhere
:::

## Step 4 — Install the course libraries

Python itself is small. The tools this course uses — tables, plotting, machine learning
— are libraries you install once with `pip`, Python's package installer.

:::os
[windows]
```
python -m pip install --upgrade pip
python -m pip install numpy pandas matplotlib scikit-learn jupyter
```

Use `python -m pip …`, exactly as written. If you see **"Fatal error in launcher"**, the
`pip` shortcut is broken but this form still works. If even that fails, try
`py -m pip install …`.

Verify:

```
python -c "import numpy, pandas, sklearn, matplotlib; print('ready')"
```
[mac]
```
pip3 install --upgrade pip
pip3 install numpy pandas matplotlib scikit-learn jupyter
```

**Do not use `sudo`.** If you see a permission error, run the command again without
it. If it still fails, your Python was installed as root — reinstall it from
python.org.

Verify:

```
python3 -c "import numpy, pandas, sklearn, matplotlib; print('ready')"
```
:::

It takes one to three minutes and prints a lot of "Successfully installed…" lines. A
few yellow warnings are normal.

:::screenshot{src=assets/setup/real/vscode-pip.png caption="A real install, start to finish: pip downloads the libraries and everything they depend on, ends with a long Successfully installed… line, and the one-line check underneath prints ready. Your version numbers will be the newest ones on the day you install."}
:::

:::cards
numpy | arrays and maths | every numeric lab
pandas | tables, CSV files | the UW and appliance datasets
matplotlib | plots | learning curves, feature importance
scikit-learn | classical ML and small networks | regression, classification, MLPRegressor
jupyter | notebooks on your own machine | optional — Colab does this in the browser
:::

:::technical{summary="Optional: keep projects separate with a virtual environment"}
A virtual environment is a private copy of Python's libraries for one project, so a
package you install for one course cannot break another. You do not need this for the
course, but if you go on to build your own projects you will want it.

```
python -m venv .venv          # Windows      (python3 on macOS)
.venv\Scripts\activate         # Windows
source .venv/bin/activate      # macOS
```

The prompt shows `(.venv)` while it is active. Install packages as usual; they land
inside `.venv`. Type `deactivate` to leave.
:::

## Step 5 — Google Colab: Python with nothing installed

Most of the course notebooks are designed to run in **Google Colab**, which is a
Jupyter notebook that runs in Google's cloud. Nothing to install, a free GPU when you
need one, and it works the same on every laptop.

Go to [colab.research.google.com](https://colab.research.google.com/), sign in with a
Google account, and click **New notebook** (or **File → New notebook**). You are now
editing a notebook.

:::screenshot{src=assets/setup/real/colab-home.png caption="The Colab start page. Sign in (top right), then New notebook. Welcome to Colab, under Example notebooks, is a good five-minute tour."}
:::

:::workflow
Cells | A notebook is a list of cells. Code cells run Python; text cells hold notes. Click a cell and press **Shift+Enter** to run it. | 
Runtime | The computer your code runs on, in the cloud. **Runtime → Run all** executes every cell in order. It resets after ~90 idle minutes; that is normal — just run the cells again. | 
GPU | **Runtime → Change runtime type → T4 GPU.** Only the deep-learning notebooks benefit; leave it off otherwise so you keep your free quota. | 
Files | The folder icon on the left. Files you download inside a notebook (`!gdown …`) land here and vanish when the runtime resets. Re-run the download cell. | 
Installing | A cell starting with `!pip install …` installs into that runtime only. Most of what the course needs is pre-installed. | 
Saving | Colab saves to your Google Drive automatically. **File → Save a copy in Drive** if you opened someone else's notebook. | 
:::

Try it now — paste this into a cell and press Shift+Enter:

```
import numpy as np, pandas as pd, sklearn, matplotlib
print("numpy", np.__version__, "· pandas", pd.__version__, "· scikit-learn", sklearn.__version__)
```

:::screenshot{src=assets/setup/real/colab-nb.png caption="A Colab notebook. Text cells and code cells alternate; the code cell at the bottom has run, and its output — 86400 — sits underneath it. The menu bar holds Runtime → Run all; Connect (top right) starts the computer your code runs on."}
:::

:::keyidea
**Colab for notebooks, your laptop for the hands-on lessons.** The ML and deep-learning
notebooks run in Colab. The Environmental Negotiators (Module 4) run on your own machine,
because it needs a local model and two servers. You need both.
:::

## Troubleshooting

| OS | What you see | What to do |
|---|---|---|
| Windows | `'python' is not recognized` | Open a **new** terminal first. With the install manager, run `py install --refresh` and add the folder it names to PATH; with the standalone installer, reinstall with "Add python.exe to PATH" ticked. `py` works in both cases. |
| Windows | `'pip' is not recognized` | Same cause. Use `python -m pip` everywhere the guide says `pip`. |
| Windows | `Fatal error in launcher` | The pip shortcut is broken. `python -m pip install …` still works. |
| macOS | `python: command not found` | Use `python3` and `pip3`. This applies to every command. |
| macOS | `Permission denied` / `EACCES` | Do not use `sudo`. Retry without it; if it persists, reinstall Python from python.org. |
| Both | `No such file or directory` | The terminal is not in the folder you think. Go back to Step 3. |
| Both | A command you just installed is "not found" | Close the terminal and open a new one. New installs only appear in fresh terminals. |
| Both | `pip install` hangs on university Wi-Fi | Some campus networks block package downloads. Try a phone hotspot. |
| Colab | "Runtime disconnected" | Normal after idle time. Runtime → Run all. |
| Colab | `ModuleNotFoundError` after a reset | Re-run the `!pip install` cell; the runtime forgot it. |
