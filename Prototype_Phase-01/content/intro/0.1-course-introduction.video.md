  A I is not one method. In architecture, many contemporary A I workflows can be
  understood through three broad roles. Each role produces a different kind of
  output, and each has to be checked in its own way.

narration: |
  Generative A I creates or proposes new content, such as images, text, code, or design
  representations: here, a community library generated from a single prompt. Agentic A I
  goes beyond a single response: agents can plan, use tools, take actions, and respond
  to feedback, like an agent that runs a daylight simulation, revises a facade, and
  checks again, with a designer approving the result. Machine learning and deep
  learning learn patterns from data to support tasks such as prediction,
  classification, analysis, and representation. The prediction plot here uses
  illustrative points to explain these tasks; it does not show actual model results.
:::

:::scene{type=diagram id=ai_hierarchy}
heading: Overlapping areas, not parallel branches
narration: |
  These areas are not separate. Many generative and agentic systems are themselves built
  on deep-learning models. Artificial intelligence is the broadest field. Machine
  learning is one family of methods within it: systems that learn patterns from data.
  Deep learning is a subset of machine learning, using many layered neural
  networks. And most of today's generative models, and the language models inside
  most agents, are deep networks. An agent also uses tools, memory and control code
  that are not learned at all. So we use these three roles as a practical way to
  organize the course, not as three separate kinds of A I.
:::

:::scene{type=idea icon=warn}
text: A plausible output is not evidence.
sub: An image is not a building. A fluent answer is not a fact. A high score on the training data is not a result.
narration: |
  Here is the thread that runs through every module. A plausible output is not
  evidence. An image is not a building. A fluent answer is not a fact. A high score on
  the data a model was trained on is not a result. Each module teaches the checks that
  turn a possibility into a claim you can defend in front of a client, a reviewer, or a
  building inspector.
:::

  Eight modules. Module one teaches Python from zero, in the browser, with nothing to
  install. Module two is generative A I: images, prompts, and language models, and the
  judgment to tell a plausible picture from evidence. Module three is coding with an A I
  assistant, and reading what it writes. Module four builds agents that plan, use
  tools, and act, and runs several of them on one design question. Then the course
  turns to how data driven models work. Module five is looking at data
  before you model it. Module six fits machine learning models and evaluates them on
  data they have never seen. Module seven opens the neural network. Module eight applies
  deep networks to images, graphs, time, and physics.

narration: |
  Think of the course as two arcs. The first arc, modules one to four, is about
  building and using contemporary A I workflows: writing code, generating and
  critiquing designs, coding with an assistant, and building agents. The second arc,
  modules five to eight, is about understanding data driven A I models: looking at the
  data, fitting and evaluating models on data they have never seen, and opening up the
  deep networks that generative and agentic tools are built on. Both arcs rest on data
  and models. The first uses them. The second opens them up.
:::
