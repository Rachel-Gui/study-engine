## What this course is about

AI is not one method. In architecture, many contemporary AI workflows can be
understood through three broad roles, and this course is organized around them.
**Generative AI** creates or proposes new content — text, images, code, geometry and
other design representations. **Agentic AI** goes beyond a single response: agents
pursue goals through planning, tool use, actions and feedback, with human oversight
where needed. **Machine learning and deep learning** learn patterns from data to
support prediction, classification, analysis and representation. The course teaches
all three roles — what each can and cannot establish, how to control it, and how to
check its output before a design decision rests on it.

These three are **not parallel or mutually exclusive categories**. Machine learning is
a broad family of methods within AI; deep learning is a subset of machine
learning; and many current generative and agentic systems are themselves built on
deep-learning models — diffusion models and large language models are deep networks,
and most agents are a language model plus tools, memory and control code. Figure 2
shows the overlap.

:::figure{id=ai_hierarchy caption="Figure 2. Overlapping areas, not parallel branches. Deep learning is a subset of machine learning, which is a subset of AI. :::

:::keyidea
The thread through every module: **a plausible output is not evidence.** An image is
not a building, a fluent answer is not a fact, and a high score on training data is
not a result. Each module teaches the checks that turn a possibility into a claim you
can defend.
:::

## Learning objectives

By the end of this course, students will be able to:

1. Explain core concepts, methods, and workflows across generative AI, agentic AI, machine learning, and deep learning.
2. Develop and adapt computational workflows using Python, data, and relevant AI methods and tools for architectural applications.
3. Apply, test, and evaluate AI models and workflows for architectural design, performance modeling, analysis, prediction, representation, and decision support.
4. Interpret AI outputs critically, including model performance, uncertainty, generalization, limitations, and appropriate validation requirements.
5. Integrate AI into architectural workflows with informed human judgment while considering accountability, bias, authorship, and broader societal and environmental impacts.

## How the modules connect

:::figure{id=course_map caption="Figure 3. The eight modules, in two arcs."}
:::

The course runs in two arcs. The **first arc**, Modules 1 to 4, is about **building
and using contemporary AI workflows**: writing and reading code, generating and
critiquing designs, coding with an assistant, and building agents that use tools. The
**second arc**, Modules 5 to 8, is about **understanding data-driven AI models**:
looking at data, fitting and evaluating models on data they have not seen, and opening
up the deep networks that generative and agentic tools are built on. Both arcs rest on
data and models — the first uses them, the second opens them up — and the accuracy
boundaries (Reference 9.1) are the checklist for both.

:::cards
Module 1 · Coding Foundations | Python from zero, in the browser | skip if you already write Python
Module 2 · Generative AI | generate, control, critique, translate — and judge | diffusion, prompts, LLMs, a local model, critical AI in architecture
Module 3 · AI-Assisted Coding and Vibe Coding | read, check and debug what the assistant writes | Claude Code on your own model; code as a design medium
Module 4 · Agentic AI | agents that plan, use tools and act; orchestration; frameworks | the Environmental Negotiators, on your own laptop
Module 5 · Exploratory Data Analysis | look before you model | numpy, pandas, matplotlib, seaborn, scipy
Module 6 · Machine Learning | features, targets, evaluation on unseen data | regression and classification on UW campus data
Module 7 · Deep Learning Foundations | neurons, learning, generalisation | an ANN on real sensor data
Module 8 · Advanced Deep Learning | CNNs, GNNs, sequences, PINNs, INRs | a PINN built from scratch
:::

Each module page ends with a short list of **selected readings** —
papers and reviews for going further, with preprints labelled and a line explaining
why each reading is useful —
and all of them are collected on one [readings page](readings.html).

## How to use the Study Engine

Every module has a landing page, every lesson a list of topics, and every topic is one
page. The left panel is the full table of contents; the arrows at the bottom of each
page (or the ← → keys) walk through the course in order.

:::cards
Grey code boxes | run Python in your browser | press Run step; edit anything; nothing to install
Purple step-through boxes | replay a program line by line | watch the variables change
Interactive figures | sliders and buttons on a diagram | the fastest way to feel an idea
Try / Predict cards | commit to an answer before reading on | feedback on every option
Claim boundary cards | what a result does and does not establish | the habit this course is built on
Narrated videos | one per lesson, animated, with a pause-and-predict quiz | to preview or review a lesson
:::

:::keyidea
**Run everything.** The labs are the course. Reading a code box is not the same as
pressing Run, changing a number, and pressing Run again — and the second run is where
the learning happens.
:::
