Architecture now has three kinds of AI at its disposal, and they do different things.
**Generative AI** proposes: images, text, code, geometry. **Agentic AI** acts: it plans,
calls tools, and works through a task with checks along the way. **Machine learning and
deep learning** predict and explain: they learn from measured or simulated data how a
building will perform. This course teaches all three — what each one can and cannot
establish, how to control it, and how to check its output before a design decision
rests on it.

:::cards
Generative AI | proposes | images, text, code and geometry, conditioned on prompts, references and constraints
Agentic AI | acts | agents that plan, call tools and negotiate — with a human in the loop
Machine and deep learning | predicts and explains | models fitted to measured or simulated building data, and evaluated on data they have not seen
:::

:::keyidea
The thread through every module: **a plausible output is not evidence.** An image is
not a building, a fluent answer is not a fact, and a high score on training data is
not a result. Each module teaches the checks that turn a possibility into a claim you
can defend.
:::

## What you will be able to do

By the end of the course you will be able to:

- Read and write the Python that the course uses, from a blank laptop.
- Explain what generative models learn, control what they produce, translate a
  generated possibility into geometry that can be analysed before performance claims,
  and say who is responsible for what an AI output becomes.
- Use AI-assisted coding to build small, reproducible design tools, and review the
  code it writes.
- Define agents as structured prompts, orchestrate several of them, and run a
  multi-agent design negotiation on your own machine.
- Explore a dataset before modelling it: distributions, relationships, and what they
  do not establish.
- Frame an architectural question as features, a target and a model; train
  regression and classification models and evaluate them on data they have never seen.
- Explain how neural networks learn and generalise, and match CNNs, GNNs, sequence
  models, physics-informed networks and neural fields to the data they suit.
- State, for any result, its data range, its evaluation, its uncertainty and its known
  failure conditions.

## How the modules connect

:::figure{id=course_map caption="Figure 1. The eight modules. Modules 1–4 are about making; Modules 5–8 are about learning from data. Every module is checked against the accuracy boundaries in the Reference section."}
:::

Modules 1 to 4 are about **making**: writing code, generating possibilities, coding
with an assistant, and building agents that act. Modules 5 to 8 are about
**learning from data**: looking at it, fitting models to it, and understanding the
networks behind those models. The two halves meet in the hands-on lessons — the agents of
Module 4 argue about the energy loads that Modules 6 to 8 predict — and in the
accuracy boundaries (Reference 9.1) that every module is checked against.

:::cards
Module 1 · Coding Foundations | Python from zero, in the browser | skip if you already write Python
Module 2 · Generative AI | generate, control, critique, translate — and judge | diffusion, prompts, LLMs, a local model, critical AI in architecture
Module 3 · AI-Assisted Coding and Vibe Coding | read, check and debug what the assistant writes | Claude Code on your own model; code as a design medium
Module 4 · Agentic AI | agents, orchestration, frameworks | the Environmental Negotiators, on your own laptop
Module 5 · Exploratory Data Analysis | look before you model | numpy, pandas, matplotlib, seaborn, scipy
Module 6 · Machine Learning | features, targets, evaluation on unseen data | regression and classification on UW campus data
Module 7 · Deep Learning Foundations | neurons, learning, generalisation | an ANN on real sensor data
Module 8 · Advanced Deep Learning | CNNs, GNNs, sequences, PINNs, INRs | a PINN built from scratch
:::

Each module page ends with a short list of **selected readings** — recent
peer-reviewed reviews the module's definitions and diagrams were checked against —
and all of them are collected on one [readings page](readings.html).

## How to use the Study Engine

Every module has a landing page, every lesson a list of topics, and every topic is one
page. The left panel is the full table of contents; the arrows at the bottom of each
page (or the ← → keys) walk through the course in order.

:::cards
Grey code boxes | run Python in your browser | press Run step; edit anything; nothing to install
Purple step-through boxes | replay a program line by line | watch the variables change
Interactive figures | sliders and buttons on a diagram | the fastest way to feel an idea
Try / Predict cards | commit to an answer before reading on | feedback on every option
Claim boundary cards | what a result does and does not establish | the habit this course is built on
Narrated videos | one per lesson, animated, with a pause-and-predict quiz | for review, or for a class that cannot run the labs
:::

:::keyidea
**Run everything.** The labs are the course. Reading a code box is not the same as
pressing Run, changing a number, and pressing Run again — and the second run is where
the learning happens.
:::
