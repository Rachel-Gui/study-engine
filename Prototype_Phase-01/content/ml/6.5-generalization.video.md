:::scene{type=title}
narration: |
  Welcome to lesson six point five, generalization and reliable model evaluation. This
  is the lesson the whole module has been pointing at. A model is only worth what it
  can do on data it has never seen. Everything else, the training score, the beautiful
  fit, the high R squared, is a description of the past. Here you learn how to measure
  the thing that matters, and the three ways people accidentally cheat.
:::

:::scene{type=idea icon=question}
text: How do you find out what your model is worth / on data it has never seen?
sub: You cannot ask the future. So you hide part of the present, and pretend.
narration: |
  The question: how do you find out what your model is worth on data it has never seen?
  You cannot ask the future. So you do the next best thing. You hide part of the data
  you have, fit the model on the rest, and then unveil the hidden part and see how it
  does. Everything in this lesson is about doing that hiding without leaks.
:::

:::scene{type=cards}
heading: One dataset, three jobs
items:
  - title: Training set
    text: Fits the weights. The model sees the answers here.
    tag: learn
  - title: Validation set
    text: Decides when to stop, and which settings to keep. Never trained on.
    tag: choose
  - title: Test set
    text: Reported once, at the very end. Tune against it and it stops being a test.
    tag: report once
narration: |
  One dataset, three jobs. The training set fits the weights; the model sees the
  answers here. The validation set decides when to stop and which settings to keep; the
  model never trains on it, but you look at it constantly. The test set is reported
  once, at the very end. The moment you tune anything against it, it stops being a test
  and becomes a second validation set, and your final number is no longer an estimate of
  anything.
:::

:::scene{type=diagram id=overfitting}
heading: Training loss always falls. Validation loss tells the truth.
points:
  - Training curve — keeps improving, whatever happens
  - Validation curve — stops improving, then turns upward
  - The turn — where the model starts memorising instead of learning
  - Stop there — that is what the validation set is for
narration: |
  Watch the two curves. The training loss always falls; the model can always fit its
  own training data a little better. The validation loss falls too, at first, and then
  it stops, and turns upward. That turn is the moment the model stops learning patterns
  that hold for new data and starts memorising the training data. The validation set
  exists to catch that moment. Stop there.
:::

:::scene{type=list}
heading: Three regimes
items:
  - Underfitting — too simple, or trained too briefly; both errors high
  - Good generalization — both errors acceptable, and close together
  - Overfitting — training keeps improving while validation stops or gets worse
narration: |
  The same picture gives three regimes. Underfitting: the model is too simple or was
  trained too briefly, and both errors are high. Good generalization: both errors are
  acceptable, and close to each other. Overfitting: training keeps improving while
  validation stops or gets worse. The gap between the two curves is the number to watch,
  not either curve on its own.
:::

:::scene{type=idea icon=warn}
text: Split by building, site or time. / Not by row.
sub: Neighbouring buildings, repeated simulations of one geometry and time-adjacent readings are near duplicates. Scatter them across a random split and the test set is full of things the model has already seen.
narration: |
  Now the way architectural data cheats on you. Neighbouring buildings look alike.
  Repeated simulations of one geometry are near copies of each other. Sensor readings
  ten minutes apart are almost the same reading. Split those randomly by row, and the
  test set is full of things the model has effectively already seen. The score looks
  wonderful and means nothing. Split by building, by site, or by time, so the test set
  holds things that are actually new.
:::

:::scene{type=diagram id=split_strategies}
heading: Three ways to split the same data
points:
  - Random split — does the model know these buildings? Usually yes, by accident
  - Chronological — train on the past, test on the future. Will it work next month?
  - Grouped by building — no building on both sides. Will it work on a new one?
narration: |
  Here are the three splits side by side. Random: shuffle and hold out twenty percent.
  Fast, common, and leaky whenever rows are near duplicates: the model usually knows the
  test buildings by accident. Chronological: train on the past, test on the future. It
  answers the question, will it work next month, and it is the only valid split for
  sensor data. Grouped by building: no building on both sides of the line, so the test
  asks, will it work on a building it has never seen. In lesson seven point four you
  will watch the same network score respectably on a random split of sensor data, and
  collapse on a chronological one.
:::

:::scene{type=idea icon=loop}
text: Cross-validation gives you a spread, / not just a mean.
sub: Rotate which slice is held out, average the scores, and report the range too. A score that swings between folds is telling you something one number hides.
narration: |
  Cross validation is hiding done several times. Rotate which slice is held out, fit,
  score, and repeat until every slice has been the test once. Then you have several
  scores, not one. Report the mean, and report the spread. A model whose score swings
  widely from fold to fold is telling you something a single number would hide: it
  depends on which buildings it happened to see. And the grouping rule from a minute
  ago applies to every fold.
:::

:::scene{type=recap}
items:
  - A model is worth what it does on data it has never seen
  - Training fits, validation chooses, test is reported once
  - Training loss always falls; watch the validation curve turn
  - Split by building, site or time — never merely by row
  - Cross-validation — report the spread as well as the mean
narration: |
  To remember. A model is worth what it does on data it has never seen. Training fits,
  validation chooses, test is reported once. Training loss always falls, so watch the
  validation curve for the turn. Split by building, site or time, never merely by row.
  And with cross validation, report the spread as well as the mean.
:::
