## Central question

How do you find out what your model is worth on data it has never seen?

:::narration
This episode is the bridge between module two and module three, and it is the one
idea the whole course keeps returning to. Training performance is not performance. It
is the score on the questions the model was given the answers to. The only number
worth reporting is the one measured on data the model has never seen, split in a way
that reflects how it would actually be used.
:::

## One dataset, three jobs

:::cards
Training set | Fits the weights | The model sees the answers here
Validation set | Decides when to stop, and which settings to keep | Never trained on
Test set | Reported once, at the very end | Tune against it and it stops being a test
:::

:::figure{id=overfitting caption="Figure 1. Training loss always falls. Validation loss is the one that tells the truth. Redrawn for this module."}
:::

## Underfitting, good fit, overfitting

- **{{Underfitting}}** — too simple or too briefly trained; both errors high.
- **Good {{generalization}}** — both acceptable, and close together.
- **{{Overfitting}}** — training keeps improving while validation stops or worsens.

## Splitting for architectural data

:::keyidea
Split by **building, site, or time** — not merely by row. Neighbouring buildings,
repeated simulations of one geometry, and time-adjacent sensor readings are near
duplicates. Scatter them across a random split and the model is tested on data it has
effectively already seen.
:::

Episode 3.7 measures exactly what that costs: the same network scores R² 0.380 on a
random split of ten-minute sensor data, and the score collapses on a chronological one.

## Cross-validation

{{Cross-validation}} rotates which slice is held out and averages the result, which
gives you a spread as well as a mean. Report both. A model whose score swings widely
across folds is telling you something a single number hides.

:::reflect
You have 40 simulation runs across 8 building geometries, 5 runs each. How should you
split?
- Randomly, 80/20 across all 40 runs
- *By geometry — all 5 runs of one building stay in the same fold
- By run number, so each fold gets one run from each geometry
:::
