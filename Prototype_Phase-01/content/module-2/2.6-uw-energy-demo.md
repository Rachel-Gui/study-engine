## About the UW building energy dataset

:::narration
This is a complete regression workflow on U W campus building data. Each of the one
hundred and twenty one rows represents one building. The nineteen columns describe
geometry, operation, program, environment, and annual energy use. We will treat
annual energy use as the target, while staying honest about fields whose units or
definitions are not documented.
:::

:::stats
121 | buildings: one row per building
19 | columns
Energy_Use_kWh | target: annual energy use
:::

The predictors fall into four useful groups: **geometric**, **operational**,
**program**, and **environmental**. These groups help us reason about a feature set;
they do not imply that every available column belongs in a model.

:::details{summary="Open the data dictionary"}
**Target**

- `Energy_Use_kWh` — annual energy use in kilowatt-hours (kWh).

**Geometric predictors**

- `Area_m` — building area field. The source does not resolve the exact definition or unit.
- `Height` — building height field. The unit is unresolved in the source.
- `Building_Length_m` — building length in metres.
- `Orientation (degrees north)` — orientation in degrees north.
- `Relative Compactness` — compactness measure. Its exact calculation is not documented here.

**Operational predictors**

- `Year_Built` — calendar year of construction.
- `Occupants` — occupant field. How it was derived is unresolved in the source.

**Program predictors**

- `apartments`, `parking`, `stadium`, `university`, `utility`, `warehouse` — binary program indicators.

**Environmental predictors**

- `Tree_Canopy` — tree-canopy field. Its unit and derivation are unresolved in the source.
- `Land_Surface_Temp` — land-surface-temperature field. Its unit is unresolved in the source.

**Identifiers and location**

- `Name` — building name.
- `Longitude`, `Latitude` — geographic coordinates.
:::

:::keyidea
**Data quality is part of the model.**

The file has no blank cells, but it is not automatically analysis-ready. Two rows
share the name **Odegaard Library**, four records report zero annual energy, and
some units or field definitions remain unresolved. We will report these observations
rather than silently deleting or explaining them away.
:::

# step: 1 — Load
import io, base64, json
import numpy as np
import pandas as pd
import matplotlib
# Export PNGs into the step output without creating browser-managed figure windows.
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from pyodide.http import open_url

DATA = "assets/data/UW_building_energy.csv"

def lab_output(*blocks):
    """Return teaching results using the reusable pylab output format."""
    return json.dumps({"type": "pylab-output", "blocks": blocks})

def metrics(*items):
    return {"type": "metrics", "items": list(items)}

def note(text):
    return {"type": "text", "text": text}

def table(frame, caption):
    return {"type": "table", "caption": caption,
            "columns": list(frame.columns),
            "rows": frame.fillna("—").astype(str).values.tolist()}

def details(summary, *blocks):
    return {"type": "details", "summary": summary, "blocks": list(blocks)}

def figure_data_url(fig):
    """Return a Matplotlib figure for display in this step's output."""
    buffer = io.BytesIO()
    fig.savefig(buffer, format="png", dpi=150, bbox_inches="tight", facecolor="white")
    plt.close(fig)
    return "data:image/png;base64," + base64.b64encode(buffer.getvalue()).decode("ascii")

df = pd.read_csv(open_url(DATA))
df.columns = df.columns.str.strip()  # normalize accidental header whitespace

preview = df[["Name", "Energy_Use_kWh", "Area_m", "Year_Built"]].head(4).round(1)
lab_output(
    metrics({"label": "UW dataset loaded", "value": f"{len(df)} buildings × {len(df.columns)} columns", "primary": True}),
    table(preview, "First four buildings · selected columns"),
    note("One row represents one building. Annual energy use is measured in kWh; the Area_m definition and unit remain unresolved."),
)

# step: 2 — Inspect
summary_columns = ["Energy_Use_kWh", "Area_m", "Height", "Year_Built", "Occupants"]
duplicate_names = df.loc[df["Name"].duplicated(keep=False), "Name"].value_counts()
zero_energy = df.loc[df["Energy_Use_kWh"] == 0, "Name"].tolist()
column_audit = pd.DataFrame({"Column": df.columns, "Type": df.dtypes.astype(str).to_numpy(),
                             "Missing": df.isna().sum().to_numpy()})
summary = df[summary_columns].describe().T[["min", "50%", "max"]].round(1)
summary = summary.rename(columns={"50%": "Median"}).reset_index(names="Field")
lab_output(
    metrics({"label": "Columns", "value": str(len(df.columns))},
            {"label": "Missing cells", "value": str(int(df.isna().sum().sum()))},
            {"label": "Repeated names", "value": str(len(duplicate_names))},
            {"label": "Zero-energy records", "value": str(len(zero_energy))}),
    note(f"Types: {len(df.select_dtypes(include='number').columns)} numeric columns and {len(df.select_dtypes(exclude='number').columns)} text column(s)."),
    note("Repeated names: " + (", ".join(f"{name} ({count} rows)" for name, count in duplicate_names.items()) or "none")),
    table(summary, "Selected numeric fields · minimum, median, maximum"),
    details("View all columns, types and missing values", table(column_audit, "Column audit")),
    details("View zero-energy buildings", note(", ".join(zero_energy) or "None")),
    note("No missing cells does not mean no data-quality issues. Check repeated names, zeros, ranges and unresolved units before modeling."),
)

# step: 3 — Clean
# This is the course's modeling-scope rule, not a universal definition of an outlier.
in_scope = (df["Energy_Use_kWh"] <= 10_000_000) & (df["Area_m"] <= 60_000)
model_df = df.loc[in_scope].copy()
excluded = df.loc[~in_scope, ["Name", "Energy_Use_kWh", "Area_m"]]

lab_output(
    metrics({"label": "Course modeling scope", "value": f"{len(df)} → {len(model_df)} buildings", "primary": True}),
    note(f"{len(excluded)} records outside the course modeling scope."),
    note("Keep Energy_Use_kWh ≤ 10,000,000 and Area_m ≤ 60,000. These are course modeling-scope rules, not universal definitions of outliers."),
    note(f"Retained: {(model_df['Energy_Use_kWh'] == 0).sum()} zero-energy records and {(model_df['Name'] == 'Odegaard Library').sum()} rows named Odegaard Library."),
    details("View excluded records", table(excluded.round(1), "Records outside this course scope")),
)

# step: 4 — Explore distributions
plot_specs = [
    ("Energy_Use_kWh", "Annual energy use (kWh)"),
    ("Area_m", "Area_m (definition/unit unresolved)"),
    ("Year_Built", "Year built"),
]
fig, axes = plt.subplots(1, 3, figsize=(10.5, 3.0))
for ax, (column, label) in zip(axes, plot_specs):
    ax.hist(model_df[column], bins=12, color="#d8d8d8", edgecolor="#111111", linewidth=0.8)
    ax.set_title(label, fontsize=9)
    ax.set_ylabel("Buildings")
    ax.tick_params(labelsize=8)
    ax.grid(axis="y", color="#eeeeee", linewidth=0.7)
fig.suptitle("Selected distributions after applying the course scope", fontsize=11)
fig.tight_layout()
figure_data_url(fig)

# step: 5 — Explore relationships
relationship_features = ["Area_m", "Height", "Year_Built"]
correlations = model_df[relationship_features + ["Energy_Use_kWh"]].corr()["Energy_Use_kWh"]

fig, axes = plt.subplots(1, 3, figsize=(10.5, 3.0))
for ax, feature in zip(axes, relationship_features):
    ax.scatter(model_df[feature], model_df["Energy_Use_kWh"], s=18,
               facecolor="#ffffff", edgecolor="#111111", linewidth=0.7)
    ax.set_xlabel(feature)
    ax.set_ylabel("Energy use (kWh)")
    ax.tick_params(labelsize=8)
    ax.grid(color="#eeeeee", linewidth=0.7)
fig.suptitle("Selected relationships with annual energy use", fontsize=11)
fig.tight_layout()
lab_output(
    {"type": "image", "src": figure_data_url(fig), "alt": "Annual energy use versus area, height and year built"},
    table(correlations.drop("Energy_Use_kWh").round(3).rename("Correlation").rename_axis("Feature").reset_index(), "Correlation with annual energy use"),
    note("Correlation does not establish causality. Which predictors appear associated with annual energy use?"),
)

# step: 6 — Define X and y
features = ["Area_m", "Height", "Year_Built"]
target = "Energy_Use_kWh"

X = model_df[features]
y = model_df[target]

lab_output(
    metrics({"label": "X · predictors", "value": ", ".join(features)},
            {"label": "y · target", "value": target}),
    note(f"Episode 2.3 in code: X supplies {X.shape[1]} inputs for each of {len(X)} buildings; y supplies the observed annual energy use that we want to predict."),
)

# step: 7 — Split train/test
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42
)

lab_output(
    metrics({"label": "Training buildings", "value": str(len(X_train))},
            {"label": "Test buildings", "value": str(len(X_test))}),
    note("The model fits only the training buildings. Test buildings remain unseen during fitting so their prediction errors measure generalization. The split is reproducible with random_state=42."),
)

# step: 8 — Train
from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(X_train, y_train)

lab_output(
    metrics({"label": "Multiple linear regression", "value": "Model fitted", "primary": True}),
    note(f"Learned {len(model.coef_)} slopes and an intercept from {len(X_train)} training buildings."),
    details("View fitted model parameters",
            table(pd.DataFrame({"Parameter": ["Intercept"] + features,
                                "Value": [model.intercept_] + list(model.coef_)}).round(2), "Fitted parameters")),
)

# step: 9 — Predict
y_pred = model.predict(X_test)

prediction_table = pd.DataFrame({
    "Building": model_df.loc[y_test.index, "Name"].to_numpy(),
    "Actual_kWh": y_test.to_numpy(),
    "Predicted_kWh": y_pred,
    "Residual_kWh": y_test.to_numpy() - y_pred,
}, index=y_test.index)

lab_output(
    metrics({"label": "Unseen test buildings", "value": f"{len(y_pred)} predictions"}),
    table(prediction_table.head(5).round(0).rename(columns={"Actual_kWh": "Actual", "Predicted_kWh": "Predicted", "Residual_kWh": "Residual"}), "First five test buildings · all energy values in kWh"),
    note("Residual = Actual − Predicted. A positive residual means the model underpredicted energy use."),
)

# step: 10 — Evaluate
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

test_mae = mean_absolute_error(y_test, y_pred)
test_rmse = np.sqrt(mean_squared_error(y_test, y_pred))
test_r2 = r2_score(y_test, y_pred)

actual = y_test.to_numpy()
lower = min(0.0, float(actual.min()), float(y_pred.min()))
upper = max(float(actual.max()), float(y_pred.max()))
padding = max((upper - lower) * 0.05, 1.0)
limits = (lower - padding, upper + padding)

fig, ax = plt.subplots(figsize=(6.6, 4.7))
ax.scatter(actual, y_pred, s=38, facecolor="#ffffff", edgecolor="#111111", linewidth=1)
ax.plot(limits, limits, color="#111111", linewidth=1.5, linestyle="--", label="Perfect prediction: y = x")
ax.set_xlim(limits)
ax.set_ylim(limits)
ax.set_aspect("equal", adjustable="box")
ax.set_xlabel("Actual annual energy use (kWh)")
ax.set_ylabel("Predicted annual energy use (kWh)")
ax.set_title("Test buildings: Actual vs Predicted")
ax.grid(color="#eeeeee", linewidth=0.8)
ax.legend(frameon=False, fontsize=8)
fig.tight_layout()
lab_output(
    metrics({"label": "PRIMARY · Test MAE", "value": f"{test_mae:,.0f} kWh", "primary": True}),
    note("MAE is the average absolute prediction error on the unseen test buildings. Lower is better."),
    {"type": "image", "src": figure_data_url(fig), "alt": "Actual versus predicted annual energy use for the 23 test buildings",
     "caption": "Points closer to the dashed y = x line have smaller prediction errors. All actual and predicted values are shown."},
    metrics({"label": "SECONDARY · Test RMSE", "value": f"{test_rmse:,.0f} kWh"},
            {"label": "SECONDARY · Test R²", "value": f"{test_r2:.3f}"}),
    note("Negative test R² means this baseline generalizes poorly on this split: its squared error exceeds the test-mean benchmark. This is a useful modeling result, not a software failure."
         if test_r2 < 0 else "Interpret test performance alongside the data scope and domain knowledge."),
)
:::

## Interpret the model

The fitted baseline connects three predictors to annual energy use. The table uses
the same fixed split from the guided workflow and rounds the fitted values for
reading. Run the workflow to compute the full-precision values live.

:::figure{id="uw-baseline-coefficients" caption="Baseline coefficients fitted on the 91 training buildings selected with random_state=42."}
:::

Interpret each slope as the predicted change in annual energy use for a one-unit
increase in that feature **while the other included predictors are held constant**.
This wording matters: a coefficient is an adjusted association, not a causal effect.

:::keyidea
Raw coefficient magnitude is not feature importance. A one-unit change means very
different things for calendar year, height, and `Area_m`, and two of those field
units remain unresolved in the source documentation.
:::

Did adding more features always improve test performance?

:::reflect
Why can training fit improve while test performance does not?
- The test buildings secretly change during training
- *The model can fit patterns or noise specific to the training buildings
- MAE cannot be calculated on a test set
:::

:::reflect
Why can a coefficient change after adding another predictor?
- Coefficients are random labels
- *Its meaning becomes conditional on a different set of held-constant predictors
- Linear regression permits only one stable coefficient
:::

- The target column contains no numbers
