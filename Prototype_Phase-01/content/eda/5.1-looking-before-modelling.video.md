:::scene{type=diagram id=data_centric}
heading: Why the hour comes first
points:
  - Model-centric — hold the data fixed, improve the model
  - Data-centric — hold the model fixed, improve the data
  - "Data cascades — 92 % of practitioners in one field study had seen them"
  - Five checks before any model — provenance, distributions, missingness, imbalance, readiness
narration: |
  Why spend the hour on the data rather than on the model? Because the field changed
  its mind about where the effort goes. For a long time the reflex was model centric:
  hold the data fixed and improve the model. The data centric view, now a research
  field of its own, holds the model fixed and improves the data, systematically: its
  quality, its coverage, its documentation. The evidence is not abstract. In a field
  study of fifty three practitioners working on high stakes A I, ninety two percent
  had seen what the authors call data cascades: problems upstream in the data that
  surfaced later as compounding failures downstream, usually after the model was
  built. So this module runs five checks before any model. Where the data came from.
  How each column is distributed. What is missing, and why. Whether the classes are
  balanced. And whether the data is ready to answer your question at all. Without
  good data, one of the surveys says, even the best algorithm cannot perform well.
:::

:::scene{type=code}
heading: numpy — maths on the whole grid at once
code: |
  import numpy as np

  loads = np.array([31.3, 13.3, 20.4, 25.4])
  print(loads * 1.1)            # every element at once
  print(loads.mean(), loads.max())
  print(loads > 20)             # a question, asked of every element
output: |
  [34.43 14.63 22.44 27.94]
  22.6 31.3
  [ True False  True  True]
note: A list holds anything and does nothing with it. An array holds numbers of one type in a grid, and maths applies to all of them at once.
narration: |
  Numpy first, because everything else is built on it. A list holds anything and does
  nothing with it. A numpy array holds numbers of one type in a grid, and maths applies
  to the whole grid at once. Multiply the array by one point one and every element is
  multiplied. Ask for the mean and the max. Ask whether each load is over twenty, and
  you get a True or False for every element. Faster than a loop, and shorter to write.
:::

:::scene{type=quiz}
question: a = np.array([1, 2, 3]) and b = [1, 2, 3]. What are a + a and b + b?
options:
  - Both give [2, 4, 6]
  - array([2, 4, 6]) and [1, 2, 3, 1, 2, 3]
  - Both give an error
answer: 1
pause: 5
explain: An array does element-wise maths. A list has no idea what adding means for numbers, so + joins two lists end to end. This is the whole reason numpy exists.
narration: |
  A check. A is a numpy array of one, two, three. B is a plain list of one, two, three.
  What are a plus a, and b plus b? A: both give two, four, six. B: the array gives two,
  four, six, and the list gives one, two, three, one, two, three. C: both give an error.
  Pause and pick.
after: |
  It is B. An array does element wise maths. A list has no idea what adding means for
  numbers, so plus joins two lists end to end. That difference is the whole reason
  numpy exists, and the reason every data library is built on it.
:::

:::scene{type=diagram id=dataframe_anatomy}
heading: pandas — a table with named columns
narration: |
  Now pandas. A DataFrame is a table: named columns, a row index, and one type per
  column. Watch the anatomy build. The index down the side, the column names across the
  top, and the cells, each column holding one kind of value. Almost everything you do
  with a DataFrame is one of three things: pick columns, filter rows, summarise.
:::

:::scene{type=code}
heading: Load, look, summarise
code: |
  import pandas as pd
  df = pd.read_csv("assets/data/energy_efficiency.csv")

  print(df.shape)                       # rows, columns
  print(df["heating_load"].mean())      # one column
  tall = df[df["overall_height"] > 5]   # filter rows
  print(tall["heating_load"].mean())
  print(df.groupby("overall_height")["heating_load"].mean())
output: |
  (768, 10)
  22.31
  31.28
  overall_height
  3.5    13.34
  7.0    31.28
note: Tall buildings average 31 kWh/m², low ones 13. That single groupby is the first real finding — and the loop from Lesson 1.3, in one line.
narration: |
  Read c s v turns a file into a DataFrame; it is the first line of every project. Shape
  tells you rows and columns. A column in square brackets gives you that column, and
  dot mean summarises it: twenty two point three. A comparison inside the brackets
  filters rows: only the buildings taller than five metres. And group by splits the
  table by height, takes the mean of each group, and hands both back. Tall buildings
  average thirty one kilowatt hours per square metre. Low ones, thirteen. That is the
  first real finding, and it is the loop you wrote in lesson one point three, in one
  line.
:::

:::scene{type=quiz}
question: df[df["orientation"] == "N"] returns zero rows. Why?
options:
  - pandas cannot filter by text
  - The column holds the numbers 2 to 5, not letters, so nothing equals "N"
  - The dataset has no north-facing buildings
answer: 1
pause: 5
explain: Look before you filter. df.dtypes and df["orientation"].unique() would have shown the codes. Map codes to names first, then group or plot.
narration: |
  A check. You filter for buildings whose orientation is N, and get zero rows. Why? A:
  pandas cannot filter by text. B: the column holds the numbers two to five, not
  letters, so nothing equals N. C: there are no north facing buildings. Pause and pick.
after: |
  It is B. Look before you filter. D f dot d types, or the column's unique values, would
  have shown you the codes. Map the codes to names first, and then group or plot. This
  is the most common mistake in the whole module, and it is silent: no error, just an
  empty answer.
:::
