:::scene{type=title}
narration: |
  Welcome to lesson four point two, orchestration: deciding who runs when. One agent is
  a prompt. Several agents are a system, and a system needs an order. This lesson is
  about that order: which agent runs first, which can run at the same time, which must
  wait, and why the answer is about dependency, not speed.
:::

:::scene{type=diagram id=orchestration}
heading: Three phases
narration: |
  Here is the shape of the Negotiators pipeline. Phase one: the site researcher runs alone,
  because everyone needs its data. Phase two: the advocates run in parallel, independent
  of each other, because none of them reads another's output. Phase three: the manager
  runs last, because it needs every advocate's result. Sequential, parallel, sequential.
  Gather context, do independent work, synthesise.
:::

:::scene{type=idea icon=bulb}
text: Dependency, not speed, / sets the shape.
sub: Two agents can run at the same time exactly when neither reads the other's output.
narration: |
  The rule that generates the shape is one sentence. Dependency, not speed, sets the
  shape. Two agents can run at the same time exactly when neither reads the other's
  output. If an agent needs something another agent produces, it waits. If it does not,
  it runs now. You never decide the order by hand; you decide who reads what, and the
  order follows.
:::

:::scene{type=idea icon=warn}
text: The advocates must not see each other.
sub: Models are agreeable. Let them read each other and they converge. Isolate them, then give one agent the explicit job of resolving the conflict.
narration: |
  Now the surprising part. The advocates must not see each other. Language models are
  agreeable: let two of them read each other's arguments and they converge, politely,
  on something in the middle. Value in this system comes from structured disagreement,
  not consensus. So isolate the advocates, let each one argue its own case as hard as
  it can, and give one agent, the manager, the explicit job of resolving the conflict.
:::

:::scene{type=cards}
heading: Real tensions to build the debate around
items:
  - title: Daylight vs energy
    text: More glass or less glass. The classic conflict. Neither is wrong; the manager has to pick and say what it sacrificed.
  - title: Carbon vs comfort
    text: A compact form or generous floor plates. Embodied carbon rewards compactness; comfort rewards space and light.
  - title: Cost vs performance
    text: The cheaper envelope or the better one. A number on each side makes the trade-off arguable.
narration: |
  What should the advocates disagree about? Real tensions. Daylight versus energy: more
  glass or less glass, the classic conflict, where neither side is wrong and the
  manager has to pick and say what it sacrificed. Carbon versus comfort: a compact form
  or generous floor plates. Cost versus performance: the cheaper envelope or the better
  one. If your two advocates want the same thing, the manager has nothing to arbitrate,
  and you have built a very slow summariser.
:::

:::scene{type=steps}
heading: The manager's job is deciding, not summarising
steps:
  - List agreements — the easy wins, named
  - Name each conflict — each position, with its number
  - "*Decide — pick one, and say what was lost"
  - Output a geometry — numbers the sliders can apply
narration: |
  The manager's job is deciding, not summarising. First, list the agreements: where did
  everyone align? Those are the easy wins, and naming them clears the ground. Second,
  name each conflict: the specific issue, each advocate's position, with the number each
  one proposed. Third, decide: pick one, and say what was lost. And fourth, output a
  geometry: numbers the dashboard sliders can apply. The instruction in the Negotiators
  prompt is two words long: do not average.
:::

:::scene{type=quiz}
question: You add a fourth advocate and the manager's verdict becomes noticeably blander. What is the most likely explanation?
options:
  - The model ran out of context
  - The new advocate overlaps an existing one, so there is less real disagreement to resolve
  - Four agents is always too many
answer: 1
pause: 5
explain: Blandness is a symptom of consensus. If two advocates argue for the same thing, the manager has fewer real conflicts to name and decide, and averaging creeps in. Add tension, not headcount.
narration: |
  A check. You add a fourth advocate and the manager's verdict becomes noticeably
  blander. What is the most likely explanation? A: the model ran out of context. B: the
  new advocate overlaps an existing one, so there is less real disagreement. C: four
  agents is always too many. Pause and pick.
after: |
  It is B. Blandness is a symptom of consensus. If two advocates argue for the same
  thing, the manager has fewer real conflicts to name and decide, and averaging creeps
  back in. Add tension, not headcount.
:::

:::scene{type=idea icon=warn}
text: An averaged answer is a design / no advocate argued for.
sub: And no reviewer can trace. Make the model choose, and make it explain the loss.
narration: |
  Why do not average matters so much: an averaged answer is a design that no advocate
  argued for and no reviewer can trace back to a reason. A window to wall ratio of
  zero point four two, because one agent said zero point three and another said zero
  point five five, is not a decision. Make the model choose, and make it explain what
  the choice cost.
:::
