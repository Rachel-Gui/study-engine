## Diffusion Playground

What changes between random noise and a recognizable architectural proposal?

Diffusion progressively transforms noise into structure. A text encoder represents the prompt, and a denoising model iterates under that condition. Some pipelines operate in a compressed latent representation rather than directly on display pixels.

## A real run, step by step

The playground is a teaching simulation. This is the real process: one generation by
Stable Diffusion v1.5, the model of the course notebook, paused after selected steps so
that the image the model was holding at that moment could be decoded and saved. The
prompt is the library prompt from Lesson 2.1: *a community library with exposed timber
structure, large glass facade, located on a sloped urban site in Seattle, soft overcast
morning light, contemporary Scandinavian style, architectural photography, 8K*.

Three things to notice.

- **The whole picture changes at once.** No step draws the roof and then the windows.
  Every step adjusts every part of the image a little, steered by the prompt.
- **Structure settles before detail.** The sky and the roofline are there by step 12;
  the timber grain and the glazing bars only in the last steps.
- **Noise lasts until late.** Each image above is the model's state *as it is*, noise
  included, so most of the run still looks like noise. A third of the way through, the
  building is barely there.

**Same prompt, same seed, different building.** The prompt, seed (100) and settings
match the seed-100 image in Lesson 2.1, yet the final image here is a different
library. The course notebook ran on a GPU in half precision; this run used a CPU, whose
random-number generator draws different starting noise from the same seed. A seed
reproduces an image only together with the model version, scheduler, precision and
hardware it was drawn on, which is why the course records all of them.

:::details{summary="The code that recorded the steps"}
Simplified from the script that made Figure 1 (it ships with the course materials as
`tools/denoising_steps.py`). The pipeline calls `keep` after every step, and `keep`
saves the latent, the model's compressed image, so it can be decoded later.

```
import torch
from diffusers import StableDiffusionPipeline

pipe = StableDiffusionPipeline.from_pretrained(
    "stable-diffusion-v1-5/stable-diffusion-v1-5",
    revision="451f4fe16113bff5a5d2269ed5ad43b0592e9a14",   # the course notebook's revision
    variant="fp16", torch_dtype=torch.float32, safety_checker=None)

saved = {}
def keep(pipe, i, t, state):                 # called after every denoising step
    saved[i + 1] = state["latents"].clone()  # the image the model holds right now
    return state

image = pipe(PROMPT, num_inference_steps=30, guidance_scale=7.5,
             generator=torch.Generator("cpu").manual_seed(100),
             callback_on_step_end=keep).images[0]

def decode(latents):                         # latent -> pixels, with the model's own decoder
    x = pipe.vae.decode(latents / pipe.vae.config.scaling_factor).sample
    return (x / 2 + 0.5).clamp(0, 1)
```
:::

**Where the model comes from.** Every generator has a source, and its page says what
it was trained on and under which licence. Read it before you use a model.

## What controls an iterative process?

:::cards
Condition | What are we asking for? | A text prompt may describe a library, its setting, materials and light.
Seed | Where does sampling begin? | An initialization can lead to a different sample even under the same prompt.
Inference steps | How many updates? | More updates cost computation; quality gains can diminish and depend on the pipeline.
:::

A {{seed}} supports reproducibility only when the model and other relevant settings are also fixed. It is not a universal design identifier. A {{condition}} steers the process; it is not automatically a geometric constraint.
