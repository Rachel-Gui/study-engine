## Why run a model locally

Everything in Modules 2, 3 and 4 that talks to a language model can talk to one running
on **your own laptop**. Ollama is the program that makes that possible: it downloads an
open model once and serves it on your machine. No API key, no per-token cost, nothing
leaves your computer, and it works on a plane.

:::narration
Ollama is a program that runs an open language model on your own laptop. You download a
model once, and from then on there is no A P I key, no per-token cost, and nothing you
type leaves your machine. The trade is that a model that fits on a laptop is smaller
than a hosted one, so expect it to be literal about instructions, which is actually
useful for learning. This guide installs Ollama, helps you pick a model your machine
can run, and shows you how to talk to it from the terminal and from Python. The same
local model is what Module 3 points Claude Code at, and what the Module 4 Negotiators runs on.
:::

:::stats
0 | API keys
0 | per-token cost
4–8 GB | disk for one good model
:::

:::compare
A hosted model | GPT, Claude, Gemini via an API | Larger, more capable, costs money per call, your prompt leaves your machine. Right for production work.
A local model | llama, qwen, gemma, mistral via Ollama | Free, private, offline, smaller. Literal about instructions — a small model punishes a vague prompt immediately, which is good for learning.
:::

:::flow
Install Ollama > Pull a model that fits your RAM > Talk to it in the terminal > Call it from Python > Reuse it in Modules 3 and 4
:::

:::figure{id=ollama_local caption="Figure 1. Where a local model runs. Ollama serves the model on your own laptop; the terminal, your Python scripts and the course's later tools all send it their prompts at localhost:11434. The only download is the model itself."}
:::

## Step 1 — Install Ollama

Go to [ollama.com/download](https://ollama.com/download) and pick your system. The page
leads with a one-line install command; the classic installer sits under **Download
manually**. Either works:

- **The installer (simplest).** Click **Download manually**: `OllamaSetup.exe` on
  Windows, `Ollama.dmg` on a Mac. Run it like any other installer.
- **The one-line command.** Copy the line the page shows and paste it into a terminal:
  PowerShell on Windows (`irm https://ollama.com/install.ps1 | iex`), Terminal on a Mac
  (`curl -fsSL https://ollama.com/install.sh | sh`). Press Enter.

:::screenshot{src=assets/generative/real/ollama-download-page.png full=assets/generative/real/ollama-download.png caption="ollama.com/download with the Windows tab selected: the PowerShell install command, and Download manually underneath for the installer. The macOS tab shows the Terminal command instead."}
:::

:::os
[windows]
After installing, look in the **system tray** (bottom-right, near the clock) for a small
llama icon. If it is not there, open **Ollama** from the Start menu.

Then open a **new** terminal (Start → `cmd`) and check:

```
ollama --version
```

If you see "not recognized", close the terminal and open a fresh one — a terminal
that was open before the install does not know Ollama exists yet.
[mac]
After installing, look in the **top menu bar** (top-right) for a small llama icon. If
it is not there, open **Ollama** from your Applications folder.

Then open a **new** Terminal window and check:

```
ollama --version
```

If you see "command not found", close Terminal and open it again — a window that was
open before the install does not know Ollama exists yet.
:::

:::keyidea
**If you already had Ollama installed, update it.** Open the app and let it update
itself. Older versions can behave unexpectedly with newer models.
:::

## Step 2 — Choose a model that fits your machine

A model has to fit in memory to run. The number that matters is your laptop's **RAM**.
Check it: Windows — Settings → System → About; macOS — Apple menu → About This Mac.

| Model | Size on disk | Needs about | Good for |
|---|---|---|---|
| `llama3.2` (3B) | 2.0 GB | 8 GB RAM | any laptop; quick answers, the Negotiators if `llama3.1` is too slow |
| `llama3.1` (8B) | 4.9 GB | 16 GB RAM | **the Environmental Negotiators default** — capable, well-tested |
| `mistral` (7B) | 4.4 GB | 16 GB RAM | a common fallback; smaller and faster than llama3.1 |
| `qwen3` (8B) | 5.2 GB | 16 GB RAM | strong at structured output and code |
| `gemma3` (4B) | 3.3 GB | 8 GB RAM | small and capable; handles images too |
| `phi4-mini` (3.8B) | 2.5 GB | 8 GB RAM | reasoning-focused small model |

Sizes and names change over time; the current list is at
[ollama.com/library](https://ollama.com/library). Every model there is free to download
and run. Each model's page lists its sizes, and what it accepts as input.

:::screenshot{src=assets/generative/real/ollama-llama32-page.png full=assets/generative/real/ollama-llama32.png caption="The Models table on llama3.2's page at ollama.com: two sizes, 1b (1.3 GB) and 3b (2.0 GB, the default that ollama pull llama3.2 downloads), both reading text only. On the gemma3 page the Input column reads Text, Image: that model can look at pictures, which Lessons 2.5 and 2.6 use."}
:::

:::keyidea
**Rule of thumb: an 8B model wants 16 GB of RAM; a 3–4B model runs on 8 GB.** If your
laptop has 8 GB, start with `llama3.2` or `gemma3`. If it has 16 GB or more, start
with `llama3.1`.
:::

Download the model (the command is the same on both systems):

```
ollama pull llama3.1
```

This downloads about 4.9 GB. On a good connection it takes a few minutes. On
university Wi-Fi it can be slow or blocked entirely — if it hangs, try a phone hotspot.

:::screenshot{src=assets/generative/real/vs-29-pull-page.png full=assets/generative/real/vs-29-pull.png caption="In VS Code's terminal: ollama --version, then ollama pull llama3.2 (the 8 GB choice; already downloaded here, so every layer reads 100%), then ollama list — the models on this laptop and their sizes."}
:::

:::predict
Your laptop has 8 GB of RAM. You run `ollama pull llama3.1` and it downloads fine, but
`ollama run llama3.1` is painfully slow or the machine freezes. What is going on?
- The download was corrupted | Unlikely; Ollama checks the download.
- *An 8B model needs about 16 GB to run comfortably; it is swapping to disk | Yes. Swap to a 3B model: `ollama pull llama3.2`. Same commands, a fraction of the memory.
- Ollama is not installed properly | It downloaded, so it is installed. The problem is memory, not the install.
:::

## Step 3 — Talk to it

```
ollama run llama3.1
```

You will see a prompt like `>>> Send a message`. Type something and press Enter. When
you are done, type `/bye` to exit. Ollama keeps the model loaded in the background so
the next call is fast.

:::screenshot{src=assets/generative/real/vs-29-run-page.png full=assets/generative/real/vs-29-run.png caption="ollama run llama3.2: one question, one answer, and the >>> prompt waiting for the next (type /bye to leave). Read the answer to the end: thermal mass is right, but evaporation is no part of how a concrete wall keeps a room cool. Fluent, and one idea wrong."}
:::

Two things worth trying while you are here:

- Ask it something you know the answer to, and then something obscure. Notice how
  confident it sounds either way. **This is the hallucination behaviour Episode 2.8
discusses, and you can see it in thirty seconds.**
- Give it a vague instruction, then a sharp one with a bullet list. A small model makes
  the difference obvious.

```
ollama list          # models you have downloaded
ollama ps            # models currently loaded in memory
ollama rm mistral    # delete one to free disk space
```

## Step 4 — Call it from Python

Ollama runs a local server at `http://localhost:11434`. Any program on your machine can
talk to it. The official Python client is one install:

:::os
[windows]
```
python -m pip install ollama
```
[mac]
```
pip3 install ollama
```
:::

Then, in a Python file or a Colab cell running on your laptop:

```
import ollama

reply = ollama.chat(model="llama3.1", messages=[
    {"role": "system", "content": "You are an energy-efficiency advocate. Be specific."},
    {"role": "user",   "content": "A 6-storey block, WWR 0.55, Seattle. One concern?"},
])
print(reply["message"]["content"])
```

That is the exact shape the Environmental Negotiators (Module 4) uses — a system prompt, a user
message, a model, a reply. Everything else in Module 4 is built on this call.

:::screenshot{src=assets/generative/real/vs-29-python-page.png full=assets/generative/real/vs-29-python.png caption="The same call run in VS Code with llama3.2. Read the first line of the answer: the model expanded WWR as wall-to-wall rating, and later gave Seattle significant winter snowfall. Fluent, confident, and wrong about the one term the question turned on. Lesson 2.8 shows the fix: put the definition in the context."}
:::

:::technical{summary="Structured output: make the model return JSON you can parse"}
Pass `format="json"` and ask for JSON in the prompt. The model's reply can then be
read by code, which is what an agent pipeline needs.

```
import ollama, json
r = ollama.chat(model="llama3.1", format="json", messages=[
    {"role": "system", "content": 'Respond ONLY with JSON: {"concern": str, "wwr_target": number}'},
    {"role": "user",   "content": "WWR 0.55, heating-dominated climate."},
])
print(json.loads(r["message"]["content"]))
```

Small models sometimes break the JSON. Wrap `json.loads` in a `try`, and re-ask on
failure — that retry is the first line of any real agent loop.

![ask_json.py: the same request with format="json" and a three-try retry, run here with llama3.2. The reply parsed on the first try and wwr_target is a number, as asked. The number is 0, a target of no windows at all, and the concern only repeats the question. The format is guaranteed; the sense is not.](assets/generative/real/vs-29-json-page.png)
:::

## Troubleshooting

| OS | What you see | What to do |
|---|---|---|
| Both | `ollama: command not found` / `not recognized` | Close the terminal, open a new one. New installs only appear in fresh terminals. |
| Both | `ollama pull` hangs forever | The network is blocking it. Switch to a phone hotspot. |
| Both | `Error: could not connect to ollama server` | The Ollama app is not running. Look for the llama icon in the tray / menu bar and open it. |
| Both | `ollama run` is very slow or the laptop freezes | Model too big for your RAM. `ollama pull llama3.2` and use that instead. |
| Both | Python: `ModuleNotFoundError: No module named 'ollama'` | Install the client: `python -m pip install ollama` (Win) / `pip3 install ollama` (Mac). |
| Both | Python connects but replies are empty or truncated | The model ran out of context. Shorten the prompt or set a larger context in Ollama. |
| Both | Disk is full | `ollama list` then `ollama rm <name>` for models you no longer use. |
