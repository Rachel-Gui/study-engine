narration: |
  Two ways to use a language model. A hosted model, G P T, Claude, Gemini through an A P
  I, is larger and more capable, costs money per call, and your prompt leaves your
  machine. A local model through Ollama is smaller, because it has to fit in your
  laptop's memory. It is free, private, and works on a plane. And it is literal about
  instructions: a small model punishes a vague prompt immediately, which is exactly
  what you want when you are learning. Hosted for real work. Local to learn.
:::

:::scene{type=number}
heading: Which model? It has to fit in memory
items:
  - value: "8 GB"
    label: of RAM runs a 3 to 4 billion parameter model — llama3.2, gemma3
    count: false
  - value: "16 GB"
    label: runs an 8 billion parameter model — llama3.1, the default, or qwen3 for code
    count: false
  - value: "4.7 GB"
    label: on disk for llama3.1 — a few minutes on a good connection, slow on campus Wi-Fi
narration: |
  A model has to fit in memory to run, so the number that matters is your laptop's RAM.
  Rule of thumb: eight gigabytes runs a three to four billion parameter model, like
  llama three point two or gemma three. Sixteen gigabytes runs an eight billion
  parameter model, like llama three point one, which the Negotiators use, or qwen three,
  which is strong at code. Llama three point one is about four point seven gigabytes on
  disk. A few minutes on a good connection, and slow on campus Wi-Fi: if the download
  hangs, a phone hotspot usually fixes it.
:::

:::scene{type=code}
heading: Talk to it, then list what you have
code: |
  ollama pull llama3.1      # download once, about 4.7 GB
  ollama run llama3.1       # chat in the terminal; /bye to leave

  ollama list               # models you have downloaded
  ollama ps                 # models loaded in memory right now
  ollama rm mistral         # delete one to free disk space
note: Try asking it something you know, then something obscure. Notice how confident it sounds either way — that is the hallucination from 2.8, live, in thirty seconds.
narration: |
  Ollama pull downloads a model once. Ollama run starts a chat right in the terminal;
  type slash bye to leave. Ollama list shows what you have downloaded, ollama p s shows
  what is loaded in memory, and ollama r m deletes one to free disk space. While you are
  chatting, try this: ask it something you know the answer to, then something obscure.
  Notice how confident it sounds either way. That is the hallucination from lesson two
  point eight, live, in thirty seconds.
:::

:::scene{type=code}
heading: Call it from Python — the shape every agent uses
code: |
  import ollama

  reply = ollama.chat(model="llama3.1", messages=[
      {"role": "system", "content": "You are an energy-efficiency advocate. Be specific."},
      {"role": "user",   "content": "A 6-storey block, WWR 0.55, Seattle. One concern?"},
  ])
  print(reply["message"]["content"])
output: |
  A window-to-wall ratio of 0.55 in a heating-dominated climate means ...
note: A system prompt, a user message, a model, a reply. Everything in Module 4 is built on this one call.
narration: |
  Now the line that matters for the rest of the course. Ollama runs a local server, and
  any program on your machine can talk to it. In Python: import ollama, then ollama dot
  chat with a model and a list of messages. The system message sets the role: you are an
  energy efficiency advocate, be specific. The user message asks the question. The reply
  comes back as text. A system prompt, a user message, a model, a reply. That is what an
  agent is, and everything in module four is built on this one call.
:::

:::scene{type=idea icon=bulb}
text: Ask for JSON, and the reply becomes something code can read.
sub: format="json" plus a prompt that describes the shape. Wrap the parse in a try, and re-ask on failure — that retry is the first line of any real agent loop.
narration: |
  One more trick from lesson two point eight, made real. Pass format equals json and
  describe the shape you want, and the model's reply becomes something code can read:
  a concern, and a target ratio. Small models sometimes break the format. So wrap the
  parse in a try, and ask again on failure. That retry is the first line of any real
  agent loop.
:::
