## Translate before evaluating

To evaluate a generated design, translate pixels into **geometry + systems**. Segmentation, tracing, parametric representations and spatial graphs can help structure the information. Check the extraction: it is not automatically accurate or simulation-ready.

:::reflect{feedback="A visible shading cue does not supply the geometry, assemblies or operating conditions needed for simulation."}
Can a generated south-facing façade image alone support an annual energy evaluation?
- Yes, use its visible glazing and shading as sufficient simulation inputs
- *No, important geometric, material and operational inputs are missing
:::

:::details{summary="Show reference answer"}
Pixels do not reliably provide dimensions, orientation, material assemblies, thermal properties, schedules or HVAC systems. Even a façade visibly shaded in one image does not establish its annual performance.
:::

  - title: Segment / extract

    information: Human-corrected labels, boundaries, confidence and source scale where available.
  - title: Structured information
    explanation: Convert observations into explicit fields and relationships. Record what remains unknown.
    information: Dimensions, orientation, room relationships, candidate assemblies and documented assumptions.
  - title: Parametric / BIM geometry
    explanation: Build and check a geometric representation rather than treating the pixels as a model.
    information: Levels, units, surfaces, openings, assemblies and connections between spaces.
  - title: Simulation
    explanation: Supply the domain inputs required by the selected solver and check the model before interpreting results.
    information: Weather, thermal properties, occupancy schedules, HVAC and a validated simulation setup.
  - title: Evaluation
    explanation: Compare results against the architectural question; revise the geometry, assumptions or initial condition.
    information: Decision criteria, uncertainty, alternative proposals and domain review.
:::

:::reflect{feedback="Clearer imagery can support interpretation, but it cannot replace checked model inputs."}
What is the essential bridge between a generated image and architectural evaluation?
- Refine the image until its materials and openings look unambiguous
- *Translate it into structured design information and verify that information
:::

:::details{summary="Show reference answer"}
More imagery may widen exploration but does not resolve missing inputs. Structured, checked information makes the design available to parametric systems, BIM and simulation.
:::

## Code as design medium

:::flow
Define condition > Generate > Process > Extract > Evaluate > Integrate
:::

Generative design is better understood as a pipeline than as a single generation act. Code can make that pipeline **programmable, reproducible and scalable**. Reproducibility requires recording inputs, settings and model versions; a seed does not behave identically in every system.

This cumulative Python lab builds an experiment record across two steps. It runs Python to organize information; it does not generate images. Rerun the second step if you change the first.

:::pylab{title="Record a controlled generation experiment"}
# step: Define one controlled comparison
import json
settings = dict(prompt="A timber community library in Seattle",
                seed=100, guidance=7.5, steps=30, negative_prompt="")
previous = settings.copy()
current = {**settings, "seed": 200}
changed = {key: (previous[key], current[key])
           for key in previous if previous[key] != current[key]}
print("Changed:", changed)
print("All other settings retained:", len(changed) == 1)

# step: Add the information required downstream
experiment = {
    "previous": previous,
    "current": current,
    "observations": "Record what actually changed after inspecting real outputs.",
    "missing_for_energy_evaluation": ["dimensions", "orientation", "assemblies",
                                      "thermal properties", "schedules", "HVAC"],
    "next_step": "Translate and verify a geometric model before simulation.",
}
print(json.dumps(experiment, indent=2))
:::

## Architectural practice and research

Jang, Roh and Lee (2025) reviewed **161 published studies from 2014–2024**, examining applications, data and evaluation methods in architectural design. The review concerns published research; publication counts do not directly measure adoption in architectural practice.

:::cards
Early design dominates | Concept, layout and rendering studies | Later design phases and construction documentation remain less developed in the reviewed literature.
Images dominate | Image inputs and outputs are common | Drawings and renderings are easier to exchange than rich geometric and system information.
Evaluation is fragmented | Different studies judge different qualities | Visual similarity is not interchangeable with spatial validity or measured performance.
Next opportunities | Benchmarks, control and integration | Connect domain knowledge, BIM and human review instead of treating generation as an isolated service.
:::

Image-distribution metrics, user studies, expert review, performance simulation and graph matching answer different questions. An attractive output is not evidence of good energy performance; a correct adjacency graph is not a complete building.

:::reflect{feedback="Circulation depends on spatial relationships, dimensions and use, not image similarity alone."}
Which evaluation would best test whether a library layout supports its intended circulation?
- Compare its visual similarity to images of successful library precedents
- *Check the layout and adjacency/circulation relationships using architectural judgment
:::

:::details{summary="Show reference answer"}
Match the evidence to the decision. A visual metric can say something about image appearance, but circulation depends on spatial relationships, dimensions and use. Combine methods where the design question spans several kinds of evidence.
:::

:::details{summary="References"}
Jang, S., Roh, H., & Lee, G. (2025). [Generative AI in architectural design: Application, data, and evaluation methods](https://doi.org/10.1016/j.autcon.2025.106174). *Automation in Construction*, 174, 106174.
:::
