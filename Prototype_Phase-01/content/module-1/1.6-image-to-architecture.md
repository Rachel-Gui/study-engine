## Translate before evaluating

AI generates images, but architects need **geometry + systems**. Lecture slides 14–16 describe segmentation, tracing, parametric representations and graph-based spatial information as possible bridges. Extraction is not automatically accurate or simulation-ready.

:::reflect
AI generated a beautiful south-facing façade. Can we evaluate its annual energy performance from that image alone?
- Yes, visual realism supplies the necessary physics
- *No, important geometric, material and operational inputs are missing
:::

:::details{summary="Show reference answer"}
Pixels do not reliably provide dimensions, orientation, material assemblies, thermal properties, schedules or HVAC systems. Even a façade visibly shaded in one image does not establish its annual performance.
:::

:::genlab{kind=pipeline}
title: Image-to-Architecture Pipeline
question: Name one missing piece of information that would prevent you from evaluating the generated façade.
disclosure: "A guided conceptual pipeline, not automated image reconstruction or a running simulator. Open checkpoints in order; return to earlier ones to inspect dependencies."
takeaway: Translation into structured information is essential before geometry, simulation and architectural evaluation.
stages:
  - title: Prompt
    explanation: Specify design intent, context and the decision the exploration should inform.
    information: A brief and known constraints, with assumptions distinguished from verified facts.
  - title: AI image
    explanation: Preserve the image alongside its prompt and generation settings. Treat it as a visual hypothesis.
    information: Provenance, model/settings in a real run, and intended design qualities.
  - title: Segment / extract
    explanation: Identify candidate walls, glazing, openings or spatial relationships; inspect extraction errors.
    information: Human-corrected labels, boundaries, confidence and source scale where available.
  - title: Structured information
    explanation: Convert observations into explicit fields and relationships. Record what remains unknown.
    information: Dimensions, orientation, room relationships, candidate assemblies and documented assumptions.
  - title: Parametric / BIM geometry
    explanation: Build and check a geometric representation rather than treating the pixels as a model.
    information: Levels, units, surfaces, openings, assemblies and connections between spaces.
  - title: Simulation
    explanation: Supply the domain inputs required by the selected solver and check the model before interpreting results.
    information: Weather, thermal properties, occupancy schedules, HVAC and a validated simulation setup.
  - title: Evaluation
    explanation: Compare results against the architectural question; revise the geometry, assumptions or initial condition.
    information: Decision criteria, uncertainty, alternative proposals and domain review.
:::

:::reflect
What is the essential bridge between a generated image and downstream architectural evaluation?
- Generate another beautiful image
- *Translate the output into structured design information and verify it
:::

:::details{summary="Show reference answer"}
More imagery may widen exploration but does not resolve missing inputs. Structured, checked information makes the design available to parametric systems, BIM, simulation and eventually tool-using agents in Module 4.
:::

## Code as design medium

:::flow
Define condition > Generate > Process > Extract > Evaluate > Integrate
:::

The lecture calls this a pipeline rather than a single generation act. Code can make that pipeline **programmable, reproducible and scalable**. Reproducibility means recording inputs and versions, not assuming that the same seed works identically everywhere.

This small cumulative Python lab makes an experiment record explicit. It performs no image generation and needs no GPU. The interactive workflow in Episode 1.7 records your own observations separately.

:::pylab{title="Record a controlled generation experiment"}
# step: Define one controlled comparison
import json
settings = dict(prompt="A timber community library in Seattle",
                seed=100, guidance=7.5, steps=30, negative_prompt="")
previous = settings.copy()
current = {**settings, "seed": 200}
changed = {key: (previous[key], current[key])
           for key in previous if previous[key] != current[key]}
print("Changed:", changed)
print("All other settings retained:", len(changed) == 1)

# step: Add the information required downstream
experiment = {
    "previous": previous,
    "current": current,
    "observations": "Record what actually changed after inspecting real outputs.",
    "missing_for_energy_evaluation": ["dimensions", "orientation", "assemblies",
                                      "thermal properties", "schedules", "HVAC"],
    "next_step": "Translate and verify a geometric model before simulation.",
}
print(json.dumps(experiment, indent=2))
:::

## Architectural practice and research

**Research context from the supplied lecture, not a current market survey.** Slides 17–26 summarize Jang, Roh and Lee's 2025 review of 161 studies from 2014–2024. The lecture describes faster adoption of model architectures and a concentration in schematic design. Publication counts do not directly measure adoption by practicing architects.

:::cards
Early design dominates | Concept, layout and rendering studies | Later design phases and construction documentation remain less developed in the reviewed literature.
Images dominate | Image inputs and outputs are common | Drawings and renderings are easier to exchange than rich geometric and system information.
Evaluation is fragmented | Different studies judge different qualities | Visual similarity is not interchangeable with spatial validity or measured performance.
Next opportunities | Benchmarks, control and integration | Connect domain knowledge, BIM and human review instead of treating generation as an isolated service.
:::

The notebook contrasts image-distribution metrics, user studies, expert review, performance simulation and graph matching. Each answers a different question. An attractive output is not evidence of good energy performance; a correct adjacency graph is not a complete building.

:::reflect
Which evaluation would help decide whether a proposed library layout supports its intended circulation?
- Only an image-realism score
- *A checked layout and adjacency/circulation review with architectural judgment
:::

:::details{summary="Show reference answer"}
Match the evidence to the decision. A visual metric can say something about image appearance, but circulation depends on spatial relationships, dimensions and use. Combine methods where the design question spans several kinds of evidence.
:::
