## What you are setting up

**Claude Code** is Anthropic's agentic coding tool: a terminal program that reads your
project, plans, edits files and runs commands, asking before anything risky. It
normally talks to Anthropic's hosted models. Ollama speaks the same API, so you can
point Claude Code at the model already on your laptop from Lesson 2.9 and get an
agentic coding tool that runs entirely offline, for free.

Doing this once is the fastest way to *feel* what Module 4 means by an agent loop:
you will watch a model observe, plan, act and check, and you will be the gate it asks
before it writes.

## Step 1 — Node.js

**Already have this?** Run `node --version`. If it shows v18 or higher, skip to Step 2.
(If you did the Module 4 setup first, you have it.)

Claude Code is a Node.js program. Go to [nodejs.org](https://nodejs.org/) and download
the **LTS** version (not "Current"). Run the installer with its defaults.

:::os
[windows]
Then open a **new** terminal (Start → `cmd`) and check:

```
node --version
npm --version
```

If you see "not recognized", close the terminal and open a fresh one — a terminal
that was open before the install does not know Node exists yet.
[mac]
Then open a **new** Terminal window and check:

```
node --version
npm --version
```

If you see "command not found", close Terminal and open it again — a window that was
open before the install does not know Node exists yet.
:::

## Step 2 — Install Claude Code

The command is the same on both systems:

```
npm install -g @anthropic-ai/claude-code
```

:::os
[windows]
If npm reports a permissions error, open the terminal as administrator (right-click
Command Prompt → Run as administrator) and run the command again.
[mac]
If npm reports `EACCES` permission errors, run `sudo npm install -g @anthropic-ai/claude-code`
and type your Mac password when asked (nothing appears while you type — that is normal).
:::

Check it:

```
claude --version
```

## Step 3 — A model with enough context

Coding agents read many files at once, so they need the most capable model your
machine runs and a **large context window**. The Ollama documentation recommends 64k
tokens or more for real projects. `qwen3` is strong at code and structured output
(use the newer `qwen3.5` if your Ollama lists it); if your laptop has 8 GB of RAM,
use `qwen3:4b` instead.

```
ollama pull qwen3
```

Ollama also offers larger models with a `:cloud` tag that run on Ollama's servers
rather than your laptop. They are more capable, but your code leaves your machine
and they are not free in the same way — this guide stays local.

(Ollama itself was installed in Lesson 2.9. If `ollama` is not recognized, that guide's
troubleshooting table applies.)

## Step 4 — Point Claude Code at Ollama

The quickest way is Ollama's own launcher, which sets everything for you:

```
ollama launch claude
```

If that command is not available in your Ollama version, set three environment
variables yourself and start Claude Code normally:

:::os
[windows]
In **PowerShell** (Start → `powershell`):

```
$env:ANTHROPIC_AUTH_TOKEN = "ollama"
$env:ANTHROPIC_API_KEY = ""
$env:ANTHROPIC_BASE_URL = "http://localhost:11434"
claude --model qwen3
```

These settings last for that PowerShell window only, which is what you want: close it
and Claude Code goes back to its normal behaviour.
[mac]
```
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_API_KEY=""
export ANTHROPIC_BASE_URL=http://localhost:11434
claude --model qwen3
```

Or all in one line:

```
ANTHROPIC_AUTH_TOKEN=ollama ANTHROPIC_BASE_URL=http://localhost:11434 ANTHROPIC_API_KEY="" claude --model qwen3
```

These settings last for that Terminal window only, which is what you want.
:::

:::predict
You start `claude --model qwen3` and it answers instantly with a request to log in to Anthropic. What went wrong?
- qwen3 is not downloaded | Then the error would come from Ollama, not a login screen.
- *The three settings did not reach Claude Code — a different terminal window, or a typo in the variable names | Yes. The settings live in the window you typed them in. Set them again in this window, exactly as written, then start `claude` from the same window.
- Claude Code cannot use local models | It can; the base URL setting is exactly what tells it where to send requests.
:::

## Step 5 — A first task, and what to watch

Make a small folder with one Python file in it — the bar-building function from Lesson
3.2 is ideal — open a terminal **inside that folder** (Step 4 of the Module 4 setup
guide shows how), and start Claude Code. Then ask it something bounded:

```
Add a docstring to every function in this folder and explain what you changed.
```

Watch the terminal. The tool will:

:::cards
Observe | it lists and reads the files | it is building context, exactly as the LLM in 2.8 needs
Plan | it says what it intends to change | read this — it is the brief it wrote for itself
Ask | it shows the edit and waits for your yes | this is the human gate; nothing is written until you say so
Act | it applies the edit | one file at a time
Check | it reports what it did, and may run the code | its own check; not a substitute for yours
:::

Then try a real one, from the Lesson 3.2 brief:

```
Write a function shading_fin_depth(window_width_m, sun_azimuth_deg) that returns the
depth in metres of a vertical fin that fully shades a window of the given width when
the sun is at the given azimuth off the facade normal, in degrees. Include a test:
a 2 m window with the sun 45 degrees off normal needs a 2 m fin.
```

Read the code it writes before you accept it. Run the test. If it converted degrees to
radians, it learned from Lesson 3.1 better than the assistant did; if not, you are the
one who caught it.

:::keyidea
**What to expect.** A local 8B model is a much weaker coding agent than a hosted
frontier model: slower, more mistakes, in need of a sharper brief. That is not a
bug; it is the size of the model. For real work, a hosted model is the better tool.
For understanding how an agent loop behaves, the local one is ideal — every step is
visible, and it costs nothing.
:::

:::narration
Make a small folder with one Python file in it, open a terminal inside it, and start
Claude Code. Ask for something bounded, such as a docstring on every function. Then
watch. It reads the files: that is observe. It says what it intends: that is plan. It
shows the edit and waits: that is the human gate. It applies the edit: act. It
reports: check. A local model does this slowly and imperfectly, and that is the point.
Every step is visible, and you are the one who decides whether any of it is written.
:::

## Troubleshooting

| What you see | What to do |
|---|---|
| `npm: command not found` / `not recognized` | Node.js is not installed, or the terminal predates the install. Install from nodejs.org, then open a new terminal. |
| `claude: command not found` after installing | Open a new terminal. On macOS, if it persists, run `npm config get prefix` and make sure that folder's `bin` is on your PATH. |
| Claude Code asks you to log in | The three settings did not reach it. Set them in the same window you start `claude` from (Step 4). |
| `Error: could not connect` / connection refused | Ollama is not running. Open the Ollama app (llama icon in the tray / menu bar). |
| Replies are very slow or the laptop freezes | The model is too big for your RAM. `ollama pull qwen3:4b` and start with `--model qwen3:4b`. |
| The tool "forgets" the start of a long task | Context is full. Give it smaller tasks, one file at a time, and start a fresh session. |
| It edits a file you did not mean it to touch | You are the gate: answer no. Give it the file name explicitly next time. |
