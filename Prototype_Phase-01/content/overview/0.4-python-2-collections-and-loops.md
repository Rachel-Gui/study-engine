## Many values at once

Chapter I used one name per value. Real work has hundreds of buildings, dozens of
rooms, thousands of sensor readings. This chapter adds the four containers that hold
many values, and the two loops that walk through them.

:::narration

Real work has hundreds of buildings, dozens of rooms and thousands of sensor readings,
so this chapter adds the four containers that hold many values at once: lists,
tuples, sets and dictionaries. Then it adds the two loops that walk through them, for

through every recording, and use the slicing widget until negative indices stop

## Lists

A **list** is an ordered sequence of values in square brackets. It can grow, shrink,
and be changed in place.

:::figure{id=indexing caption="Figure 2. Counting starts at 0; negative indices count from the end; a slice includes start and excludes stop. Redrawn for this module."}
:::

:::trace{title="Make a list, read from it, change it"}
rooms = ["kitchen", "living", "hall", "bed 1"]
print(len(rooms))
print(rooms[0])
print(rooms[-1])
rooms.append("bath")
rooms[2] = "corridor"
print(rooms)
print(rooms[1:3])
print("bath" in rooms)
:::

:::widget{id=slice-lab}
:::

:::cards
rooms[0] | the first item | counting starts at 0
rooms[-1] | the last item | negative counts from the end
rooms[1:3] | items 1 and 2 | start included, stop excluded
rooms.append(x) | add to the end | changes the list in place
len(rooms) | how many | a function, not a method
x in rooms | is it there? | True or False
:::

:::pylab{title="Lists"}
# step: Build and inspect
loads = [15.55, 20.84, 29.79, 11.28, 38.35]
print(len(loads), "buildings")
print("first:", loads[0], " last:", loads[-1])
print("middle three:", loads[1:4])
print("biggest:", max(loads), " smallest:", min(loads), " total:", sum(loads))

# step: Change it
loads.append(12.07)         # add one
loads[0] = 16.0             # replace the first
loads.sort()                # sort in place, smallest first
print(loads)
print("sorted copy, largest first:", sorted(loads, reverse=True))
loads.remove(12.07)         # remove by value
print(loads, len(loads))

# step: Lists of anything
mixed = ["kitchen", 12.5, True, [1, 2]]     # allowed, though usually a sign to use a dict
print(mixed[3][1])                          # the second item of the inner list
words = "energy daylight carbon".split()
print(words, len(words))
print(" | ".join(words))                     # list of strings -> one string

# step: Your turn - the top two
# Print the two largest values in `areas` as a list, largest first, without editing the numbers by hand.
areas = [30, 12.5, 5, 18, 22, 9]
top_two = ...

:::

:::predict
`rooms = ["a", "b", "c"]` — what is `rooms[3]`?
- "c" | "c" is at index 2. There are three items: indices 0, 1, 2.
- *An IndexError: list index out of range | Yes. The last valid index is one less than the length. `rooms[-1]` is the safe way to say "the last one".
- An empty string | Python does not invent values for positions that do not exist.
:::

## Tuples and sets

A **tuple** is a list you cannot change: round brackets, fixed once made. Use it for a
record whose parts belong together — `(width, depth)`, `(lat, lon)`, `(x, y, z)`. A
**set** holds unique values with no order: curly brackets, and duplicates vanish.

:::trace{title="Tuples unpack; sets deduplicate"}
size = (6, 4)
width, depth = size
print(width * depth)
orientations = ["N", "S", "N", "E", "S", "N"]
unique = set(orientations)
print(unique)
print(len(unique))
print("W" in unique)
:::

The line `width, depth = size` is **unpacking**: a tuple of two values assigned to two
names at once. You will see it constantly: `for name, area in ...`, `x, y = point`,
`fig, ax = plt.subplots()`.

:::pylab{title="Tuples and sets"}
# step: Tuples
plan = ("kitchen", 4, 3)          # name, width, depth - one record
name, w, d = plan                 # unpack
print(f"{name}: {w * d} m2")
# plan[1] = 5                     # TypeError: tuples cannot be changed (remove the # to see it)
print(plan[0], len(plan))

# step: Sets
materials = ["brick", "glass", "brick", "timber", "glass", "brick"]
print(set(materials))                  # duplicates gone, order not kept
print(len(set(materials)), "distinct materials")
print(sorted(set(materials)))          # sorted() turns it back into an ordered list
a = {"brick", "glass"}; b = {"glass", "timber"}
print(a & b)      # in both
print(a | b)      # in either
print(a - b)      # in a only

# step: Your turn - how many distinct orientations?
readings = [2, 3, 2, 5, 4, 2, 3, 5, 5, 4]
n_distinct = ...
assert n_distinct == 4, "not yet - n_distinct should be 4"
print("Correct:", n_distinct, "distinct values")
:::

:::compare
List `[...]` | ordered, changeable | Use when items have a sequence, or the collection grows: readings over time, rooms in a plan.
Tuple `(...)` | ordered, fixed | Use for a record whose parts belong together and should not change: a coordinate, a size, a key in a dictionary.
:::

## Dictionaries

A **dictionary** maps **keys** to **values**. You look things up by name instead of by
position: `areas["kitchen"]`, not `areas[0]`. It is the container you will use most
after the list, and it is the shape of every JSON file and every table row.

:::figure{id=dict_lookup caption="Figure 3. A dictionary is a lookup table: key in, value out. Redrawn for this module."}
:::

:::trace{title="Look up, add, count"}
areas = {"kitchen": 12, "living": 30, "bath": 5}
print(areas["living"])
areas["garage"] = 18
print(len(areas))
print("attic" in areas)
print(areas.get("attic", 0))
print(list(areas.keys()))
print(sum(areas.values()))
:::

:::cards
d[key] | the value for that key | KeyError if missing
d[key] = v | add or replace | dictionaries grow as you go
d.get(key, default) | safe lookup | returns default instead of an error
key in d | is the key there? | checks keys, not values
d.keys() d.values() d.items() | all keys, all values, all pairs | what you loop over
:::

:::pylab{title="Dictionaries"}
# step: A record
building = {"name": "Gould Hall", "floors": 4, "area_m2": 9300, "year": 1971}
print(building["name"], "-", building["floors"], "floors")
building["eui"] = 142.0                # add a field
building["floors"] = 5                 # change a field
print(building)
print("keys:", list(building.keys()))

# step: Counting with a dictionary
orientations = ["N", "S", "N", "E", "S", "N"]
counts = {}
for o in orientations:                 # loops are the next section; read ahead
    counts[o] = counts.get(o, 0) + 1
print(counts)

# step: Nested: a dictionary of dictionaries
campus = {
    "Gould": {"floors": 4, "eui": 142},
    "Architecture": {"floors": 3, "eui": 118},
}
print(campus["Gould"]["eui"])
campus["Sieg"] = {"floors": 5, "eui": 160}
print(len(campus), "buildings")

# step: Your turn - safe lookup
# `areas` has no "attic". Use .get so that `attic` becomes 0 instead of crashing.
areas = {"kitchen": 12, "living": 30, "bath": 5}
attic = areas["attic"]
print("attic:", attic)
:::

:::predict
`d = {"a": 1, "b": 2}` — what does `d[1]` give?
- 1 | The keys are the strings "a" and "b". `1` is not a key here.
- *A KeyError | Yes. Dictionaries look up by key, not by position, and there is no key `1`.
- 2 | Position does not exist in a dictionary in this sense.
:::

## Repeating work: for loops

A **for loop** runs a block once for each item in a sequence. You never write the
counting yourself; Python hands you each item in turn.

:::figure{id=for_loop caption="Figure 4. A for loop: any items left? If so, take the next one and run the block. Redrawn for this module."}
:::

:::trace{title="A running total"}
areas = [12, 30, 5, 18]
total = 0
for a in areas:
    total = total + a
    print(a, total)
print("done:", total)
:::

Step through it slowly. The line `total = total + a` runs four times, once per item,
and `a` takes each value in turn. After the last item, Python skips back to the top,
finds nothing left, and continues after the loop.

:::pylab{title="for loops"}
# step: Over a list
rooms = ["kitchen", "living", "hall"]
for room in rooms:
    print(room.title(), "-", len(room), "letters")

# step: Over numbers with range()
for floor in range(1, 5):          # 1, 2, 3, 4 - the stop is excluded, like a slice
    print(f"floor {floor} at {floor * 3.2:.1f} m")

# step: With the index too - enumerate()
loads = [15.55, 20.84, 29.79]
for i, load in enumerate(loads):
    print(f"building {i}: {load} kWh/m2")

# step: Building a new list from an old one
loads_mj = []
for load in loads:
    loads_mj.append(load * 3.6)
print(loads_mj)
print([load * 3.6 for load in loads])          # the same thing in one line: a list comprehension
print([load for load in loads if load > 20])   # with a filter

# step: Your turn - count the tall ones
heights = [3.5, 7.0, 7.0, 3.5, 7.0, 3.5, 3.5, 7.0]
n_tall = 0
for h in heights:
    pass            # replace `pass` with code that adds 1 to n_tall when h is 7.0
assert n_tall == 4, "not yet"
print("Correct:", n_tall, "tall buildings")
:::

:::keyidea
`range(5)` is 0, 1, 2, 3, 4 — five numbers, starting at 0, stopping *before* 5. The
same rule as slices. Almost every off-by-one bug in a beginner's code is this rule.
:::

:::predict
What does this print? `for i in range(3): print(i)` then `print(i)` after the loop.
- 0 1 2 then an error, because i no longer exists | The loop variable survives the loop.
- *0 1 2 then 2 | Yes. After the loop, `i` keeps its last value.
- 0 1 2 then 3 | `range(3)` never produces 3.
:::

## Repeating until: while loops

A **while loop** repeats as long as a condition is `True`. Use it when you do not
know in advance how many times: keep halving until small enough, keep reading until
the file ends, keep asking until the answer is valid.

:::figure{id=while_loop caption="Figure 5. A while loop checks the condition before every pass. The block must change something the condition depends on. Redrawn for this module."}
:::

:::trace{title="Doubling until it fits"}
budget = 100
cost = 12
years = 0
while cost < budget:
    cost = cost * 1.5
    years = years + 1
print(years)
print(round(cost, 1))
:::

:::pylab{title="while loops"}
# step: Count down
floors = 5
while floors > 0:
    print("floor", floors)
    floors = floors - 1          # without this line the loop never ends
print("ground")

# step: Search until found
readings = [18.2, 19.0, 21.4, 26.8, 27.1, 24.0]
i = 0
while readings[i] < 26:
    i = i + 1
print(f"first reading above 26 is number {i}: {readings[i]}")

# step: break and continue
for r in readings:
    if r > 25:
        print("too warm, stopping at", r)
        break                    # leave the loop entirely
    if r < 19:
        continue                 # skip the rest of this pass
    print("ok:", r)

# step: Your turn - how many halvings?
# Starting from 1000, how many times can you halve it before it drops below 1? Use a while loop.
value = 1000
halvings = 0
assert halvings == 10, "not yet"
print("Correct:", halvings)
:::

:::keyidea
If a while loop seems to hang, its condition never became `False`. In the browser
box that means a frozen page; on your laptop, **Ctrl+C** stops it. Always ask: which
line changes what the condition looks at?
:::

:::compare
for | "for each item in this sequence" | You know what to visit. Lists, ranges, dictionary items, file lines.
while | "keep going while this is true" | You know when to stop. Convergence, searching, waiting for input.
:::

## Nested data and loops inside loops

Real data is nested: a list of buildings, each a dictionary, each with a list of
rooms. Loops nest the same way.

:::trace{title="A table is a list of dictionaries"}
rows = [
    {"name": "Gould", "height": 7.0, "load": 31.3},
    {"name": "Sieg", "height": 3.5, "load": 13.3},
    {"name": "Denny", "height": 7.0, "load": 28.7},
]
tall = []
for row in rows:
    if row["height"] == 7.0:
        tall.append(row["name"])
print(tall)
:::

:::pylab{title="Nested data"}
# step: Loop over dictionary items
areas = {"kitchen": 12, "living": 30, "bath": 5}
for room, area in areas.items():           # unpacking, two names per pass
    print(f"{room:10s} {area:4d} m2")
print("largest:", max(areas, key=areas.get))

# step: A loop inside a loop
floors = ["ground", "first"]
rooms = ["kitchen", "bath"]
for f in floors:
    for r in rooms:
        print(f, r)                         # 2 x 2 = 4 lines

# step: A list of dictionaries - the shape of a data table
rows = [
    {"name": "Gould", "height": 7.0, "load": 31.3},
    {"name": "Sieg", "height": 3.5, "load": 13.3},
    {"name": "Denny", "height": 7.0, "load": 28.7},
]
total = 0
for row in rows:
    total = total + row["load"]
print("mean load:", round(total / len(rows), 2))
by_height = {}
for row in rows:
    by_height.setdefault(row["height"], []).append(row["load"])
print(by_height)

# step: Your turn - mean load of the tall buildings only

assert mean_tall != ..., "not yet - replace the ... with your code"
assert round(mean_tall, 1) == 30.0, "close, but the number is wrong"
print("Correct:", mean_tall)
:::

## Test yourself (II)

:::predict
`nums = [1, 2, 3, 4, 5]` — what is `nums[1:-1]`?
- [1, 2, 3, 4] | Index 1 is the second item, and -1 (the last) is excluded.
- *[2, 3, 4] | Yes: start at index 1, stop before the last item.
- [2, 3, 4, 5] | The stop, -1, is excluded, so 5 is not included.
:::

:::predict
`counts = {}` then `counts["N"] = counts["N"] + 1`. What happens?
- counts becomes {"N": 1} | There is no "N" key yet, so the right-hand side fails before anything is stored.
- *A KeyError | Yes. Use `counts.get("N", 0) + 1`, or check `if "N" in counts` first.
- counts becomes {"N": 0} | Python never invents a starting value.
:::

:::predict
How many lines does this print? `for i in range(3): for j in range(2): print(i, j)`
- 3 | Each of the three outer passes runs the inner loop twice.
- 5 | The counts multiply, they do not add.
- *6 | Yes: 3 × 2. Nested loops multiply.
:::

:::predict
Which container would you use for "the set of materials that appear anywhere on the
facade", where order does not matter and each should be listed once?
- A list | It would hold duplicates and force you to remove them yourself.
- *A set | Yes. Uniqueness is built in, and `in` checks are fast.
- A tuple | It cannot grow, and it keeps duplicates.
:::

# `rooms` is a list of (name, width, depth) tuples.
# 1. Build a dictionary `areas` mapping each name to its area.
# 2. Print each room and its area, one per line, largest first.
# 3. Print the total area.
rooms = [("kitchen", 4, 3), ("living", 6, 5), ("bath", 2.5, 2), ("bed", 4, 3.5)]

:::

:::details{summary="Show reference answer"}
```
rooms = [("kitchen", 4, 3), ("living", 6, 5), ("bath", 2.5, 2), ("bed", 4, 3.5)]
areas = {}
for name, w, d in rooms:
    areas[name] = w * d
for name in sorted(areas, key=areas.get, reverse=True):
    print(f"{name:8s} {areas[name]:5.1f} m2")
print("total", sum(areas.values()), "m2")
```

`sorted(areas, key=areas.get, reverse=True)` sorts the keys by their values. If you
sorted a list of `(area, name)` tuples instead, that is also correct.
:::
