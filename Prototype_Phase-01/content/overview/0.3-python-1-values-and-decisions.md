## Your first program

The smallest useful program is one line: `print("hello")`. `print` shows something on
the screen; the round brackets hold what to show; the quotes mark text.

:::trace{title="Three lines, three outputs"}
print("Hello, architect")
print("Welcome to Python")
print(2 + 2)
:::

Step through it. Notice that `2 + 2` prints `4`, not `2 + 2`: Python **works out** what
is inside the brackets before printing it. `"2 + 2"` in quotes would print the text
`2 + 2` unchanged.

:::pylab{title="Run it, then change it"}
# step: Print something
print("Hello, architect")
print("This line is also Python")
print(6 * 4)          # numbers are worked out first

# step: Break it on purpose
# Remove the closing quote on the next line and run: you will get a SyntaxError.
# Put it back, then delete one bracket. Errors are normal; reading them is a skill.
print("The closing quote matters")

# step: Your turn - two lines
# Write two print lines: one with your name in quotes, one with the year you were born (no quotes).
print("...")
:::

:::cards
print(...) | shows something on the screen | the brackets hold what to show
"quotes" | mark text | "42" is text; 42 is a number
# a comment | ignored by Python | notes for humans
:::

:::keyidea
**Comments.** Anything after `#` on a line is for humans; Python skips it. Use them
to say *why*, not what: `# heating, not cooling — winter case`.
:::

## Values and types

Everything Python works with is a **value**, and every value has a **type**. Four types
cover almost everything in this course:

:::figure{id=types_four caption="Figure 2. The four types you will use daily. Redrawn for this module."}
:::

:::trace{title="type() tells you what you have"}
print(type(768))
print(type(22.31))
print(type("kitchen"))
print(type(True))
print(7 / 2)
print(7 // 2)
print(7 % 2)
print(2 ** 10)
:::

- `+ - *` add, subtract, multiply. `/` always gives a float: `7 / 2` is `3.5`.
- `//` divides and drops the remainder: `7 // 2` is `3`. `%` gives the remainder: `7 % 2` is `1`.
- `**` is a power: `2 ** 10` is `1024`.

:::pylab{title="Numbers and text"}
# step: Arithmetic
area = 6 * 4
print(area)
print(area / 5)          # a float
print(area // 5)         # whole part only
print(area % 5)          # remainder
print(area ** 2)         # squared

# step: Text and numbers do not mix by accident
print("3" + "1")         # text + text joins them
print(3 + 1)             # number + number adds them
print(int("3") + 1)      # int(...) converts text to a number
print(str(3) + "1")      # str(...) converts a number to text

# step: Your turn - a floor
# A floor is 12.5 m by 8 m. Print its area, and its area in square feet (1 m2 = 10.764 ft2).
:::

:::predict
What does `print("3" + 1)` do?
- Prints 4 | The `"3"` is text. Python will not silently turn it into a number.
- Prints 31 | That would need both sides to be text. One is a number.
- *Stops with a TypeError: can only concatenate str (not "int") to str | Yes. Mixing text and a number is an error. Convert first: `int("3") + 1`.
:::

:::keyidea
The quotes are the whole difference between the number `3` and the text `"3"`. When
data arrives from a file it often arrives as text — converting it (`int`, `float`) is
one of the first things you do in chapter 0.6.
:::

## Names: variables

A **variable** is a name attached to a value. `width = 6` does not mean "width equals
6"; it means *work out the right-hand side, then attach the name `width` to it*.

:::figure{id=variable_box caption="Figure 3. A name is a label, not a box. Reassigning moves the label. Redrawn for this module."}
:::

:::trace{title="Watch the names change"}
width = 6
depth = 4
area = width * depth
print(area)
width = width + 2
print(width)
print(area)
:::

Step through it and watch `area`: it stays 24 after `width` changes. The line
`area = width * depth` ran once, when width was 6; changing `width` later does not
re-run it. **Python does not remember formulas, only values.**

:::pylab{title="Names"}
# step: Assign, use, reassign
floors = 3
height_per_floor = 3.2
building_height = floors * height_per_floor
print("height:", building_height, "m")

floors = floors + 1          # add a floor
print("floors now:", floors)
print("height still:", building_height, "m   <- not updated on its own")
building_height = floors * height_per_floor
print("recomputed:", building_height, "m")

# step: Naming rules
site_area = 1200            # letters, digits, underscores; starts with a letter
siteArea = 1200             # allowed, but Python style prefers snake_case
# 2nd_site = 5              # cannot start with a digit  (remove the # to see the error)
# class = "office"          # cannot use Python's own words
print(site_area == siteArea)

# step: Your turn - fix the mistake
# This should print the window-to-wall ratio 0.4, but it prints 0.0. Fix ONE line.
window_area = 48
wall_area = 120
wwr = window_area // wall_area
print("WWR:", wwr)
assert wwr == 0.4, "not yet - still 0.0"
print("Correct!")
:::

:::keyidea
`=` is *assignment*: right side first, then attach the name. `==` (two signs) is the
*question* "are these equal?", and you meet it in the decisions section below.
:::

:::compare
Good name | `glazing_area`, `total_heating_kwh`, `n_rooms` | Says what it holds. Lowercase, words joined by underscores. Units in the name when they matter.
Poor name | `x`, `data2`, `temp` | Fine for two lines of scratch work; a mystery a week later. `temp` is temperature or temporary?
:::

## Text: strings

Text values are **strings** (`str`). You will spend a surprising amount of a data
project building labels, file names, and messages.

:::trace{title="Building a message"}
name = "Living room"
area = 30
label = name + ": " + str(area) + " m2"
print(label)
print(f"{name} is {area} m2")
print(name.upper())
print(len(name))
print(name[0])
:::

- `+` joins strings. Numbers must be converted with `str()` first.
- **f-strings** are the cleaner way: put an `f` before the quote and write names in
  `{curly braces}`. `f"{name} is {area} m2"`. Use them everywhere.
- Strings have **methods** — actions you call with a dot: `.upper()`, `.lower()`,
  `.replace(old, new)`, `.split(",")`, `.strip()`.
- `len(s)` is the number of characters; `s[0]` is the first one (counting starts at 0 —
  chapter II explains why).

:::pylab{title="Strings"}
# step: Joining and formatting
room = "kitchen"
area = 12.5
print(room + " has " + str(area) + " m2")
print(f"{room} has {area} m2")
print(f"{room.title()} has {area:.1f} m2 ({area * 10.764:.0f} ft2)")   # :.1f = one decimal

# step: Methods
address = "  3950 University Way NE  "
print(address.strip())                 # remove surrounding spaces
print(address.strip().upper())
print(address.replace("Way", "Wy"))
print("energy,daylight,carbon".split(","))    # text -> a list (chapter II)
print("kitchen" in "kitchen and bath")        # is this text inside that text?

# step: Your turn - a file name
# Build the file name "site_42_south.csv" from these three parts, using an f-string.
site = 42
orientation = "south"
file_name = "..."
assert file_name == "site_42_south.csv", "not yet - file_name is " + file_name
print("Correct:", file_name)
:::

:::keyidea
`f"{value:.2f}"` formats a number with two decimals. `f"{value:,.0f}"` adds thousands
separators. You will use these in every table and plot label from here on.
:::

## Talking to the program: input

`input("prompt")` pauses and waits for the user to type something. It **always returns
text**, even when they type a number — so convert it.

:::trace{title="input() returns text" inputs="4|3.5"}
floors = input("How many floors? ")
height = input("Floor height in m? ")
print(type(floors))
total = int(floors) * float(height)
print(f"Building height: {total} m")
:::

The trace above pretends the user typed `4` and `3.5`. Note the first `print`:
`floors` is a `str` until `int()` converts it. Forgetting that conversion is the most
common beginner bug there is.

:::keyidea
The code boxes on this site cannot pause for typing, so `input()` appears only in
step-through boxes. On your own laptop (VS Code, Setup 1) it works exactly as shown.
:::

## Making decisions: if, elif, else

Programs branch. Comparisons produce `True` or `False`; `if` runs a block only when its
condition is `True`.

:::trace{title="An energy label"}
eui = 142
if eui < 100:
    label = "A"
elif eui < 150:
    label = "B"
else:
    label = "C"
print(f"EUI {eui} -> label {label}")
:::

Step through it and watch which lines run: the first condition is `False`, the second
`True`, so only `label = "B"` executes, and the `else` block is skipped entirely.

:::cards
== != | equal, not equal | `eui == 142`
< > <= >= | less, greater, or-equal | `wwr <= 0.4`
and or not | combine conditions | `tall and glazed`
in | membership | `"N" in orientations`
:::

**Indentation is not decoration.** The lines that belong to an `if` are the ones
indented under it (four spaces, which VS Code does for you when you press Enter after
the colon). The block ends where the indentation ends.

:::pylab{title="Decisions"}
# step: One condition
wwr = 0.55
if wwr > 0.4:
    print("High glazing ratio: check solar gains")
print("This line runs either way - it is not indented")

# step: Several branches
height = 7.0
glazing = 0.4
if height >= 7 and glazing >= 0.4:
    print("tall and heavily glazed: expect the highest loads")
elif height >= 7:
    print("tall")
else:
    print("low-rise")

# step: Your turn - an orientation label
# orientation is a number: 2 = North, 3 = East, 4 = South, 5 = West.
# Write an if / elif / else that sets `name` to the right word, then print it.
orientation = 4
name = "..."
assert name == "South", "not yet - name is " + name
print("Correct:", name)
:::

:::predict
`x = 5` then `if x = 5:` — what happens?
- It prints nothing because 5 is not True | It never gets that far.
- *A SyntaxError: a single = is assignment, not a comparison | Yes. Inside a condition you need `==`. Python refuses to run the file at all.
- It sets x to 5 again and continues | Python does not allow assignment inside an if condition like this.
:::

:::keyidea
Read `if` blocks by their indentation, and remember that `elif` and `else` are
checked only when everything above them was `False`. Order the branches from the most
specific condition to the most general.
:::
