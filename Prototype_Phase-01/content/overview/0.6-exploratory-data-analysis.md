## The dataset: 768 buildings

The **Energy Efficiency** dataset (Tsanas & Xifara, 2012) is on Kaggle and in the UCI
Machine Learning Repository. It holds 768 residential building variants generated in
the Ecotect simulator: twelve base shapes with the same volume, each simulated at four
orientations, four glazing areas and five glazing distributions, in the Athens
climate. Eight columns describe the building; two record the simulated **heating
load** and **cooling load** in kWh/m².

:::stats
768 | buildings
8 | descriptive columns
2 | targets: heating and cooling load
0 | missing values
:::

| Column | Meaning | Values |
|---|---|---|
| `relative_compactness` | how compact the form is; higher = closer to a cube | 0.62 – 0.98 (12 values) |
| `surface_area` | total envelope, m² | 514.5 – 808.5 |
| `wall_area` | m² | 245 – 416.5 |
| `roof_area` | m² | 110.25 – 220.5 |
| `overall_height` | m | 3.5 or 7.0 |
| `orientation` | code: 2 N, 3 E, 4 S, 5 W | a category stored as a number |
| `glazing_area` | glazing as a fraction of floor area | 0, 0.1, 0.25, 0.4 |
| `glazing_distribution` | where the glazing is: 0 none, 1 uniform, 2–5 one facade emphasised | 0 – 5 |
| `heating_load` | simulated, kWh/m² | 6.0 – 43.1 |
| `cooling_load` | simulated, kWh/m² | 10.9 – 48.0 |

A copy ships with the course at `assets/data/energy_efficiency.csv`, with the
original `X1 … Y2` column names replaced by the ones above and nothing else changed.

:::keyidea
**Where it came from matters.** These are simulations on a designed grid, not
measurements of real houses. Every conclusion below is a conclusion about *the
simulator on those twelve shapes in Athens*. The claim-boundary card at the end says
so in full; keep it in mind as you go.
:::

## numpy: arrays

A list holds anything and does nothing with it. A numpy **array** holds numbers of one
type in a grid, and maths applies to the whole grid at once — which is both faster and
shorter to write. pandas, matplotlib, scikit-learn and every model in this course are
built on arrays.

:::figure{id=array_shapes caption="Figure 2. Arrays have a shape: one axis, two, or more. Redrawn for this module."}
:::

:::pylab{title="numpy" packages=numpy}
# step: A list is not an array
import numpy as np

heights_list = [3.5, 7.0, 3.5, 7.0]          # a plain Python list
heights = np.array(heights_list)             # the same numbers as a numpy array
print(heights_list * 2)                      # a list repeats itself
print(heights * 2)                           # an array does maths on every element
print("shape:", heights.shape, " dtype:", heights.dtype)

# step: Maths on the whole grid at once
loads = np.array([15.55, 20.84, 29.79, 11.28, 38.35, 12.07])
print("mean:", loads.mean().round(2), " max:", loads.max(), " where:", loads.argmax())
print("in MJ/m2 instead of kWh/m2:", (loads * 3.6).round(1))
print("above 20:", loads > 20)               # a boolean mask, one True/False per element
print("which ones:", loads[loads > 20])      # the mask picks elements out

# step: Two dimensions - rows and columns
table = np.array([[514.5, 294.0, 110.25],    # one building per row
                  [563.5, 318.5, 122.50],    # surface, wall, roof areas
                  [588.0, 294.0, 147.00]])
print("shape:", table.shape)
print("second building:", table[1])          # a row
print("all roof areas :", table[:, 2])       # a column
print("mean per column:", table.mean(axis=0).round(1))
print("mean per row   :", table.mean(axis=1).round(1))

# step: Where numpy earns its keep - speed on real sizes
big = np.random.default_rng(0).normal(size=1_000_000)
import time
t = time.time(); s = sum(x * x for x in big); t_py = time.time() - t
t = time.time(); s2 = (big * big).sum(); t_np = time.time() - t
print(f"a million squares - Python loop: {t_py:.3f} s   numpy: {t_np:.4f} s   ({t_py / t_np:.0f}x faster)")
print("same answer:", round(s, 3) == round(float(s2), 3))
:::

:::cards
np.array(list) | make an array | one dtype for everything in it
a.shape a.dtype | size along each axis; the type | (768,) or (768, 10); float64
a.mean() a.std() a.max() | summaries | add axis=0 for per-column
a > 20 | a boolean mask | a[a > 20] keeps the True ones
a[:, 2] | slicing works in every axis | rows, then columns
:::

:::predict
`a = np.array([1, 2, 3])` and `b = [1, 2, 3]`. What are `a + a` and `b + b`?
- Both give [2, 4, 6] | A list has no idea what adding means for numbers.
- *array([2, 4, 6]) and [1, 2, 3, 1, 2, 3] | Yes. Arrays do element-wise maths; lists concatenate.
- Both give [1, 2, 3, 1, 2, 3] | An array never concatenates with `+`.
:::

## pandas: tables

A **DataFrame** is a table: named columns, a row index, one dtype per column. Almost
everything you do with one is *pick columns, filter rows, summarise*.

:::figure{id=dataframe_anatomy caption="Figure 3. Anatomy of a DataFrame. Redrawn for this module."}
:::

:::pylab{title="pandas" packages=numpy,pandas}
# step: Load the table and look at it
import pandas as pd
from pyodide.http import open_url
df = pd.read_csv(open_url("assets/data/energy_efficiency.csv"))
print(df.shape)            # (rows, columns)
print(df.head(3))          # the first three rows
print(df.dtypes)           # what kind of value each column holds

# step: describe() - the whole table in one table
print(df.describe().round(2).T)     # .T flips it so columns become rows

# step: Pick columns, filter rows
loads = df["heating_load"]                        # one column: a Series
print(type(loads), loads.mean().round(2))
tall = df[df["overall_height"] == 7.0]           # rows where a condition is True
print("tall buildings:", len(tall), "of", len(df))
print("their mean heating load:", tall["heating_load"].mean().round(2),
      " vs low buildings:", df[df["overall_height"] == 3.5]["heating_load"].mean().round(2))
worst = df.sort_values("heating_load", ascending=False).head(3)
print(worst[["surface_area", "overall_height", "glazing_area", "heating_load"]])

# step: New columns and groupby
df["total_load"] = df["heating_load"] + df["cooling_load"]
df["orient"] = df["orientation"].map({2: "N", 3: "E", 4: "S", 5: "W"})   # numbers -> names
print(df.groupby("orient")["heating_load"].mean().round(2))
print()
print(df.groupby("glazing_area")[["heating_load", "cooling_load"]].mean().round(2))
print()
print(df.groupby(["overall_height", "glazing_area"])["heating_load"].mean().round(1).unstack())
:::

:::figure{id=groupby caption="Figure 4. groupby: split the rows by a column, apply a summary to each group, combine the results. Redrawn for this module."}
:::

:::cards
pd.read_csv(...) | file → DataFrame | the first line of every project
df.head() df.shape df.dtypes | look | before anything else
df.describe() | count, mean, std, min, quartiles, max | for every numeric column at once
df["col"] | one column, a Series | df[["a", "b"]] for several
df[df["col"] > x] | filter rows | a boolean mask, exactly as in numpy
df.groupby("col")["y"].mean() | summarise per group | the question "does col matter?"
:::

:::predict
`df[df["orientation"] == "N"]` returns zero rows. Why?
- pandas cannot filter by text | It can. The comparison is fine; it just matches nothing.
- *The column holds the numbers 2–5, not the letters; nothing equals "N" | Yes. Check `df.dtypes` and `df["orientation"].unique()` before filtering. Codes-as-numbers is the most common data trap there is.
- The file has no North-facing buildings | It has 192 of them, coded as 2.
:::

## matplotlib: plots

matplotlib draws one element at a time and gives you control over all of it. The
pattern is always the same: make a figure and an axes, call methods on the axes, label
it.

:::figure{id=figure_anatomy caption="Figure 5. Figure, axes, title, labels, legend: the parts of every plot. Redrawn for this module."}
:::

:::widget{id=hist-lab}
:::

:::pylab{title="matplotlib" packages=numpy,pandas,matplotlib}
# step: One figure, one plot
import pandas as pd, matplotlib.pyplot as plt
from pyodide.http import open_url
df = pd.read_csv(open_url("assets/data/energy_efficiency.csv"))

fig, ax = plt.subplots(figsize=(6, 3.4))
ax.hist(df["heating_load"], bins=25, color="#4b2e83", edgecolor="white")
ax.set_xlabel("heating load (kWh/m2)"); ax.set_ylabel("buildings")
ax.set_title("768 buildings - two clusters, not one hump")
plt.tight_layout()

# step: A scatter plot answers a different question
fig, ax = plt.subplots(figsize=(6, 3.4))
ax.scatter(df["relative_compactness"], df["heating_load"], s=12, alpha=0.5, color="#4b2e83")
ax.set_xlabel("relative compactness"); ax.set_ylabel("heating load (kWh/m2)")
ax.set_title("More compact -> higher heating load? Look closer.")
plt.tight_layout()
print("correlation:", df["relative_compactness"].corr(df["heating_load"]).round(3))

# step: Colour by a third variable, and the story changes
fig, ax = plt.subplots(figsize=(6, 3.4))
for h, c in [(3.5, "#b7a57a"), (7.0, "#4b2e83")]:
    sub = df[df["overall_height"] == h]
    ax.scatter(sub["relative_compactness"], sub["heating_load"], s=12, alpha=0.6, color=c, label=f"height {h} m")
ax.set_xlabel("relative compactness"); ax.set_ylabel("heating load (kWh/m2)"); ax.legend()
ax.set_title("The two clusters are the two building heights")
plt.tight_layout()

# step: Several plots side by side
fig, axes = plt.subplots(1, 3, figsize=(9, 3))
means = df.groupby("glazing_area")["heating_load"].mean()
axes[0].bar(means.index.astype(str), means.values, color="#4b2e83"); axes[0].set_title("mean load by glazing area")
axes[1].boxplot([df[df.orientation == o]["heating_load"] for o in (2, 3, 4, 5)])
axes[1].set_xticklabels(["N", "E", "S", "W"]); axes[1].set_title("load by orientation")
axes[2].scatter(df["heating_load"], df["cooling_load"], s=8, alpha=0.4, color="#4b2e83")
axes[2].set_title("heating vs cooling"); axes[2].set_xlabel("heating"); axes[2].set_ylabel("cooling")
plt.tight_layout()
print("Three questions, one figure. Which of the three panels has the least to say?")
:::

:::compare
Histogram | one column | How is it distributed? Skew, clusters, outliers. The bin count is a choice — try three.
Scatter | two columns | Do they move together? Colour by a third column before believing the shape.
:::

:::keyidea
**Colouring by a third variable changed the story.** Compactness alone looks like a
weak positive relationship; split by height, it is two flat-ish clouds. The pattern
was height all along. This is why EDA is a loop: the first plot sends you back with a
better question.
:::

## seaborn: statistical plots in one line

seaborn sits on top of matplotlib and knows about DataFrames. Give it the table and
the column names and it draws the comparison, the grid of panels, or the correlation
matrix, with sensible defaults.

:::pylab{title="seaborn" packages=numpy,pandas,matplotlib pip=seaborn}
# step: Seaborn - statistical plots in one line each
import pandas as pd, seaborn as sns, matplotlib.pyplot as plt
from pyodide.http import open_url
df = pd.read_csv(open_url("assets/data/energy_efficiency.csv"))
df["orient"] = df["orientation"].map({2: "N", 3: "E", 4: "S", 5: "W"})
sns.set_theme(style="whitegrid", palette=["#4b2e83", "#b7a57a", "#767676", "#111111"])

fig, ax = plt.subplots(figsize=(6, 3.4))
sns.boxplot(data=df, x="orient", y="heating_load", ax=ax)
ax.set_title("Heating load by orientation: four identical boxes")
plt.tight_layout()

# step: A correlation heatmap - every pair at once
cols = ["relative_compactness", "surface_area", "wall_area", "roof_area", "overall_height",
        "glazing_area", "heating_load", "cooling_load"]
corr = df[cols].corr()
fig, ax = plt.subplots(figsize=(7, 5.5))
sns.heatmap(corr, annot=True, fmt=".2f", cmap="Purples", vmin=-1, vmax=1, ax=ax)
ax.set_title("Correlation between columns")
plt.tight_layout()
features = corr["heating_load"].drop(["heating_load", "cooling_load"])
print("strongest feature for heating_load:", features.abs().idxmax(), round(features.abs().max(), 3))

# step: One plot per group, automatically
g = sns.relplot(data=df, x="surface_area", y="heating_load", hue="glazing_area", col="overall_height",
                palette=["#cfc6e3", "#9a86c9", "#6a4fa8", "#2e1a5a"], height=3.2, aspect=1.1)
g.figure.suptitle("Surface area vs heating load, split by height, coloured by glazing", y=1.04)
print("Two panels, one per height. Inside each, glazing area shifts the cloud up.")
:::

:::keyidea
**seaborn in the browser.** It is not part of the standard browser Python, so this lab
installs it from a copy shipped with the course (about 300 KB, once per visit). On
your laptop it is `pip install seaborn`. The first run of the step above takes a few
extra seconds.
:::

:::technical{summary="What the correlation heatmap can and cannot tell you"}
Pearson's r measures how well a *straight line* describes two columns. Here
`roof_area` and `heating_load` have r = −0.86: strongly negative. Does a bigger roof
lower the heating load? No. In this dataset the twelve shapes share one volume, so the
tall buildings (high loads) are the ones with small footprints, and small footprints
mean small roofs. Roof area is a **proxy** for height. A heatmap shows what moves
together; it never shows why. The scipy section puts numbers on this, and Module 2
(Episode 2.2) covers correlation and causation properly.
:::

## scipy: putting numbers on what you see

scipy is a large library of scientific tools; `scipy.stats` is the part EDA uses:
tests of whether groups differ, correlations with p-values, and simple fits.

:::pylab{title="scipy.stats" packages=numpy,pandas,scipy}
# step: Does orientation matter? Ask the numbers, not the eye
import pandas as pd
from scipy import stats
from pyodide.http import open_url
df = pd.read_csv(open_url("assets/data/energy_efficiency.csv"))

groups = [df[df.orientation == o]["heating_load"] for o in (2, 3, 4, 5)]
print("group means:", [round(float(g.mean()), 2) for g in groups])
f, p = stats.f_oneway(*groups)
print(f"one-way ANOVA: F = {f:.3f}, p = {p:.3f}")
print("A p-value near 1 says: these four means are as alike as random samples from one pot.")

# step: Height matters - and how much
tall = df[df.overall_height == 7.0]["heating_load"]; low = df[df.overall_height == 3.5]["heating_load"]
t, p = stats.ttest_ind(tall, low)
print(f"means {tall.mean():.1f} vs {low.mean():.1f} kWh/m2   t = {t:.1f}   p = {p:.2g}")
print("The difference is not subtle: the effect size, not the p-value, is the finding.")

# step: Correlation, two ways
r, p = stats.pearsonr(df["glazing_area"], df["heating_load"])
rho, p2 = stats.spearmanr(df["glazing_area"], df["heating_load"])
print(f"glazing vs heating   pearson r = {r:.3f}   spearman rho = {rho:.3f}")
r, p = stats.pearsonr(df["roof_area"], df["heating_load"])
print(f"roof area vs heating pearson r = {r:.3f}   (negative! bigger roof = lower load?)")
print("Roof area is large only for the LOW buildings. It is a stand-in for height, not a cause.")

# step: A straight line through the glazing effect
res = stats.linregress(df["glazing_area"], df["heating_load"])
print(f"heating_load = {res.intercept:.1f} + {res.slope:.1f} * glazing_area     R2 = {res.rvalue**2:.3f}")
print("Each +0.1 of glazing area adds about", round(res.slope * 0.1, 1), "kWh/m2 on average - but glazing alone explains only",
      f"{res.rvalue**2:.0%} of the variation.")
:::

:::cards
stats.f_oneway(a, b, c) | do several groups share a mean? | orientation: p = 0.999, no
stats.ttest_ind(a, b) | do two groups differ? | height: t = 54, yes, enormously
stats.pearsonr(x, y) | straight-line correlation and its p-value | glazing vs heating: r = 0.27
stats.spearmanr(x, y) | rank correlation; robust to curves and outliers | 0.32 here
stats.linregress(x, y) | slope, intercept, r, p in one call | the simplest model there is
:::

:::keyidea
A p-value answers one narrow question: "could a difference this large appear by
chance if there were none?" It does not say the difference matters. Report the effect
(31.3 vs 13.3 kWh/m²) first and the p-value second, and Module 2 will show you why
this dataset's tiny p-values still do not make it a model of real buildings.
:::

## Four questions the data can answer, and one it cannot

The EDA loop, run end to end. Each step is a question, the code is how you ask it, and
the printed answer is what the data says. Then a question it *cannot* answer.

:::pylab{title="Four questions" packages=numpy,pandas}
# step: Question 1 - what drives heating load most?
import pandas as pd
from pyodide.http import open_url
df = pd.read_csv(open_url("assets/data/energy_efficiency.csv"))
corr = df.corr()["heating_load"].drop(["heating_load", "cooling_load"]).sort_values()
print(corr.round(3))
print("\nAnswer: height (+0.89). Roof and surface area are negative only because tall buildings have less of both.")

# step: Question 2 - does orientation matter?
print(df.groupby("orientation")["heating_load"].agg(["mean", "std", "count"]).round(2))
print("\nAnswer: no. Four means within 0.12 kWh/m2 of each other. (Why? See the claim boundary below.)")

# step: Question 3 - how much does glazing cost, for a given height?
pivot = df.groupby(["overall_height", "glazing_area"])["heating_load"].mean().round(1).unstack()
print(pivot)
print("\nAnswer: for 7 m buildings, 0 -> 0.4 glazing adds", round(pivot.loc[7.0, 0.4] - pivot.loc[7.0, 0.0], 1),
      "kWh/m2; for 3.5 m buildings", round(pivot.loc[3.5, 0.4] - pivot.loc[3.5, 0.0], 1), "kWh/m2.")

# step: Question 4 - is anything odd in the data?
print("distinct values per column:")
print(df.nunique())
print("\nglazing_distribution == 0 exactly when glazing_area == 0:",
      ((df.glazing_distribution == 0) == (df.glazing_area == 0)).all())
print("Answer: the columns are not free-floating measurements. 12 shapes x 4 orientations x")
print("(1 no-glazing case + 3 glazing areas x 5 distributions) = 12 x 4 x 16 = 768 rows: a designed")
print("grid of simulations, not a survey of real buildings.")
:::

:::predict
Orientation makes no difference to heating load in this dataset. A colleague
concludes that orientation does not matter for building energy. Is that justified?
- Yes — 768 buildings is a large sample | Sample size is not the issue. What was simulated is.
- *No — it is a fact about these twelve simulated shapes in one climate, not about buildings in general | Yes. The result is real for this grid and says nothing about a real house with a real south-facing window in a real city.
- No — the ANOVA was the wrong test | The test is fine; the data cannot carry the conclusion.
:::

:::boundary
Data | 768 building variants simulated in Ecotect by Tsanas & Xifara (2012): 12 base shapes of equal volume, Athens climate, 4 orientations × 4 glazing areas × up to 5 glazing distributions; [[simulated]], not measured; shipped as `assets/data/energy_efficiency.csv` with renamed columns
Split | none — this chapter describes, it does not predict; Module 2 splits this kind of data properly
Evidence | every number on this page is [[simulated]] output summarised by the code shown, and reproduces exactly
Establishes | that height dominates heating and cooling load on this grid; that glazing area adds load roughly linearly; that orientation makes no difference *here*; that roof and surface area act as proxies for height
Does not establish | anything about real buildings, other climates, other shapes, or causation — the simulator was told the physics, and the grid was designed, not sampled
:::

## Common mistakes, so you can recognise them

:::cards
Category stored as a number | orientation 2–5 averaged as if 3.5 meant something | map codes to names before grouping or plotting
Correlation read as cause | roof area "lowers" heating load | ask what else changes with it; here, height
Too few or too many bins | a two-cluster column shown as one hump | try 10, 25, 50 and look for what survives
Filtering on the wrong type | `df[df.orientation == "N"]` returns nothing | check dtypes and unique() first
Means without spread | "orientation N: 22.31" | show std or a boxplot; the boxes overlap entirely
Believing the dataset is the world | "orientation does not matter" | write the claim boundary before the conclusion
:::

:::compare
A number | `df["heating_load"].mean()` → 22.31 | Fast, precise, and blind: it hides the two clusters completely.
A picture | `ax.hist(df["heating_load"])` | Slower to make, imprecise, and it shows the two clusters in one glance. Do both.
:::

## Test yourself

:::predict
`df.groupby("overall_height")["heating_load"].mean()` returns two numbers. What are they?
- The mean heating load of the shortest and tallest building | groupby averages *all* the rows in each group, not one building.
- *The mean heating load over all 3.5 m buildings and over all 7 m buildings | Yes: split by height, average each group, two rows out.
- The heating load at height 3.5 and at height 7 for the first building | groupby never picks a single row.
:::

:::predict
A histogram of `glazing_area` shows four thin bars with gaps between them. What does that tell you?
- The data is corrupted | Nothing is wrong with it.
- *The column takes only four distinct values — it is a category in disguise, and a bar chart of counts would be the better plot | Yes. `df["glazing_area"].value_counts()` is the honest summary.
- More bins would smooth it out | More bins would show the same four spikes, thinner.
:::

:::predict
`stats.pearsonr` gives r = −0.86 between roof area and heating load, p < 0.001. The safest sentence is:
- Larger roofs cause lower heating loads | Correlation never establishes cause, and here a third variable (height) drives both.
- *Roof area and heating load are strongly negatively correlated in this dataset | Yes — and then say why you think so.
- Roof area explains 86% of heating load | r² is 0.74, and "explains" already implies too much.
:::
