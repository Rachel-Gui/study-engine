## What you are setting up

The Module 4 workshop (Episode 4.4) runs on **your own laptop**: a local language
model, a small Python server, and a web dashboard. Nothing runs in the cloud. This
guide takes you from a blank machine to "2 agents online" in about an hour, most of it
downloading. **Do it before the workshop, not during it.**

:::narration
This is the setup guide for the Environmental Negotiators workshop in Module 4. The
workshop runs entirely on your own laptop: a local language model through Ollama, a
small Python backend, and a web dashboard. Work through the eleven steps top to
bottom. Where a command differs between operating systems you will see a Windows tab
and a Mac tab; follow the one for your machine and ignore the other. The step students
get wrong most often is step four, opening the terminal inside the right folder, so
read that one slowly. Finish with step ten, the verification script, before class.
:::

:::stats
11 | steps
~4.7 GB | model download, once
2 | terminals open during the workshop
:::

:::keyidea
**If you did Setup 1 and Setup 2, Steps 1, 2 and 5 are already done** — skip to Step 3
after a quick version check. Everything in this guide still works if you start from
zero.
:::

:::flow
Python > VS Code > Unzip the folder > Terminal inside `negotiators` > Ollama > `llama3.1` + one edit > pip packages > Node.js > npm packages > verify.py > Run both servers
:::

Where the command differs between operating systems you'll see two tabs — **Windows**
and **macOS**. Follow the one for your machine and ignore the other. Grey boxes are
commands to type into the terminal. Key-idea boxes flag things that commonly trip
people up.

## Step 1 — Install Python

**Already have this?** Run `python --version` (Windows) or `python3 --version`
(macOS). If it shows 3.10 or higher, skip to Step 2.

Python is the language the workshop code is written in. You need version **3.10 or
newer**. Go to [python.org/downloads](https://www.python.org/downloads/) and download
the latest Python 3 installer for your OS. Run it.

:::os
[windows]
**Tick "Add python.exe to PATH" on the first installer screen.** If you miss this
checkbox, every command in this guide will fail. If you already installed without it,
uninstall and reinstall with the box checked.

Verify the install:

```
python --version
```
[mac]
**Always use `python3`, not `python`.** Plain `python` often points at an old built-in
version or doesn't exist. Every Python command in this guide uses `python3` on Mac for
that reason.

Verify the install:

```
python3 --version
```
:::

You should see Python 3.10 or higher. If you see "command not found" or "not
recognized", close the terminal, open a new one, and try again.

## Step 2 — Install VS Code

**Already have this?** If VS Code (or another proper code editor like PyCharm or
Sublime) is already installed, skip to Step 3.

VS Code is the editor you'll use to open and edit the workshop code. Go to
[code.visualstudio.com](https://code.visualstudio.com/), download the installer for
your OS, run it, and accept the defaults.

:::keyidea
**Do NOT use Notepad, TextEdit, or Word to edit code.** They silently mangle
indentation and your code will break in ways that are painful to debug. Any real code
editor is fine — just not those three.
:::

## Step 3 — Download and unzip the workshop folder

Download the workshop `.zip` file your instructor sent you. Unzip it to a location
you'll remember — Desktop or Downloads is fine.

After unzipping, you'll have a folder named `environmental-negotiators-student`. Open
it — inside is a subfolder called `negotiators`. **That inner `negotiators` folder is
where everything happens.**

:::cards
negotiators.py | the only file you edit in the workshop | your agents live here
backend/ | the Python server that calls the model | you change one line, once
frontend/ | the web dashboard | Node.js builds it
verify.py | checks your setup in one go | Step 10
:::

## Step 4 — Open a terminal INSIDE the negotiators folder

:::keyidea
**This is the step students mess up most — read carefully.** Every command in the
rest of this guide only works if your terminal is currently sitting inside the
`negotiators` folder. If you open a terminal from the Start menu or Spotlight, it
starts in your home folder — that's wrong. Use one of the methods below instead.
:::

:::os
[windows]
**Easiest method — right-click in File Explorer:**

- Open File Explorer and navigate into `environmental-negotiators-student` until you
  can see the `negotiators` folder.
- Right-click the `negotiators` folder.
- **Windows 11:** click **Open in Terminal**.
- **Windows 10:** hold **Shift** while right-clicking, then choose **Open PowerShell
  window here**.

**Alternative — type the path manually in Command Prompt:**

```
cd "C:\path\to\environmental-negotiators-student\negotiators"
```

Confirm you're in the right place:

```
dir
```

You should see `negotiators.py`, `requirements.txt`, `verify.py`, and a `backend`
folder. If you don't, you're in the wrong place — try again.
[mac]
**Easiest method — drag the folder into Terminal:**

- Open Terminal (Cmd+Space, type "Terminal", hit Enter).
- Type `cd ` in the terminal (note the space after `cd` — don't hit Enter yet).
- Open Finder, navigate into `environmental-negotiators-student`, and find the
  `negotiators` subfolder.
- Drag the `negotiators` folder from Finder directly onto the Terminal window. macOS
  pastes its full path after your `cd `. Hit Enter.

**Alternative** — right-click in Finder → **Services → New Terminal at Folder**.

Confirm you're in the right place:

```
ls
```

You should see `negotiators.py`, `requirements.txt`, `verify.py`, and a `backend`
folder. If you don't, you're in the wrong place — try again.
:::

:::keyidea
**Keep this terminal open for Steps 5 through 10.** If you close it and open a new one
later, you'll need to navigate back into the `negotiators` folder first — same method
as above.
:::

:::predict
You typed `python -m pip install -r requirements.txt` and got
`No such file or directory: requirements.txt`. What happened?
- The download is missing a file | Unlikely — the zip your instructor sent contains it.
- *The terminal is not inside the `negotiators` folder | Yes. Almost every "no such file" in this guide is a wrong-folder problem. Go back to Step 4.
- pip is broken | pip ran fine; it just could not find the file where the terminal was looking.
:::

## Step 5 — Install Ollama

Ollama is the tool that runs the AI model on your computer. Think of it as a
translator between the Python code and the AI brain.

Go to [ollama.com/download](https://ollama.com/download), download the installer for
your OS, and run it.

:::os
[windows]
After installing, look at your **system tray** (bottom-right of the screen) for a small
llama icon. If you don't see it, open the Ollama app from the Start menu.
[mac]
After installing, look at the **top menu bar** (top-right of the screen) for a small
llama icon. If you don't see it, open the Ollama app from your Applications folder.
:::

:::keyidea
**If you already had Ollama installed from before — update it.** Open the Ollama app
and let it update itself. Older versions may behave unexpectedly with the `llama3.1`
model.
:::

## Step 6 — Download llama3.1 and point the workshop code at it

Three parts: download the model, test it runs, then edit one line of code so the
workshop knows which model to use.

**6a — Download the model.** In your terminal (still inside the `negotiators` folder),
run this. The command is the same on Windows and macOS:

```
ollama pull llama3.1
```

:::keyidea
**This downloads about 4.7 GB.** On a decent connection it takes a few minutes. On
university Wi-Fi it can be slow or get blocked entirely. If it hangs or fails, try
your phone hotspot.

**If you see "ollama is not recognized" (Windows) or "command not found: ollama"
(macOS)…** close the terminal, open a new one, navigate back into the `negotiators`
folder (Step 4 method), and try again. New installs don't show up in terminals that
were already open.
:::

**6b — Test that it runs.** Once the download finishes, start the model to confirm
it's working:

```
ollama run llama3.1
```

You'll see a prompt like `>>> Send a message`. That means it's working. Type this and
hit Enter to exit back to your normal terminal:

```
/bye
```

Ollama keeps the model available in the background for the workshop.

**6c — Edit `backend/runner.py` so the code uses llama3.1.** By default the workshop
code is configured for a different model. You need to change one line so it points at
the `llama3.1` model you just downloaded.

- Open VS Code.
- Go to **File → Open Folder…** and choose the `negotiators` folder (the same one your
  terminal is in).
- In the sidebar on the left, expand the `backend` folder and click on `runner.py` to
  open it.
- Scroll to **line 9**. Line numbers appear on the left edge of the editor.

Line 9 currently looks like this:

```
MODEL = os.environ.get("OLLAMA_MODEL", "glm-5.1:cloud")
```

Change the model name so line 9 reads exactly:

```
MODEL = os.environ.get("OLLAMA_MODEL", "llama3.1")
```

Save the file: **Ctrl+S** on Windows, **Cmd+S** on macOS.

:::technical{summary="If llama3.1 is too slow on your laptop, swap to a lighter model"}
`mistral` is a common fallback (smaller, faster, less RAM). To swap: run
`ollama pull mistral` in your terminal to download it, then come back to line 9 of
`backend/runner.py` and change `"llama3.1"` to `"mistral"`, and save the file.

```
MODEL = os.environ.get("OLLAMA_MODEL", "mistral")
```

For the workshop, **start with `llama3.1`** — only swap if you hit real performance
problems during class. The RAM table in Setup 2 tells you what your machine can run.
:::

## Step 7 — Install the Python packages

Make sure your terminal is still inside the `negotiators` folder (Step 4). Then run:

:::os
[windows]
```
python -m pip install -r requirements.txt
```

**If you see "Fatal error in launcher"…** your pip shortcut is broken. Use the command
exactly as written above (`python -m pip …`). If even that fails, try:

```
py -m pip install -r requirements.txt
```
[mac]
```
pip3 install -r requirements.txt
```

**Do NOT use `sudo`.** If you get a permission error, try the command again without
`sudo`. If it still fails, your Python was installed as root — reinstall from
python.org.
:::

This installs FastAPI, Uvicorn, the Ollama client, and a few others. It takes 30
seconds to a minute. You'll see a lot of "Successfully installed…" lines at the end. A
few yellow warnings are normal.

:::keyidea
**If you see "No such file or directory: requirements.txt"…** your terminal isn't
inside the `negotiators` folder. Go back to Step 4 and fix that first.
:::

## Step 8 — Install Node.js

**Already have this?** Run `node --version`. If it shows v18 or higher, skip to Step 9.

Node.js runs the web dashboard. Check first:

```
node --version
```

If you need to install it, go to [nodejs.org](https://nodejs.org/) and download the
**LTS** version on the left side of the page (not "Current"). LTS means long-term
support — more stable.

:::keyidea
**After installing Node, close your terminal and open a new one.** The old terminal
doesn't know Node exists yet. Re-do Step 4 to get back into the `negotiators` folder,
then keep going.
:::

## Step 9 — Install the dashboard packages

From inside the `negotiators` folder, run these three commands one at a time. The
commands are the same on Windows and macOS:

```
cd frontend
npm install
cd ..
```

This takes one to two minutes. You'll see a lot of warnings — ignore them. The `cd ..`
at the end puts you back in the main `negotiators` folder, which matters for the next
step.

:::keyidea
**If you see "npm is not recognized" / "command not found: npm"…** you either skipped
Step 8 or didn't restart your terminal after installing Node. Close the terminal, open
a new one, navigate back into the `negotiators` folder, and try again.
:::

## Step 11 — Run the agents

Installation done. Now you'll start the two servers that make the dashboard work. You
need **TWO terminal windows open at the same time** — one for the backend (the AI
brain), one for the frontend (the dashboard web page).

:::keyidea
**Before you start — confirm Ollama is running.** Look for the llama icon (Windows
system tray / Mac top menu bar). If you don't see it, open the Ollama app first. The
backend will crash on startup if Ollama isn't running.
:::

**Terminal #1 — start the backend.** Open your first terminal and make sure it's
inside the `negotiators` folder (Step 4 method). Then run:

:::os
[windows]
```
python -m uvicorn backend.main:app --reload --port 8002
```
[mac]
```
python3 -m uvicorn backend.main:app --reload --port 8002
```
:::

You should see log lines ending with:

```
INFO:     Uvicorn running on http://127.0.0.1:8002
INFO:     Application startup complete.
```

:::keyidea
**LEAVE this terminal running the whole time you're using the workshop.** Do not close
it. If you close it, the dashboard dies. If you need to stop the server later, press
**Ctrl+C** in this terminal.
:::

**Terminal #2 — start the frontend.** Open a SECOND terminal (don't close Terminal
#1) and navigate it into the `negotiators` folder too — same Step 4 method. Then run
these two commands one at a time. The commands are the same on Windows and macOS:

```
cd frontend
npm run dev
```

You should see:

```
VITE v5.x.x  ready in 500 ms
➜  Local:   http://localhost:5173/
```

:::keyidea
**LEAVE this terminal running too.** Both servers — backend and frontend — must stay up
while you use the dashboard.
:::

**Open the dashboard.** In Chrome or Edge, go to **http://localhost:5173**. Check the
header — it should say **"2 agents online"** (the Site Researcher and the Manager —
you'll add the advocates during the workshop).

:::keyidea
**If the header says "0 agents online"…** look at Terminal #1 — there's probably red
error text meaning `negotiators.py` has a syntax error. Your instructor will walk you
through fixing this during class.
:::

When class is over and you want to shut everything down, go to each terminal and press
**Ctrl+C**. Close the browser tab. Done.

:::compare
Terminal #1 — backend | `uvicorn backend.main:app --reload --port 8002` | The AI brain. Reads `negotiators.py`, calls Ollama, returns JSON. Reloads itself when you save the file.
Terminal #2 — frontend | `npm run dev` inside `frontend/` | The dashboard at localhost:5173. Sliders in, agent cards out. Talks to Terminal #1 on port 8002.
:::

## What this setup is, in course terms

Every piece you just installed maps onto a concept from Module 4. The model is the
thing that reads a system prompt and answers; the backend is where an agent's
`instructions` become that system prompt; the pipeline in `backend/pipeline.py` is the
orchestration — Site Researcher first, advocates in parallel, Manager last. Episode
4.1 walks through those files line by line.

:::boundary
Setup | Ollama + `llama3.1` on your own hardware, Python 3.10+, Node.js 18+; guide last verified September 2026
Evidence | every argument an advocate makes is [[generated]] — the debate surfaces tradeoffs, it does not verify them
Establishes | a working local agent system you can edit, run, and watch phase by phase
Does not establish | that the model's numbers are right, or that a local 8B model matches a hosted one in quality
:::

## Troubleshooting

Scan the middle column for what you're seeing. The fix is in the right column. The OS
column tells you which system the row applies to (Both = applies to both).

| OS | What you see | What to do |
|---|---|---|
| Windows | `'python' is not recognized` | You installed Python without "Add python.exe to PATH". Reinstall with that box checked, or use `py` instead of `python` everywhere. |
| Windows | `'pip' is not recognized` | Same root cause. Use `python -m pip` or `py -m pip` everywhere this guide says `pip`. |
| Windows | `Fatal error in launcher` | The pip shortcut is broken. Use `python -m pip install -r requirements.txt` instead of plain `pip`. |
| macOS | `python` not found | On Mac use `python3`, not `python`. Same for pip — use `pip3`. This applies to every command in this guide. |
| macOS | Permission error (`EACCES`) | Don't use `sudo`. Try the command again without it. If it still fails, your Python was installed as root — reinstall from python.org. |
| Both | `ollama` command not found | Close the terminal, open a new one, navigate back into the `negotiators` folder (Step 4), and try again. New installs need a fresh terminal. |
| Both | `No such file: requirements.txt` | Your terminal isn't inside the `negotiators` folder. Go back to Step 4. |
| Both | `ollama pull` hangs forever | Your network is probably blocking Ollama. Switch to a phone hotspot and try again. |
| Both | `npm install` fails or hangs | Press Ctrl+C to cancel. Delete the `frontend/node_modules` folder if it was partially created. Make sure you ran `cd frontend` first. Try again. |
| Both | verify.py says model not found | You skipped `ollama pull llama3.1` in Step 6, or it failed silently. Run it again. |
| Both | verify.py says Ollama not running | The Ollama app isn't open. Start it — look for the llama icon in the system tray (Windows) or top menu bar (Mac). |
| Both | verify.py: only "Backend reachable" fails | That's expected until you reach Step 11. Your setup is fine. |
| Both | Browser shows "Connection refused" | Terminal #1 (backend) isn't running. Start it again — see Step 11. |
| Both | Browser shows a blank page | Terminal #2 (frontend) isn't running. `cd frontend` then `npm run dev`. |
| Both | Header says "0 agents online" after you save | A typo in `negotiators.py` — missing comma between agents, unclosed quote, extra or missing parenthesis. Terminal #1 shows the error in red. |
| Both | Nothing happens when you click Debate | Your `advocates` list is empty. Add at least one agent (Episode 4.4). |

If you're stuck, ask for help early — don't wait until the workshop starts.
