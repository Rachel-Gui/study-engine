## Repeating yourself is a bug

If you compute an area in three places, you will fix a mistake in two of them. A
**function** is a named block you write once and call many times; a **class** is a
bundle of data and the functions that belong to it; a **library** is a collection of
functions someone else wrote. This chapter adds all three, and then the skill that
holds them together: reading an error message calmly.

:::narration
Chapter three is about not repeating yourself. If you compute an area in three
places, you will fix a mistake in two of them. A function is a block you write once
and call many times, with its own private workspace. A class bundles data with the
functions that belong to it, which is how every library you meet is built. And a
library is a toolbox of functions someone else wrote, which you bring in with import.
The chapter ends with the skill that holds everything together: reading an error
message from the bottom up, calmly, and fixing what it names. Then a capstone program
that uses all of it.
:::

## Functions

`def` names a block and lists its **parameters**. Calling the function with
**arguments** runs the block with those values; `return` hands one value back.

:::trace{title="Define once, call twice"}
def area(width, depth):
    result = width * depth
    return result

kitchen = area(4, 3)
living = area(6, 5)
print(kitchen, living)
print(area(2.5, 2) + area(4, 3.5))
:::

Watch the variables panel while stepping. Inside the call a second table appears,
`inside area()`, with `width`, `depth` and `result`. When the function returns, that
table vanishes: those names never existed outside. Only the returned value comes back.

:::cards
def name(params): | starts a function | the colon and the indent, as with if
return value | hands a value back and ends the call | a function without return gives None
area(4, 3) | a call: arguments fill the parameters | in order, or by name: area(depth=3, width=4)
"""docstring""" | a sentence about what it does | shown by help(area)
:::

:::pylab{title="Functions"}
# step: Define and call
def area(width, depth):
    """Floor area in square metres."""
    return width * depth

print(area(4, 3))
print(area(width=6, depth=5))            # by name: clearer, order does not matter
rooms = [(4, 3), (6, 5), (2.5, 2)]
print([area(w, d) for w, d in rooms])    # a function inside a comprehension

# step: Defaults, and more than one result
def eui(energy_kwh, area_m2, per="year"):
    """Energy use intensity. `per` is only for the label."""
    value = energy_kwh / area_m2
    return value, f"{value:.1f} kWh/m2 per {per}"

number, label = eui(1_320_000, 9300)     # a function can return a tuple; unpack it
print(number)
print(label)
print(eui(1_320_000, 9300, per="annum")[1])

# step: What happens without return
def shout(text):
    print(text.upper())

result = shout("done")
print(result)                            # None: shout printed, but returned nothing

# step: Your turn - a comfort function

    return "..."

assert comfort(17) == "too cold" and comfort(30) == "too warm" and comfort(22) == "comfortable", "not yet"

:::

:::predict
A function ends with `print(total)` instead of `return total`. What does `x = f()` leave in `x`?
- The total | It was printed, not returned. Printing and returning are different things.
- *None | Yes. Without `return`, a function returns `None`. You see the number on the screen but cannot use it.
- An error | Calling it is fine; the surprise comes later when `x + 1` fails.
:::

:::keyidea
**Scope.** Names created inside a function live only inside that call. That is a
feature: `total` in your function cannot collide with `total` in mine. To get a value
out, `return` it; to get a value in, pass it as an argument.
:::

## Methods: functions that belong to a value

`len(rooms)` is a function. `rooms.append("hall")` is a **method**: a function that
belongs to the list and acts on it, called with a dot. Strings, lists, dictionaries,
files and every library object you meet come with methods.

:::trace{title="The dot reaches inside"}
name = "living room"
print(name.upper())
print(name.replace(" ", "_"))
rooms = ["hall", "bath"]
rooms.append("kitchen")
rooms.sort()
print(rooms)
print(rooms.index("hall"))
:::

:::compare
function(thing) | `len(rooms)`, `sum(loads)`, `round(x, 1)` | Stands alone; the thing goes in the brackets. Works on many types.
thing.method() | `rooms.append(x)`, `name.upper()`, `df.head()` | Belongs to the thing; called with a dot. Often changes the thing in place.
:::

:::pylab{title="Methods"}
# step: In place, or a new value?
rooms = ["hall", "bath", "kitchen"]
result = rooms.sort()            # sorts the list itself...
print(rooms, result)             # ...and returns None
name = "hall"
result = name.upper()            # strings cannot change; upper() returns a NEW string
print(name, result)

# step: Discover the methods
print([m for m in dir(rooms) if not m.startswith("_")])     # every list method
print(rooms.count("hall"), rooms.index("kitchen"))
rooms.insert(0, "entry"); rooms.pop(); print(rooms)

# step: Your turn - clean a label

raw = "  Gould Hall "
clean = raw
assert clean == "gould-hall", "not yet"
print("Correct:", clean)
:::

## Libraries: import

Python ships with a standard library — hundreds of modules such as `math`, `random`,
`statistics`, `csv`, `json`, `datetime` — and `pip install` (Setup 1) adds thousands
more: numpy, pandas, matplotlib, scikit-learn. `import` brings a module in; the dot
reaches inside it.

:::figure{id=imports caption="Figure 2. A library is a toolbox someone else wrote. import brings it in; the dot reaches inside. Redrawn for this module."}
:::

:::trace{title="Three ways to import"}
import math
from statistics import mean, median
import random as rnd
print(math.sqrt(2))
print(math.pi)
print(mean([12, 30, 5]))
print(median([12, 30, 5]))
rnd.seed(1)
print(rnd.choice(["N", "E", "S", "W"]))
:::

:::cards
import math | brings the module in | use math.sqrt, math.pi
from statistics import mean | brings one name in | use mean directly
import numpy as np | brings it in under a short alias | the convention everyone uses
help(math.sqrt) | reads the documentation | works for anything
:::

:::pylab{title="Libraries" packages=numpy}

## Errors, and how to read them

You will see error messages every hour you write code, for as long as you write code.
They are not failures; they are the most precise help you will get. Read them from the
**bottom up**.

:::figure{id=traceback caption="Figure 3. Anatomy of a traceback: the last line says what went wrong; the line above it says where. Redrawn for this module."}
:::

:::trace{title="A program that crashes"}
areas = {"kitchen": 12, "living": 30}
total = 0
for room in ["kitchen", "living", "attic"]:
    total = total + areas[room]
print(total)
:::

Step to the end. The third pass through the loop asks for `"attic"`, which is not a
key, and the program stops with `KeyError: 'attic'`. Everything before that ran; the
last `print` never did.

| Error | What it almost always means | First thing to check |
|---|---|---|
| `SyntaxError` | Python cannot even read the line | a missing `:` or `)` or quote, usually on the line above the arrow |
| `IndentationError` | the indent does not match | mixed tabs and spaces, or a block with nothing in it |
| `NameError: name 'x' is not defined` | you used a name before giving it a value | a typo, or a variable made inside a function |
| `TypeError` | the types do not fit the operation | text + number, or calling something that is not a function |
| `ValueError` | right type, impossible value | `int("abc")`, a wrong-length unpacking |
| `IndexError` | position does not exist | off by one; the last index is `len - 1` |
| `KeyError` | the dictionary has no such key | a typo in the key, or use `.get()` |
| `ZeroDivisionError` | you divided by zero | an empty list's mean, a zero area |
| `ModuleNotFoundError` | the library is not installed | `pip install`, in the same Python you run |
| `FileNotFoundError` | wrong path | the terminal is in the wrong folder (Setup 1, Step 3) |

:::pylab{title="Errors"}
# step: Read one
loads = [15.55, 20.84, 29.79]
print(loads[3])

# step: Handle one with try / except
areas = {"kitchen": 12, "living": 30}
for room in ["kitchen", "living", "attic"]:
    try:
        print(room, areas[room])
    except KeyError:
        print(room, "- no area recorded, skipping")
print("the program continued")

# step: Convert user text safely
for text in ["42", "3.5", "twelve"]:
    try:
        print(text, "->", float(text))
    except ValueError:
        print(text, "-> not a number")

# step: Your turn - find the bug
# This should print the mean of the loads, but it crashes. Read the error, fix one character.
loads = [15.55, 20.84, 29.79]
total = 0
for i in range(1, len(loads) + 1):
    total = total + loads[i]
print(total / len(loads))
:::

:::keyidea
`try:` runs a block; if the named error happens, the `except` block runs instead and
the program carries on. Catch **specific** errors (`except KeyError`), not everything
— a bare `except:` hides your own mistakes.
:::

:::predict
The last line of an error says `NameError: name 'totl' is not defined`. What happened?
- The variable was deleted | Python does not delete variables on its own.
- *A typo: the name was written differently where it was created | Yes. Read the name in the message letter by letter against your assignment.
- The function needs a return | That would be a different error later, not a NameError.
:::

## Classes and objects

A **class** is a blueprint: which data each thing carries (**attributes**) and which
functions belong to it (**methods**). An **object** is one thing built from the
blueprint. You have used objects all along — a string is an object with methods like
`.upper()`; a pandas DataFrame is an object with `.head()`. Writing your own shows what
is behind the dot.

:::figure{id=class_blueprint caption="Figure 4. One class, three objects: the same methods, their own data. Redrawn for this module."}
:::

:::trace{title="A Room class"}
class Room:
    def __init__(self, name, width, depth):
        self.name = name
        self.width = width
        self.depth = depth

    def area(self):
        return self.width * self.depth

kitchen = Room("kitchen", 4, 3)
living = Room("living", 6, 5)
print(kitchen.area())
print(living.name, living.area())
kitchen.width = 5
print(kitchen.area())
:::

- `__init__` runs when you build an object: `Room("kitchen", 4, 3)` calls it with those
  values. `self` is the object being built; `self.name = name` stores an attribute on it.
- Every method takes `self` first. Calling `kitchen.area()` passes `kitchen` as `self`.
- Attributes can be read and changed with the dot: `kitchen.width = 5`.

:::pylab{title="Classes"}
# step: Build the class
class Room:
    """A rectangular room."""
    def __init__(self, name, width, depth, floor=0):
        self.name = name
        self.width = width
        self.depth = depth
        self.floor = floor

    def area(self):
        return self.width * self.depth

    def describe(self):
        return f"{self.name} ({self.area():.1f} m2, floor {self.floor})"

rooms = [Room("kitchen", 4, 3), Room("living", 6, 5), Room("bed", 4, 3.5, floor=1)]
for r in rooms:
    print(r.describe())
print("total:", sum(r.area() for r in rooms), "m2")

# step: Objects hold their own state
kitchen = rooms[0]
kitchen.width = 5.5
print(kitchen.describe())
print(rooms[0].describe())        # the same object - lists hold references, not copies

# step: A class that builds on another
class Building:
    def __init__(self, name):
        self.name = name
        self.rooms = []
    def add(self, room):
        self.rooms.append(room)
        return self               # so calls can chain
    def floor_area(self):
        return sum(r.area() for r in self.rooms)

house = Building("Cottage").add(Room("kitchen", 4, 3)).add(Room("living", 6, 5))
print(house.name, house.floor_area(), "m2", len(house.rooms), "rooms")

# step: Your turn - a method
# Add a method `volume(self, height)` to Room that returns area x height, then print it for a 2.7 m kitchen.
class Room:
    def __init__(self, name, width, depth):
        self.name, self.width, self.depth = name, width, depth
    def area(self):
        return self.width * self.depth

k = Room("kitchen", 4, 3)
assert round(k.volume(2.7), 2) == 32.4, "not yet"
print("Correct:", k.volume(2.7), "m3")
:::

:::keyidea
You will write few classes in this course and use hundreds. The point of writing one
is to see that `df.head()` is just a method on an object, `self.width` is just an
attribute, and nothing behind the dot is magic.
:::

## Files

Data lives in files. Text files are read and written with `open`; CSV files (comma
separated values — the format every dataset in this course arrives in) with the
`csv` module or, from chapter 0.6 on, with pandas.

:::pylab{title="Files"}
# step: Write a file, then read it back
lines = ["name,width,depth", "kitchen,4,3", "living,6,5", "bath,2.5,2"]
with open("rooms.csv", "w") as f:            # "w" = write; the file closes itself after the block
    f.write("\n".join(lines) + "\n")

with open("rooms.csv") as f:                 # default is read
    text = f.read()
print(text)

# step: Read it as rows
import csv
with open("rooms.csv") as f:
    rows = list(csv.DictReader(f))           # one dictionary per row, keys from the header
print(rows[0])
total = sum(float(r["width"]) * float(r["depth"]) for r in rows)    # values arrive as TEXT
print("total area:", total, "m2")

# step: JSON - the shape of nested data on disk
import json
building = {"name": "Cottage", "rooms": rows}
with open("building.json", "w") as f:
    json.dump(building, f, indent=2)
print(open("building.json").read()[:120], "...")
back = json.load(open("building.json"))
print(back["rooms"][1]["name"])

# step: Your turn - append a room
# Add a line "study,3,3" to rooms.csv (open with mode "a" = append), then re-read and print the number of rows.
n_rows = ...
assert n_rows == 4, "not yet - n_rows should be 4"
print("Correct:", n_rows, "rows")
:::

:::keyidea
`with open(...) as f:` is the pattern. The file is closed automatically at the end of
the block, even if an error happens inside it. Values read from a CSV are **text**
until you convert them — which is the first thing pandas does for you in 0.6.
:::

## Capstone: a room schedule report

Everything from three chapters in one small program: data in a file, a class, a
function, loops, dictionaries, formatting, and an error handled. Run the steps in
order; the last two are yours.

:::pylab{title="Capstone"}
# step: The data
import csv
text = """name,floor,width,depth,use
kitchen,0,4,3,service
living,0,6,5,living
hall,0,2,4,circulation
bath,1,2.5,2,service
bed 1,1,4,3.5,sleeping
bed 2,1,3.5,3,sleeping
study,1,3,3,living
"""
with open("schedule.csv", "w") as f:
    f.write(text)
rows = list(csv.DictReader(open("schedule.csv")))
print(len(rows), "rooms loaded; first:", rows[0])

# step: A class and a function
class Room:
    def __init__(self, row):                       # build straight from a CSV row
        self.name = row["name"]
        self.floor = int(row["floor"])
        self.width = float(row["width"])
        self.depth = float(row["depth"])
        self.use = row["use"]
    def area(self):
        return self.width * self.depth

def by_key(rooms, key):
    """Group rooms by an attribute name: {value: [rooms]}."""
    groups = {}
    for r in rooms:
        groups.setdefault(getattr(r, key), []).append(r)
    return groups

rooms = [Room(row) for row in rows]
print("total area:", sum(r.area() for r in rooms), "m2")

# step: The report
for floor, group in sorted(by_key(rooms, "floor").items()):
    print(f"\nFloor {floor}")
    for r in sorted(group, key=Room.area, reverse=True):
        print(f"  {r.name:8s} {r.area():5.1f} m2  {r.use}")
    print(f"  {'subtotal':8s} {sum(r.area() for r in group):5.1f} m2")

## Test yourself (III)

:::predict
`def f(x): x = x + 1` then `n = 5; f(n); print(n)`. What prints?
- 6 | The `x` inside the function is a separate name. Changing it does not change `n`.
- *5 | Yes. Numbers are passed by value into the function's own workspace; nothing was returned or reassigned outside.
- An error | Everything here is valid; it just does not do what a beginner expects.
:::

:::predict
Which is the method call?
- `len(names)` | A function: `len` stands alone and takes the list as an argument.
- *`names.sort()` | Yes: called with a dot, it belongs to the list.
- `sorted(names)` | A function that returns a new list.
:::

:::predict
`import numpy as np` fails with `ModuleNotFoundError`. What is the fix?
- Rename the alias | The alias is fine; the module itself was not found.
- *Install it into this Python: `python -m pip install numpy`, then run again | Yes — and make sure it is the same Python that runs your script.
- Restart the computer | Almost never the answer for a Python error.
:::

:::predict
In `class Room: def area(self): ...`, what is `self`?
- A keyword that must always be there but means nothing | It is not a keyword; it is a name, by convention.
- *The particular object the method was called on | Yes. `kitchen.area()` runs `area` with `self` set to `kitchen`.
- The class itself | The class is `Room`; `self` is one room.
:::
