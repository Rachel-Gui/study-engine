:::scene{type=title}
narration: |
  Welcome to lesson eight point two: graphs, graph neural networks, and spatial
  relationships. A photograph tells you what a building looks like. It does not tell you
  that the kitchen opens onto the living room, or that two air handlers share a duct.
  Architecture is full of relationships, and a grid of pixels cannot hold them. This
  lesson is about the data structure that can, the network that learns on it, and the
  one word people misuse when they talk about it.
:::

:::scene{type=diagram id=plan_to_graph}
heading: The same seven rooms — as geometry, and as relationships
points:
  - A floor plan — rooms have positions and sizes
  - A graph — nodes are rooms, edges are doors, adjacency, sightlines
  - Node features — area, use, occupancy, temperature
  - Edge features — distance, door width, shared wall
narration: |
  Here is a seven room plan drawn twice. On the left, as geometry: every room has a
  position and a size. On the right, the same plan as a graph: each room becomes a node,
  a dot, and each door or shared wall becomes an edge, a line between two dots. The
  geometry is gone and the relationships remain. Nodes carry features, like area and use.
  Edges can carry features too, like distance or door width. A graph is simply this:
  things, and the connections between them.
:::

:::scene{type=cards}
heading: What a graph can be asked
items:
  - title: Node-level
    text: One answer per node. Which rooms overheat? Which sensors are faulty?
    tag: per room
  - title: Edge-level
    text: One answer per pair. Should these two rooms be adjacent? Will this door see traffic?
    tag: per connection
  - title: Graph-level
    text: One answer for the whole thing. Does this plan meet the brief? What is its energy class?
    tag: per plan
narration: |
  Three kinds of question. Node level: one answer per node. Which rooms overheat, which
  sensors are faulty. Edge level: one answer per pair. Should these two rooms be
  adjacent, will this door see heavy traffic. Graph level: one answer for the whole
  structure. Does this plan meet the brief, what is this building's energy class. Rooms,
  facades, sensors, whole buildings, city blocks: anything with relationships can be a
  node.
:::

:::scene{type=diagram id=message_passing}
heading: One layer of message passing
points:
  - Every node starts with its own features
  - Messages arrive from connected neighbours
  - Aggregate — mean, sum or max of the messages
  - Update — combine with the node's own state, giving a new state
narration: |
  Now the operation a graph neural network repeats, called message passing. Every node
  starts with its own features. Then each node receives messages from the nodes it is
  connected to, its neighbours. It aggregates them, with a mean, a sum or a max, so it
  does not matter how many neighbours there are or in what order. Then it updates: it
  combines the aggregate with its own state and produces a new one. That is one layer.
  After one layer, every room knows about the rooms next door.
:::

:::scene{type=quiz}
question: A signal starts in the kitchen. The kitchen has one door, to the living room. The living room connects to the hall, and the hall to Bed 1. How many layers does the signal need to reach Bed 1?
options:
  - One
  - Two
  - Three
answer: 2
pause: 5
explain: Each layer moves information one hop. Kitchen to living room is one; living room to hall is two; hall to Bed 1 is three. Depth in a GNN is how far information can travel through the plan.
narration: |
  A check. A signal starts in the kitchen. The kitchen has one door, to the living room.
  The living room connects to the hall, and the hall to bedroom one. How many layers does
  the signal need to reach bedroom one? A: one. B: two. C: three. Pause and pick.
after: |
  It is C, three. Each layer moves information one hop along the edges. Kitchen to living
  room is one hop; living room to hall is two; hall to bedroom one is three. In a graph
  network, depth is how far information can travel through the plan. Which raises a
  question: why not use twenty layers?
:::

:::scene{type=idea icon=warn}
text: Over-smoothing. / Enough layers, and every room holds the same average.
sub: Every layer averages a node with its neighbours. Real GNNs are two to four layers deep, with skip connections when they need more reach.
narration: |
  Because of over smoothing. Every layer averages a node with its neighbours. Do that
  enough times and every node holds the same average, and the model can no longer tell
  the kitchen from the bedroom. Real graph networks are two to four layers deep, and use
  skip connections, shortcuts that carry a node's original features forward, when they
  need more reach. The lab on the lesson page lets you watch the rooms blur together.
:::

:::scene{type=compare}
heading: Grid or graph?
left:
  title: Grid — a CNN
  points:
    - Pixels with a fixed neighbourhood
    - Right for images and rasters
    - Wrong for a plan — "next to" is not a pixel offset
right:
  title: Graph — a GNN
  points:
    - Nodes with whatever neighbours they have
    - Right for plans, systems, networks
    - Rooms can have different numbers of neighbours
verdict: Pick the representation that matches how the data is actually connected.
narration: |
  Grid or graph? A convolutional network works on a grid: every pixel has the same eight
  neighbours in the same places. That is right for images and rasters. It is wrong for a
  plan, where next to is not a pixel offset, and a hall might touch six rooms while a
  closet touches one. A graph network works on nodes with whatever neighbours they have.
  Pick the representation that matches how the data is actually connected, not the one
  you happen to know.
:::

:::scene{type=idea icon=bulb}
text: A graph is a data structure. / A GNN is a model that learns on it.
sub: A hypergraph, an adjacency algorithm, a rule-based generator or a self-organizing map is not automatically a GNN. Use the word only when a neural message-passing model actually trained.
narration: |
  Now the word people misuse. A graph is a data structure: nodes and edges. A graph
  neural network is a neural model that learns on that structure through message
  passing. Drawing your plan as a graph does not make your method a G N N. A hypergraph,
  where one edge can connect several rooms at once, is a richer data structure; it is
  still not a network. Use the word only when a neural message passing model actually
  trained on the graph.
:::

:::scene{type=quiz}
question: A paper builds a hypergraph of room relationships, runs a rule-based generator on it, and describes the method as "a GNN approach". Is the description accurate?
options:
  - Yes — a hypergraph is a kind of graph
  - No — no neural message-passing model learned anything; it is a graph-based method
  - Yes, if the rules were tuned by hand
answer: 1
pause: 5
explain: GNN names a model that learns on graphs, not the presence of a graph. The data structure is graph-like; nothing neural learned on it. Tuning rules by hand is not training a network.
narration: |
  A check. A paper builds a hypergraph of room relationships, runs a rule based
  generator on it, and describes the method as a G N N approach. Is the description
  accurate? A: yes, a hypergraph is a kind of graph. B: no, no neural message passing
  model learned anything, so it is a graph based method. C: yes, if the rules were tuned
  by hand. Pause and pick.
after: |
  It is B. G N N names a model that learns on graphs, not the presence of a graph. The
  data structure is graph like; nothing neural learned on it. And tuning rules by hand
  is not training a network. When you read that word in a paper, look for the training.
:::
