:::scene{type=title}
narration: |
  Welcome to lesson eight point three: sequences, time and attention. In lesson seven
  point four, a network looked at twenty eight sensors and the clock and tried to predict
  the next ten minutes of appliance energy. It did poorly, evaluated on unseen data. Every reading was
  treated as if it had no past. This lesson gives the model the past, in three different
  ways, and starts with the simplest sequence model there is: a model with no learning
  in it at all.
:::

:::scene{type=idea icon=bulb}
text: Persistence — ŷ(t) = y(t − 1). / Tomorrow will be like today.
sub: On the appliance data, persistence reaches R² ≈ 0.47 on a chronological test period. Any sequence model that cannot beat it has learned nothing about time.
narration: |
  The persistence baseline. The prediction for the next reading is simply the last
  reading. No training, no weights, one line of code. On the appliance data it reaches
  an R squared of about zero point four seven on a chronological test period. Remember
  that the network from seven point four, with all its sensors, scored far lower on that
  same split. So here is the rule for this whole lesson: any sequence model that cannot
  beat persistence has learned nothing about time. Always fit it first.
:::

:::scene{type=code}
heading: Sliding window — the recent past as features
code: |
  # build lag features from the PAST only
  for k in (1, 2, 3, 6):                       # 10, 20, 30, 60 minutes ago
      df[f"lag_{k}"] = df["Appliances"].shift(k)

  df = df.dropna()                             # the first rows have no past

  cut = int(len(df) * 0.8)                     # chronological split, always
  train, test = df.iloc[:cut], df.iloc[cut:]
note: shift(1) looks back one row. shift(−1) would look forward — into the answer. With windows, a random split is not merely optimistic; every test window overlaps a training window.
narration: |
  The first way to give a model the past is a sliding window: the last few readings
  become extra columns. Shift the appliance column down by one row, and every row now
  carries the reading before it. Shift by two, three, six, and it carries the last hour.
  Two rules. Lag features are built from the past only: shift one, never shift minus one,
  which looks forward into the answer. And with windows, a random split is not merely
  optimistic; every test row's window overlaps a training row's window. Chronological,
  always.
:::

:::scene{type=diagram id=sequence_models}
heading: Three ways to let a model see the past
points:
  - Sliding window — the last k readings as k features. Simple, fixed memory
  - Recurrent — a state carried step to step. Unbounded memory, sequential
  - Attention — every past step weighed against the query. Parallel, inspectable
narration: |
  Three ways to let a model see the past. The sliding window you just built: the last k
  readings as k features, simple, with a fixed memory length. A recurrent network, an R N
  N or an L S T M: a state carried from one step to the next, so memory is unbounded, but
  the computation is sequential and slow. And attention, the mechanism inside
  transformers: every past step is weighed against the current question, in parallel,
  and the weights can be read afterwards.
:::

:::scene{type=compare}
heading: Window or recurrent network?
left:
  title: Sliding window + a tabular model
  points:
    - Fixed memory, any model you already know
    - Cheap, robust
    - On the appliance data, hard to beat. Start here
right:
  title: LSTM / GRU
  points:
    - Learned memory of unbounded length
    - Wins when the relevant past is far away or varies in length
    - A heating cycle, a weekly pattern, a fault developing over days
verdict: Start with the window. Reach for the recurrent network when the window cannot hold what matters.
narration: |
  Which one? Start with the window and a model you already know. It is cheap, robust,
  and on the appliance data, hard to beat. An L S T M, a recurrent network with gates
  that learn what to keep and what to forget, wins when the relevant past is far away or
  varies in length: a heating cycle, a weekly pattern, a fault that develops over days.
  Reach for it when the window cannot hold what matters, and not before.
:::

:::scene{type=diagram id=attention}
heading: Attention — weigh the past, then sum it
points:
  - A query — what am I asking about now?
  - Scores against every past reading become weights, via softmax
  - The weights sum to one — and you can read them
  - The prediction is the weighted sum of the past values
narration: |
  Attention, in one picture. The model forms a query: what am I asking about now? It
  scores that query against every past reading, and a softmax turns the scores into
  weights that add up to one. The prediction is the weighted sum of the past values. Here
  the model looks hardest at the same time yesterday and at the last hour, and lightly at
  everything else. The weights are learned, they sum to one, and, this is the part that
  matters for engineering, you can read them afterwards. The model can show what it
  looked at.
:::

:::scene{type=list}
heading: Where sequence models earn their place
items:
  - Short-horizon load and indoor-temperature forecasting, for control
  - Fault detection from the shape of a sensor trace over hours or days
  - Occupancy inference from CO₂, motion and plug-load sequences
  - Predictive maintenance of HVAC equipment
  - And always — a persistence baseline, a chronological split, features matched to the horizon
narration: |
  Where sequence models earn their place. Short horizon forecasting of load and indoor
  temperature, for control. Fault detection from the shape of a sensor trace over hours
  or days. Occupancy inference from C O two, motion and plug load sequences. Predictive
  maintenance of heating and cooling equipment. And in every one of them, the same three
  habits: a persistence baseline, a chronological split, and features matched to the
  horizon you are predicting.
:::
